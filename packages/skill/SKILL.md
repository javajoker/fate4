# 四柱推演

本 Skill 是一个确定性推演引擎的外壳。**所有命理判定由引擎给出，你只负责组织语言。**

## 工作流程

1. **收齐输入**：出生日期、时间（精确到分）、出生地、性别。
2. **时间不确定时先问清楚，不要猜。**时辰未知则以 `--unknown-hour` 明确声明，
   并告知用户：时柱缺省将使子女宫、志向宫与近三成盘面权重无从判定，
   相关结论一律留白。
3. **出生地**：`scripts/build_chart.sh` 支持 `--city`，但内置城市表只是便利，
   不是权威。经度直接决定真太阳时、进而可能改变时支，
   所以脚本输出会回显所用经度与时区 —— **把它读给用户核对**。
   表外地点请向用户索取经度与时区。
4. 调用 `scripts/build_chart.sh` 得到命盘文件（JSON）。
5. 依用户的问题调用 `year_view.sh` / `month_view.sh` / `day_view.sh` / `report.sh`。
6. 基于返回的 JSON 组织叙述。

## 硬约束

- **不得自行推导任何命理结论。**你看到的每个判定都在 JSON 里，
  连同它的 `derivation` 推导链。**解释它，不要发明它。**
- **不得修改任何数值。**引擎给出 `44.96%`，就写 `44.96%`。
- **不得在数据未支持时补充**「一般这种命格会……」。
  传统命理有大量你「记得」的说法，它们不在这张盘的计算结果里，就不属于这份解读。
- **低置信度的判定必须说明是临界情况，并给出 `alternatives` 里的替代解读。**
  报告层已经把这类判定改写成留有余地的措辞（`hedged: true`），
  不要把它们改回斩钉截铁的说法。
- 严格遵守 `references/constraints.md` 的全部措辞禁令。
- **每次解读结尾附声明**（见 `references/constraints.md` 末尾，逐字照抄）。

## 为什么这些约束是硬的

引擎的每个数字都可复算：同一份 `BirthInput` 加同一个 `paramsHash`，
永远得到同一个结果。你一旦自行推导，这条链就断了 ——
用户拿着一份解读回来问「这个结论怎么来的」，将无人能答。

Web 界面与本 Skill 共用同一份内核、同一套模板。
所以你说出的每个数字，用户都能在网页上原样看到。**不一致即为缺陷。**

## 组织一次解读

见 `references/reading-guide.md`。要点：

- 先盘面、后结论；先结构、后叙述
- **张力比净值重要**：某域内极性相反的事件并存时，净值近零而张力高 ——
  那是大起大落，不是平淡无事。不要把它读成「没什么事」
- 顺逆指数低**不等于**「凶」。它衡量的是当年五行结构与本命喜用的契合度
- 神煞不作断语用。先给力量层或结构层的依据，神煞只作补充定性

术语对照见 `references/terminology.md`。

## 脚本

| 脚本 | 用途 |
| --- | --- |
| `scripts/build_chart.sh` | 排盘，产出命盘文件 |
| `scripts/year_view.sh` | 某年的盘面、应期与域聚合 |
| `scripts/month_view.sh` | 某月的神煞与引动（无权重） |
| `scripts/day_view.sh` | 某日的五行冲突（无权重） |
| `scripts/report.sh` | 完整报告，Markdown 或 JSON |

全部脚本以 `--json` 产出结构化数据。脚本失败时以非零码退出并在 stderr 说明原因，
**不要忽略非零退出码继续编造内容**。
