## 1. 先厘清五条边界

写在最前面，因为下面每一条都会否掉一种看起来很自然的做法。

### 1.1 按时起卦是确定性的，卦属于「时刻」而不属于「人」

按时起卦的输入只有时刻。直接后果：

> **同一时辰内，所有人问所有事，得到的是同一个卦。**

第一反应会觉得这是缺陷，想加点随机数或者把问题文本混进去。**不要那样做**，
两条理由：

其一，**这是该方法的前提，不是它的漏洞**。梅花易数的时间起卦，卦象属于那个「应机」
的时刻本身。同一时刻的不同问题，靠**取不同的用神**来区分 —— 问财取妻财爻，
问职取官鬼爻，同一个卦读出的是不同的结构。这是设计，不是巧合。

其二，把问题文本哈希进起卦，是**发明一种传统里没有的方法**，还伪装成传统。
本项目对《穷通宝鉴》调候表都要标「凭记忆转录」，没有理由在这里凭空造一个起卦法。

但**必须如实告诉用户它的后果**：同一时辰的两次问事，卦相同、用神可能相同，
于是断语高度相关。想要真正区分，用 §2 的另外两种起卦法。

### 1.2 按时起卦要农历 —— 已定案：实现定朔农历

梅花易数的年月日时起卦法：

```
上卦 = (年支序 + 农历月 + 农历日) mod 8      余 0 取 8
下卦 = (年支序 + 农历月 + 农历日 + 时支序) mod 8
动爻 = (年支序 + 农历月 + 农历日 + 时支序) mod 6      余 0 取 6
```

**「农历月」「农历日」是朔望月的月序与日序**，不是节气月，也不是公历。
本项目至今只算节气（定气，VSOP87 求太阳黄经），**没有定朔**，因而没有农历。

**已定案：实现定朔农历（P17a）。** 曾考虑过的两个替代方案与否掉它们的理由：

| 方案 | 否掉的理由 |
| -- | -- |
| 以节气月序 + 干支日序代入同一公式 | **是发明。** 得到的卦与任何传统排法都不同，只能在报告里标注「与传统排法不同」—— 而这种标注等于承认功能是错的 |
| 先不做按时起卦，默认掷钱／报数 | 可行且忠实，但推迟的是你明确要的那个功能 |

选它的理由不止这一个公式：

- 农历是四柱应用的常规需求（用户报生日常报农历；报告也该并列显示）
- 择日、部分神煞起例在若干流派按农历
- 天文实现与既有的 `solarTerms.ts` **同构** —— 同一套牛顿求根，换一个目标函数
  （日月视黄经差 = 0° 求定朔），复用 `deltaT`、`julian`、`nutation`

**农历不只是求朔。** 完整实现还需要（这是本阶段真正的工作量所在）：

| 环节 | 说明 |
| -- | -- |
| 定朔 | 日月视黄经差归零。需月球黄经 —— 新增截断级数 |
| 月首 | 朔日所在的那一天为初一，**按东八区地方时的日界**，不是 UT |
| 月序与置闰 | 以**中气**定月序：含冬至之月为十一月；两冬至之间若有 13 个朔望月，则第一个**无中气**之月为闰月 |
| 岁首 | 正月初一（春节），与四柱的立春年界**不同** —— 报告须明确区分，勿混用 |

最后一条是常见错误来源：本项目的年柱以立春为界（见 [02](02-chart.md)），
而农历年以正月初一为界，两者可差一个多月。**同一份报告里出现两种年界时必须各自标名。**

### 1.3 起卦用梅花法、断卦用京房法 —— 这是混用，必须声明

| 环节 | 出处 | 说明 |
| --- | --- | --- |
| 起卦 | 梅花易数（邵雍一系） | 年月日时数起卦、先天八卦数 |
| 装卦断卦 | 京房纳甲（六爻） | 纳甲、六亲、世应、六神、用神旺衰 |

梅花本身的断法是**体用生克 + 互变卦**，与六爻的**用神旺衰 + 生克冲合**是
两套不同的分析框架。当代实务里「时间起卦 + 六爻装断」很常见，但它确实是混用。

按本项目一贯做法，这进 `params` 作流派开关（`liuyao.castMethod`），
随卦声明，与十二长生、土的长生同等对待。**不静默混用。**

### 1.4 六爻的原生语汇与措辞守卫正面冲突

这是本文最要紧的一节。

六爻典籍的断语是**赤裸的结果预言**：「用神旺相，主求财必得」「官鬼持世，病难愈」
「应爻发动来生，行人即至」。而 §6 的措辞守卫拦的正是「主体 + 情态 + 后果」这种形状。

不能靠改词绕过去 —— 把「必得」改成「多半能得」只是把强断言换成弱断言，形状没变。

**做法：卦象层出结构，叙述层只描述结构。**

| 传统断语 | 本系统输出 |
| --- | --- |
| 用神旺相得日辰生扶，主求财必得 | 妻财爻临月建得令，日辰生之，动而化进 —— 传统上视为「力量充足且趋势向上」的结构 |
| 官鬼持世，病难愈 | 官鬼爻持世且逢月破 —— 传统上视为「所问之事与自身位置相纠缠」的结构。本系统不判断病情，不给出预后 |
| 应期在申月 | 用神旬空，传统以「出空」「填实」为应期之候，对应本卦为申、酉两个月建；这是卦象结构给出的**候选时段**，不是事件预报 |

需要新增的守卫规则（`report/guard.ts`）：

| 规则 id | 拦什么 | 为什么现有规则拦不住 |
| --- | --- | --- |
| `zh.liuyao.verbZhu` | 「主」作断言动词：主得、主失、主散、主成、主凶 | 「主」是单字，现有规则按「主体+情态+后果」构句匹配，逮不到这种省略主语的祈使式 |
| `zh.liuyao.outcomeVerb` | 可成／不成／必得／难成／立至／即至／无妨 | 六爻特有的成败词，不在通用情态表里 |
| `zh.liuyao.yingqiPoint` | 应期报到「某日某时」这样的**时点** | 与统计节点同一条纪律：只报区间，时点是伪精度 |
| `zh.liuyao.divineMedical` | 占病类断语出现预后（愈／不愈／凶险／危） | 现有 `zh.medical.diseaseName` 只拦病名，不拦预后 |

并沿用现有的 `requireContext` 一档：占病、占官非、占财的叙述**必须**带
「传统上……视为」的框定语，缺则拦下。

### 1.5 三个系统「相互印证」不是统计意义上的印证

你说的「六壬和奇门遁甲相互参照支持」，实现时有一个必须避开的陷阱：

**六爻、六壬、奇门都是同一时刻干支的确定性函数。** 它们一致，不构成独立证据；
它们不一致，也不代表哪个错了。这与 [12](12-persona-curves-nodes.md) §4 对统计节点的
表述是同一条纪律 —— 确定性序列上算出来的散布，不是概率。

| | |
| -- | -- |
| ✅ 成立 | 「三个体系在这件事上给出方向一致／不一致的结构判断」 |
| ❌ 不成立 | 「三个体系都说好，所以更可信」 |

因此 **crossref 层只报一致与分歧，不做加权合成**。三者分歧是信息，
平均掉就把信息毁了 —— 与调候／扶抑并列、与《内经》五窍两说并列，同一处理。

## 2. Q0 起卦

### 2.1 三种起卦法

| 法 | 输入 | 可复现 | 区分度 | 需历法 |
| --- | --- | --- | --- | --- |
| `time` 按时 | 起卦时刻 | ✅ | 同时辰不可分（§1.1） | 农历（§1.2） |
| `number` 报数 | 时刻 + 求问者报的数 | ✅ | 由报数区分 | 否 |
| `coin` 掷钱 | 六次三枚铜钱的正反 | ✅（记录钱象） | 完全区分 | 否 |

**`coin` 是六爻的本法**，`time` 是借梅花的方法（§1.3）。

报数法有单数与两数两式：

| 式 | 算法 | 一个时辰内的结果数 |
| -- | -- | -- |
| 单数 | `上卦 = n mod 8`、`下卦 = (n + 时支序) mod 8`、`动爻 = (n + 时支序) mod 6` | **24** |
| 两数 | `上卦 = a mod 8`、`下卦 = b mod 8`、`动爻 = (a + b + 时支序) mod 6` | 384（全覆盖） |

⚠️ **单数法退化得比想象的厉害。** 时支在一个时辰内固定，于是上卦、下卦、动爻位
全部由 `n` 单独决定；而 `n mod 8` 与 `n mod 6` **不互素**，周期是 `lcm(8,6) = 24`。
故一个时辰内只有 24 种结果 —— 不是 64 × 6 = 384，也不是「8 个卦 × 6 个动爻 = 48」。
规格初稿写的正是 48，实测才发现是 24。要全覆盖，用两数法或掷钱。

掷钱法：一次掷三枚，背面数 0–3 对应
`0 背 = 老阴(动，⚋→⚊)`、`1 背 = 少阳(静)`、`2 背 = 少阴(静)`、`3 背 = 老阳(动，⚊→⚋)`。
自初爻向上掷六次。**动爻可以有零个，也可以有多个** —— 这是掷钱法与时间法的结构差异：
时间法恒定一个动爻，掷钱法不定。断法须两者都支持。

### 2.2 先天八卦数与卦的表示

```
乾1 兑2 离3 震4 巽5 坎6 艮7 坤8
```

一卦记作六个爻的阴阳，**自下而上**（初爻在下标 0）：

```ts
type Yao = 0 | 1;                    // 0 = 阴 ⚋, 1 = 阳 ⚊
type Hexagram = readonly [Yao, Yao, Yao, Yao, Yao, Yao];
```

本卦六爻中的动爻取反得**变卦**。动爻为空则无变卦（掷钱法可能出现）。

### 2.3 起卦记录是一等对象，且不可重掷

```ts
interface Casting {
  readonly method: "time" | "number" | "coin";
  readonly at: Instant;              // 起卦时刻（真太阳时口径与四柱一致）
  readonly pillars: FourPillars;     // 起卦时刻的年月日时四柱 —— 即月建与日辰
  readonly input: TimeInput | NumberInput | CoinInput;
  readonly benGua: Hexagram;
  readonly moving: readonly number[]; // 动爻下标，升序
  readonly bianGua: Hexagram | null;
  readonly paramsHash: string;
  readonly engineVersion: string;
}
```

**一事不二占。** 同一问题在同一日内重复起卦，返回**首次**的 `Casting`，
并明确告知这是首卦。理由有二：传统上「不诚不占、一事不二占」；
工程上，允许重掷等于允许用户一直摇到满意为止 —— 那样得到的不是占卜，是筛选。

实现：`(占事类型, 问题指纹, 日干支)` 为键持久化首卦。问题指纹取问题文本的
规范化哈希，**只存哈希不存原文**（与生辰数据同一条隐私纪律）。
命令行落在 `--journal` 指的 JSON 文件，Web 落在 `localStorage`。

三条实现时才想清楚的细节：

- **重放要连起卦法一起重放。** 首卦以按时起，再问时给 `--method coin`，
  若只重放输入而让参数里的起卦法照命令行走，`cast` 会当场抛错「输入与声明不符」。
  修法不是放宽校验，而是**首卦的起卦法才作数** —— 否则「一事不二占」就成了
  「换个起卦法即可重来」。
- **换个时刻也返回首卦。** 否则等一个时辰就能重来。键里只有日干支，不含时辰。
- **记录文件损坏时报错，不静默重置。** 一份能被悄悄清空的记录，等于没有记录。
- **不给 `--journal` 即不设防**，这一点在用法里明写 —— 默默不设防比明说更糟。

伏神能否起作用（「得出」）传统有多条判据（飞神生伏、日月生伏、伏神旺相、飞神空破……），

## 4. Q3 力量

用神强弱是六爻断卦的核心。与四柱不同，六爻**不做权重传导** —— 没有 L3。
六爻的力量是**分档 + 生克关系**，不是连续量。这个差异要写进类型：
四柱的旺衰是 `number`，六爻的旺衰是 `枚举 + 关系列表`。

### 4.1 月建：旺相休囚死

以月建五行为令：

| 档 | 关系 | 说明 |
| -- | -- | -- |
| 旺 | 与月建同五行 | 当令 |
| 相 | 月建所生 | 次旺 |
| 休 | 生月建者 | 泄气 |
| 囚 | 克月建者 | 受制 |
| 死 | 月建所克 | 最弱 |

**月破**：与月建相冲之支。破而逢动、逢日建生扶者，传统称「破而不破」——
判据各家不一，进参数。

### 4.2 日辰

日辰对爻可生、可克、可冲、可合、可比。日辰之力在诸家中**最重**
（「日辰为六爻之主宰」），但具体权重不一。本系统不合成数值，
只记录**关系集合**，让 Q4 按规则判断。

**静爻逢日冲有两种归宿，旺衰不同、结局相反**：

| 逢冲之爻 | 名 | 后果 |
| -- | -- | -- |
| 旺相 | **暗动** | 虽静而实动，**能生克他爻**，只是不显于卦面 |
| 衰弱 | **冲散** | 本就无力，一冲即溃 |

规格初稿把两者一并当作「日冲」记入关系，于是暗动之爻既不算动、
又只被记了一笔「受冲」—— 它对他爻的作用整个丢了。实测四千余卦中暗动屡见，
不是边角情形。

### 4.2.1 力量为什么不合成分数

把「月建旺相 +2、日辰生扶 +1、化回头克 −2」加起来得一个爻力分，是六爻软件的通行
做法，也很诱人 —— 有了数就能排序、能画图。但这些量**性质不同，不可通约**：

- 「月破」是**资格上的否定**（该支这个月不成立）
- 「日辰相冲」是**一次具体的冲击**
- 「化回头克」是**趋势的反转**

压成同一个标量，等于宣称三者可以互相补偿 —— 而断卦恰恰要分开看它们：
月破的用神纵有百般生扶，传统上仍以待时论。

故 `liuyao/strength.ts` 走**有序的规则阶梯**：逐级判定，命中即止，记下命中的是哪一级。
输出是五档枚举加一条推导链，不是一个数。阶梯的次序即是传统断法的优先级 ——
先看有没有资格问题（月破、真空），再看得令与否，最后看生克。

### 4.3 旬空

由日柱所在旬定。空亡的处理：

- 静而空 → 真空，待出空
- 动而空 → 不为空，动出即用
- 空而逢冲 → 冲空则实

三条判据各家一致度较高，仍进参数。

### 4.4 动爻生克与化爻

动爻生克其余各爻；动爻自身变出的爻（变爻）反过来影响动爻，称**回头生／回头克**。
变爻与动爻的关系另有专名：

| 名 | 判据 |
| -- | -- |
| 化进神 | 变爻地支为动爻地支的「前一位」同五行（寅→卯、巳→午、申→酉、亥→子、丑→辰→未→戌） |
| 化退神 | 反向 |
| 化回头生 | 变爻生动爻 |
| 化回头克 | 变爻克动爻 |
| 化空／化破 | 变爻旬空／月破 |

**反吟、伏吟**（卦变或爻变呈特定形态）作为整卦级别的标记。

### 5.4 健康类占事 —— 已定案：开启但严格受限

占病是六爻的传统大宗，也是本系统风险最高的一类。**保留该类目，输出严格受限**：

1. **不给病名**，沿用现有 `zh.medical.diseaseName` 规则
2. **不给预后**（愈／不愈／轻重／凶险），新增 `zh.liuyao.divineMedical`
3. **不给应期**，健康类不产出时间窗 —— 「病在某月」是本系统绝不输出的句式
4. 输出限于：用神（官鬼为病、子孙为医药解忧）所临六神与五行，
   对应到 [12](12-persona-curves-nodes.md) §2.7 已有的《内经》五行配属，
   **与四柱身体层同一套框定语与免责**
5. 强制附「请咨询持证专业人士」

定这个方案的理由：**用户不问，不等于不想问**；给一个受约束的答案，
好过把人推去别处拿一个没有约束的。开关仍在（`liuyao.topics.health.enabled`），
但默认开启，且 `emitYingqi: false` 是硬约束 —— 改则参数校验失败。

## 6. Q4 断论 · Q5 应期

### 6.1 断论输出的是结构，不是结果

Q4 的产物是一组**结构判断**，每条都可溯源，形状与四柱的 `Verdict<T>` 一致：

```ts
interface LiuyaoFinding {
  readonly aspect: "用神力量" | "用神动静" | "世应关系" | "原忌消长" | "卦变";
  readonly value: string;            // 如「用神临月建而旬空」
  readonly confidence: number;
  readonly derivation: readonly DerivationStep[];
  readonly alternatives: readonly { value: string; reason: string }[];
}
```

### 6.2 应期只报区间

传统应期取法（用神旬空取出空、被合取冲开、发动取逢合、安静取逢值逢冲……）
给出的是**干支之候**，落到日历上天然是**若干个候选时段**，不是一个时点。

沿用 [12](12-persona-curves-nodes.md) §4 的纪律：

- 报「未来十二个月内，申、酉两个月建为传统所指的候选时段」
- 不报「应在 X 年 X 月 X 日」
- 由 `zh.liuyao.yingqiPoint` 强制

候选时段按「与今日的距离」升序，**不排序为可能性高低** ——
确定性规则给出的候选，没有可言的概率。

## 7. 当日运程

两条独立的线，**并列，不合并**：

| 线 | 来源 | 已有？ |
| -- | -- | -- |
| 四柱侧 | `temporal/views.ts` 的 `dayView(base, date)` —— 流日事件匹配，不重算权重 | ✅ 已实现 |
| 六爻侧 | 该日的日卦（起卦时刻取当日**用户首次打开**的时刻，记入 `Casting`） | 新增 |

**为什么不合并**：见 §1.5。两者都是当日干支的确定性函数，一致不构成印证。
输出形如：

```
四柱侧：今日 己巳，冲本命亥（配偶宫），日主得禄
六爻侧：泽水困变泽地萃，世爻持兄弟临白虎，用神妻财伏而不现
一致处：两侧都指向「财务相关的位置受扰」
分歧处：四柱侧的日禄为得力，六爻侧的用神伏藏为无着落 —— 两说并列
```

对照分**五个类目**，刻意分得比「一致／分歧」细：

| 类目 | 含义 |
| -- | -- |
| 一致 | 两侧都给出方向，且方向相同 |
| 分歧 | 两侧方向相反 —— 并列两说，不作裁决 |
| **单侧表态** | 一方给出方向，另一方判中性。**这不是一致** —— 沉默不等于同意 |
| 无从比对 | 两侧皆判中性，两边都没话说 |
| **并列** | 该轴本就不判方向（事之动静、时间窗）—— 动不等于好，静也不等于坏 |

后两个类目是实现时补上的：初稿只有「一致／分歧／单侧」，于是
**一侧中性、一侧有方向被记成了「一致」**，而「事之动静」两侧都说了话
却因为都判中性被记成「无从比对」。两处都会让「一致率」这个数字虚高，
而虚高的那部分恰恰最没有信息。

**实测半年逐日：一致 110 次、分歧 116 次。** 两者几乎相等 ——
若两侧真在互相印证，一致率该显著更高。这条数字本身就是
「一致不构成印证」的实证，故写进测试当不变量：一致率须落在 25%–75% 之间，
压倒性地高反而说明两侧其实在算同一件事。

「一致处／分歧处」由 crossref 层（§11）按共同词汇比对，**不加权、不裁决**。

**日卦起在哪一刻**：按时起卦的卦属于时刻，而当日运程需要一个该日的代表时刻。
取用户当日首次查看的时刻最合「应机」之义，但那不可复现。故默认取**该日子时初**：
它是该日的起点，对同一日恒定，报告可复算。

**当日运程只支持按时起卦。** 报数与掷钱都要人当场给输入，而当日运程是每日自动
生成的一页 —— 没有人报数，也没有人掷钱。替用户代掷一把，得到的是伪造的随机性。

## 7.5 Q7 指事 —— 爻辞一路

到 Q5 为止，输出全是**结构**：用神偏无力、动而化退、候选时段在申月。
结构是对的，但它说不出「说的是什么事」。用户问的是求职，得到的是
「妻财爻临月建得令」；这中间缺一层**所指**。

爻辞正是那一层。它给的是具体的象：旅行、争讼、婚嫁、田猎、涉大川。

### 7.5.1 这是第二次混用，且比第一次更彻底

§1.3 声明过第一次混用：起卦用梅花，装断用京房。这里是第二次，性质不同：

| | 起卦 vs 断卦 | 纳甲 vs 象辞 |
| 混的是什么 | 同一件事的两个环节 | **两套互不相干的分析体系** |
| 京房一路 | 六亲、生克、旬空月破 | 一句爻辞都不用 |
| 象辞一路 | —— | 只读卦爻之辞，不问纳甲 |

《卜筮正宗》《增删卜易》断卦不引爻辞；引爻辞的是《周易》本经与义理一路。
民间的「文王卦」才把两者并读。

故本项目的处置是**分层，不是融合**：

- 爻辞**不进 `Judgement`**，不影响用神取舍，不影响应期；
- 取爻按象辞自己的规矩（下节），**不看用神**；
- 取到的位置是否恰好是用神位，只作一行记录，**不作「两法相符」的加权** ——
  与 §1.5 同一条纪律：一致不等于互证。

由测试锁住：换一个占事（用神随之改变），取到的爻与引文**逐字不变**。

### 7.5.2 取爻

| 卦况 | 取 | 依据 |
| 有动爻 | 每个动爻：本卦此爻 → 变卦同位爻 | 动爻为事之所主 |
| 六爻皆静 | 世爻与应爻 | 《增删卜易》静卦看世应 |

按时起卦恒得一个动爻（动爻位 = 四数之和 mod 6），故默认路径永远走第一路；
世应那一路只在掷钱六爻皆静时出现 —— 掷钱法下约六分之一。

⚠️ **应爻是对方，不是将来。** 参考实现把静卦的应爻标作「future」，
与本爻的「now」相对。那是把一组**空间关系**（我方／他方）读成了**时间关系**，
凭空多出一条对未来的话。唯有动爻那一路的本卦→变卦才真是由此及彼。

⚠️ **世爻位置不从卦画算。** 民间有一套口诀（比对初四、二五、三上三组爻的异同
定世位）。参考实现照它写，但三个标志位用 `&` 而不是 `|` 合并 —— 位于不同位的
三个比特相与恒为 0，于是静卦一律取初爻，六十四卦全错。
本项目不走这条路：世位由八宫次序直接给出（`SHI_POSITION`），而八宫是生成的，
这类错误在结构上发生不了。

### 7.5.3 语料：四类文字，各有各的分寸

语料共 64 卦 × 7 格（第 0 格卦辞，1–6 格六爻），简繁英三份：

| 类 | 是什么 | 谁写的 |
| `classic` | 卦辞、爻辞原文 | 《周易》，公有领域 |
| `gist` | 一句话指事 | 语料作者的撰述 |
| `expand` | 白话转述 | 语料作者的撰述 |
| `stage` | 六个爻位各自的阶段 | 语料作者的撰述 |

**后三类是转述，不是经文。** 这个区分决定了下一节的全部处置。

⚠️ **第 0 格是卦辞，爻位是 1–6。** 参考实现把动爻的 0 基下标直接当格号用，
于是初爻取到卦辞、上爻取到五爻，六爻全体错开一格 —— 而读起来都通顺，
所以这种错不会被人眼发现。本项目把卦辞格显式定为 `GUA_SLOT`，
并由测试逐格对质：爻辞原文自带爻题（初九、九二……上六），错开一格必然全线失败。

语料**程序化搬运**，不经任何人工或模型转录（`scripts/generate-yaoci.mjs`），
源文件 SHA256 记入 `provenance.ts`。理由与 VSOP87 同：1350 条文字里错在
「第几爻」上是查不出来的。

卦序也不靠人对照：语料按**通行本**编号，本项目的六十四卦按**京房八宫**生成。
源文件恰好给了两份互相独立的通行本次序（64 个卦画二进制串、64 个卦名），
两份都搬过来，由测试断言「照二进制查出来的卦，卦名必须等于名单里那一个」。
任一份搬错都会当场暴露；只搬一份则无从发觉。

### 7.5.4 引文与措辞守卫：不通过就不发

§1.4 说的是**本系统自己的话**如何避开结果预言。爻辞语料是**外来的**，
四百多条，而且不是本项目写的。三种可选做法：

| 做法 | 问题 |
| 给引文开豁免 | 守卫立刻形同虚设 —— 任何一句都可以说「这是引文」 |
| 逐条改写语料 | 那就不是引文了，是借别人的口说自己的话 |
| **不通过就不发** | 少几条，但没有一条是坏的 |

取第三种（`report/screen.ts`）。读者偶尔看到「这一条未通过措辞检查（规则 id）」，
而那句话本身是诚实的：它说出了发生过什么，也说得出是哪一条拦的。

**筛在读取时，不在生成数据时。** 若把「哪些条目可发」预先算好写进数据文件，
这份判断就冻在生成那一刻：此后守卫加严，旧条目照发；守卫修掉一处误杀，
被误杀的条目也再不会回来。改成读取时扫、按条记忆 —— 规则一变，结果当场跟着变。
一次问卦只取三五条，扫不了几个字。

**哪一层载哪几项，是构造决定的**：爻位阶段与白话转述通篇第二人称，
而技术层禁第二人称（`zh.secondPerson.address`），故这两项技术层**根本不取** ——
不是「取了被拦」。实测印证：技术层扫描下阶段一项 2184 条全数被拦，
全数拦下的东西不该端上去让读者看 2184 遍「未通过检查」。

| | 爻辞原文 | 一句话指事 | 爻位阶段 | 白话转述 |
| 技术层 | ✅ | ✅ | —— | —— |
| 人话层 | ✅（作出处） | ✅ | ✅ | ✅ |

实测拦下率（723 卦 × 简繁两种字形）：

| 层 | 引文条数 | 拦下 | 分布 |
| 技术层 | 10167 | 84（0.8%） | 全在「一句话指事」 |
| 人话层 | 18156 | 552（3.0%） | 指事 1.0%、白话转述 10.0% |

**爻辞原文两层皆零拦。** 经文虽有吉、凶、悔、吝，却不构成「主体 + 情态 + 后果」
的断言形状 —— 这正是 §1.4 那套「拦形状不拦词」的设计所预期的结果，
而 448 条经文是它最硬的一次反向对照。

### 7.5.5 语料把守卫的四个洞照了出来

引入一份四百多条的外来语料，等于给守卫做了一次远超自有语料的压力测试。
逮到四处，都是实打实的：

| 洞 | 症状 | 修法 |
| `PLAIN_RULES` 只装了简体规则 | 繁体人话输出只受人话层自己那六条约束，预言、医疗、财务、六爻成败词一条不管。同一批语料：简体命中 51 处、**繁体命中 1 处** | 改取 `ALL_GUARD_RULES`，并由测试断言简繁一一对应 |
| 「凶险」的繁体作**兇險**，而机械派生给出「凶險」 | `zh.liuyao.divineMedical` 的繁体版在真繁体文本上一次都不命中（27 → 0） | 「凶」入 `AMBIGUOUS`，「凶险／凶猛／凶手／凶残」入 `TERMS` |
| `zh.body.framing` 把「胆」一律当脏腑 | 「大胆」「闻风丧胆」全数误杀 —— 而人话层「你可以更大胆一些」这种句子迟早自己撞上来 | 「胆」排除定型搭配 |
| `zh.liuyao.outcomeVerb` 的「不成」命中「不成熟」 | 「时机尚不成熟」被当作「事不成」 | `allow` 补「不成熟／不成形」 |

前两处修完，简繁拦下条数从 51 : 1 变成 **47 : 47**，且逐规则镜像对应。
这个对等由测试锁住 —— 它是本次最有价值的产出：
「人话层比技术层更严」这句话，得对每一种字形都成立才算数。

### 7.5.6 繁体引文不经转换

报告其余部分的繁体由 `toHant` 机械转出，故有一条硬测试要求
「报告里的每一个汉字都已归类」。引文不同 —— **它自带繁体原文**。

于是两件事：

1. `collectYaociText` 返回的 `where` 一律带 `quote:` 前缀，简繁完整性测试据此
   排除引文段。否则就要为四百多条爻辞的两百来个生僻字（贞、咎、吝、簋、禴、豮……）
   逐个做简繁对照，而这些字一次都不会被转换。
2. `renderQuestionMarkdown` 末尾对整份文档过一遍 `toHant`（给函数里硬写的
   简体标题兜底）。引文先换成占位符，转完再换回来 —— 再转一次也许无害，
   但那是运气，不是保证。

引文的繁体另有把关：`yaoci.spec.ts` 拿 `SIMPLIFIED_ONLY` 筛整份繁体语料。
筛出一处 —— 源语言包把「鼎槓」漏转成「鼎杠」，勘误列在生成脚本里，看得见、可追。

⚠️ **占位符保护的是「不再转一次」，不是「转对了」。** 当日运程上栽过一次：
`dailyOutlook` 按 `params.report.locale` 建读法，而 `renderDailyMarkdown(o, locale)`
的语言是调用方当场给的。`fate daily --locale zh-Hant` 两者不一致，占位符就忠实地
保住了**简体**爻辞，让它原样穿过繁体转换 —— 繁体文档里嵌着简体引文，
而所有测试都绿。修法是渲染前按目标语言 `relayerYaoci` 重取一遍；
测试改为直接查「繁体当日运程里没有一个简体字」，与四柱报告那条同一个判据。

教训是：**保护引文不被改动，与保证引文是对的语言，是两件事。** 第一件由占位符
负责，第二件必须另有人负责 —— 否则第一件做得越好，第二件的错越隐蔽。

## 11. 六壬与奇门的接口

### 11.0 六壬已实现（P23）

| 环节 | 落点 | 要点 |
| -- | -- | -- |
| 月将 | `liuren/plate.ts` | **以中气为界**，随太阳逆行十二支。与四柱月柱的「以节为界」不同源，同一份报告里出现两者必须各自标名 |
| 天地盘 | 同上 | 月将加时：`天盘(g) = 月将 + (g − 占时)` |
| 四课 | 同上 | 一课下神取日干寄宫，三课下神取日支；二四课各承前课上神 |
| 十二天将 | 同上 | 贵人由日干与昼夜定；临地盘阳位顺布、阴位逆布 |
| 三传 | `liuren/sanchuan.ts` | 九宗门，**有序的阶梯** |

**九宗门是阶梯不是选项**：前一门取不出才轮到后一门。故实现记下是在哪一门发用
（课体），报告须说明 —— 「元首课」与「昴星课」得出的三传，可信程度本就不同。

实测 2026 一年 × 四时辰共 1460 课，十一种课体全部出现，常法（元首/重审/知一/涉害）
占 76%。若特殊课式反而占多数，说明课式判定过宽 —— 这条写成了测试不变量。

⚠️ **别责与八专的取法各家不一**（尤其中末传），伏吟的中末传取刑亦有异说。
这三种课体标 `disputed: true`，跨体系断言的置信度随之下调，并已并入待校准清单。

### 11.1 与六爻的一处结构差异

六爻的卦可以掷钱、可以报数；**六壬的课完全由时刻决定** ——
同一时刻同一日，任何人起出的是同一课。
故六壬里没有「一事不二占」的技术问题：重问必得同课，防无可防，也无需防。

### 11.3 奇门已实现（P24）

时家**转盘**法，五步：

```
1 定阴阳遁与局数   节气 + 三元（符头之支）→ 查三元局数表
2 排地盘三奇六仪   自局数之宫起「戊」，阳遁顺飞、阴遁逆飞宫数
3 定值符值使       旬首所遁之仪在地盘的哪一宫，该宫的九星为值符、八门为值使
4 转天盘           值符星飞到「时干所在的地盘宫」，其余星沿洛书圆序跟转
5 布八门八神       值使门按时辰在本旬中的位次移动；八神自值符宫顺逆布
```

**九宫的两种次序不可混**：排地盘用**宫数序**（1…9 顺飞逆飞），
转天盘与布八神用**洛书圆序**（1 8 3 4 9 2 7 6，自坎一顺时针绕外圈）。中五不在圈上。

**最易错的一处**：三奇六仪的次序是 **戊己庚辛壬癸丁丙乙** —— 三奇殿后且丁丙乙倒排。
写成「…癸乙丙丁」全盘皆错，而错得很隐蔽：地盘看上去仍是九干各一，
只有对着典籍逐宫核才看得出。故测试拿阳遁一局与阴遁一局逐宫对账。

**天禽寄坤二**，随天芮同行。初稿把它静态留在中五，于是它永远不参与格局，
而实务上「天禽加临某门」是要断的。现在如实给出它的落宫（`qinPalace`）。
旬首之仪落中五时值符即为天禽，此时它落在何宫，看的正是天芮落在何宫。

⚠️ **两个流派开关在枚举里有、实现里没有**：置闰法（超神接气）与飞盘法。
两者与已实现的拆补／转盘在结论上可以相反，故 `loadParams` **在构建期直接拦下** ——
拿拆补的结果冒充置闰的，等于让 `paramsHash` 说谎，比少一档枚举坏得多。

### 11.4 「方位」这条轴只有奇门说得上话

奇门的九宫本就是空间的（坎北、离南、震东、兑西），故它比六爻、六壬多出一条方位轴。
crossref 会如实标为**单侧**，不让读者误以为另两家默认同意。
这正是把轴定得少而稳的好处：宁可一条轴只有一家表态，
也不要为了凑齐而让另外两家说些它们说不出的话。

**八门的吉凶不入顺逆判定。** 开休生为三吉门、死惊伤为三凶门是传统的分野，
但那是对结果的断言。顺逆只看**门与日干的生克**，与四柱、六爻用的是同一把尺；
门的传统事象另作素材陈述。测试为此配了一条反向对照：
三凶门必须曾经判过中性 —— 若恒判逆，说明是在照吉凶表抄，不是在算生克。

### 11.2 共同词汇

现在只定接口，不实现。三个体系各自产出**同一套结构断言词汇**：

```ts
interface StructuralClaim {
  readonly system: "liuyao" | "liuren" | "qimen" | "bazi";
  readonly axis: "用神力量" | "我方位置" | "对方位置" | "阻碍来源" | "时间窗" | "方位";
  readonly polarity: "顺" | "逆" | "中性";
  readonly evidence: string;
  readonly confidence: number;
}
```

crossref 层只做三件事：**对齐轴**、**报一致**、**报分歧**。不合成。

**四家时更要防的是把对照读成投票。** 「四家有三家判顺」不是七成五的把握 ——
那是把计数当概率，与统计节点那一层禁的是同一件事。故注记里写**谁判什么**
（「六爻、奇门判顺；六壬判逆」），不写比数；且分歧时明写这一句提醒。

**沉默必须写出来。** 三家判顺、一家判中性仍算一致，但注记要说明那一家没表态 ——
不写，读者会把沉默读成默许。

实测 120 个时刻的四家合参：「我方位置」一轴上一致 45 次、分歧 66 次。
家数越多，全体同向越难，故分歧多于一致是应有之义。这条同样写成了不变量：
一致率须低于 60%，压倒性地高反而说明四家其实在算同一件事。

**说得上话的才说。** 六壬只出「我方位置、阻碍来源、事之动静」三条轴 ——
它的应期取法（三传所值、天将所临）与六爻的取候之法不是同一套词汇，
硬对齐会造出「两个体系在同一轴上表态」的假象，而 crossref 会把凑数的断言
当成真的表态。宁可少一条轴。

已有的基础设施够用：

| 体系 | 需要 | 本项目已有？ |
| -- | -- | -- |
| 六壬 | 月将（中气定）、日干支、时支、四课三传、天将 | ✅ **已实现**（P23）—— 见下 |
| 奇门 | 节气、上中下元（符头定）、阴阳遁、九星八门八神 | ✅ **已实现**（P24）—— 见 §11.3 |

两者**都不需要农历** —— §1.2 的农历只为按时起卦而需。

## 15. 反向对照清单（实现时必须配的测试）

沿用本项目一贯做法 —— 每条正向断言配一条反向对照，否则「全绿」可能只是没跑到东西：

| 反向对照 | 防的是什么 |
 -- | -- |
| 64 卦逐卦装卦，与手工核对的黄金卦对账 | 纳甲表抄错 |
| 八宫 × 八卦 = 64，无重无漏，且世应位置与卦序表逐格相符 | 宫序错位 |
| 六亲由卦宫五行推出 —— 断言五类齐全且**互斥**，并逐卦验证「同我者为兄弟」 | 生克方向反了（四柱里犯过三次的同一个错） |
