# 09 · L6 报告系统

报告层把 L0–L5 的结构化输出组织成人可读的内容。**它不做任何新的判断**——报告里出现的每一句结论，都必须能指回某个 `Verdict` 或 `YingqiEvent`。

---

## 1. 报告的三种形态

| 形态 | 载体 | 生成方式 |
| --- | --- | --- |
| **结构化报告** | Web UI | 模板 + 数据绑定，纯确定性 |
| **叙述报告** | Web / Skill | 模板槽位填充；Skill 场景下由模型润色 |
| **交互问答** | Agent Skill | 模型基于 `EvaluatedChart` JSON 回答具体问题 |

三者共用同一份数据。**模型永远不重新计算命理**——它只负责组织语言。这条边界一旦破了，系统就不可复现了。

---

## 3. 叙述生成

### 3.1 槽位模板

每条叙述由 `(结论类型, 状态组合)` 索引到模板，模板中的槽位由数据填充。

```ts
interface LocalizedText { zhHans: string; zhHant?: string; en: string }

interface NarrativeTemplate {
  id: string;
  appliesTo: { source: 'verdict' | 'event' | 'data'; kind: string };
  slots: readonly string[];        // 需要的数据字段
  text: LocalizedText;
  confidenceFloor: number;         // 低于此置信度改用 hedged
  hedged?: LocalizedText;          // 留有余地的措辞，逐语言维护
}
```

原稿把三种语言并列为三个字段、而 `hedgedVariant` 只有一个字符串 —— 二者不自洽，
hedged 同样需要逐语言维护。已合并为 `LocalizedText`。

三条由测试强制的自洽性：

1. **`slots` 与占位符对账。**正常措辞的占位符集合须与 `slots` **完全相等**；
   hedged 只要求是**子集** —— 降级本就可能连同某个细节一并收回
   （`geju` 的 hedged 不再报相神）。两份表述有一份写错，报告里就会留下裸 `{slot}`。
2. **`confidenceFloor > 0` 必须带 `hedged`**，否则降级机制无处可去。
3. **hedged 必须真的在留余地** —— 按限定语查，不按长度查。
   起初这条写作「hedged 不得比正常措辞更短」，是错的：
   `kin.neither` 的 hedged 恰恰**删掉**了「传统上……」那句断语。
   判别本就不可靠时连传统解读一并收回，是正确的降级方向，而它使文本变短。

**`hedgedVariant` 是强制机制。**当 `confidence < confidenceFloor`，系统自动切到留有余地的措辞，而不是把一个 0.3 置信度的判定写成斩钉截铁的断语。

示例：

```
id: strength.weak.standard
confidenceFloor: 0.6
zhHans: "日主{dm}生于{monthBranch}月，同党占 {ratio}，身弱。取{yongshen}为用。"
hedged: "日主{dm}生于{monthBranch}月，同党占 {ratio}，偏向身弱，但距中和仅 {distance}，
        取用需兼看{altYongshen}。此盘属临界格局，两种取法各有依据。"
```

### 3.2 Skill 场景下的模型润色

Agent Skill 中，模型拿到的是 `EvaluatedChart` JSON + 命中的模板列表。它的职责：

- ✅ 把多条模板输出组织成连贯段落
- ✅ 依用户提问聚焦相关部分
- ✅ 解释某个判定是怎么来的（读 `derivation`）
- ❌ **不得**推导新的命理结论
- ❌ **不得**修改任何数值
- ❌ **不得**在数据未支持时补充「通常这种命格会…」

SKILL.md 中会把这四条写成硬约束。

## 5. 导出

- **PDF** —— 完整报告，含方法声明页
- **JSON** —— `EvaluatedChart` 全量，供二次分析
- **Markdown** —— 供 Skill 场景引用

导出必须包含 `paramsHash` 与 `engineVersion`。半年后有人拿着一份旧报告来问「为什么现在算出来不一样」，这两个字段是唯一能回答的依据。

## 6. 措辞约束（硬性）

这一节是**产品规范，不是建议**。违反的输出视为 bug。

### 6.1 禁止的输出形态

- ❌ 断言式预言：「你 2027 年会离婚」「明年必破财」
- ❌ 医疗判断：「你肝不好」「注意心脏病」
- ❌ 财务建议：「今年适合买房」「该年不宜投资」
- ❌ 法律判断：「会有官司」
- ❌ 以神煞名直接作断语：「你有孤鸾煞，婚姻不顺」
- ❌ 对他人的判断：用户输入他人生辰时，不生成针对该人的人格或健康描述
- ❌ 吉凶总分：不给「命格评分 82 分」这类东西

### 6.2 要求的输出形态

- ✅ 描述**结构与张力**：「这一年配偶宫受冲，同时桃花逢合——婚姻领域的张力指数为本年最高」
- ✅ 保留**主体性**：「传统上此结构常被解读为……」而非「你会……」
- ✅ 标注**置信度**：低置信度判定必须带限定词与替代解读
- ✅ 五行与脏腑的对应，只作**传统对照表**呈现，措辞限于「传统上木对应肝胆」，不接任何关于用户身体的推论

### 6.3 强制声明

每份报告首尾各一次：

> 本报告为四柱命理的计算实现，属传统文化研究与自我省思的工具。
> 其中的判定基于传统命理典籍的规则与本系统的量化模型，**不具备预测未来事件的能力**，
> **不构成医疗、法律、财务或任何专业建议**。涉及健康、法律、财务的决策，请咨询相应领域的持证专业人士。

### 6.4 实现方式

措辞约束不能只靠模板作者自觉。

### 拦的是断言的形状，不是词

「禁用词表」这个说法会把实现引到错的方向上。朴素的子串黑名单在本领域**两头都会失败**：

- **误杀**：「病药」是本系统的取用神法之一（`yongshen.priority` 里就有 `bingyao`），
  「疾病」「血光」是神煞表里的传统语义标签。禁掉「病」，等于禁掉自己的术语表。
  一个天天误报的守卫，三天之内就会被关掉。
- **漏放**：「你 2027 年会离婚」里没有任何一个词单独有问题。

所以每条规则由「主体 + 情态 + 后果」构成，词汇本身一律放行。共两种模式：

| 模式 | 语义 | 判定窗口 |
| --- | --- | --- |
| `forbid` | 命中即违规 | 命中处 **±4 字**的 `allow` 豁免窗 |
| `requireContext` | 命中后，所在**整句**必须带框定语 | 句子 |

窗口大小的差别是刻意的。`allow` 要豁免的是「病药」这类紧邻的合法复合词；
若改用整句作窗，「病药用神在此，注意心脏病」会整句放行 —— 那正是要拦的东西。
而 `requireContext` 要求的是叙述框架（「传统上……」），框架本就是句级的。

`requireContext` 正是 §6.2 两条「要求的输出形态」的可执行形式：
五行脏腑对应必须带「传统上」，灾病语汇必须框定为传统关联而非对命主的判断。

### 词汇与断语要分开

`scanText` 的 `kind` 区分二者。神煞标签表里的「血光」是**词汇** ——
一个孤立名词不构成对任何人的断言，`requireContext` 对它不适用；
而报告正文里出现「血光」，就必须带上框定语。禁令类规则对两者一视同仁。

### 放行不得吞掉后续违规

扫描手工推进 `lastIndex`，而非 `matchAll`。原因是一个真实的漏网：

> 「其他情况下，对方身体偏弱。」

正则从第 1 字的「他」起匹配到「他情况下，对方身体」，因豁免窗内有「其他」而放行；
若就此跳过整段匹配，真正的「对方身体偏弱」便再也扫不到。
**放行时只前进一个字符，重新开扫。**

### 三处落点

1. **模板库与全部叙述语料**的扫描，随 `pnpm test` 执行（`pnpm guard` 可单独跑）。
   扫描面不止模板：流月流日的叙述由 `views` 直接生成、不经模板，
   推导链与替代解读也会印进报告 —— 它们同样会显示给读者，同样要扫。
   P7b 的英文漏出（「月支寅害 month 支巳」）正出在这类不经模板的文本上。
2. Skill 的 SKILL.md 中把 §6.1 写成显式禁令（P10）
3. 报告组装完毕即跑一次 `guardReport`，结果随报告返回（`Report.guard`）

### 反向对照是必需的

只断言「扫描全绿」是空转的：扫描根本没跑到东西时它同样全绿。
故有两条配套断言 —— `scanned` 必须大于阈值，且**植入一句违规必须被逮到**。

### 附带的一条硬约束：中文报告里不得漏出英文枚举

内核里的枚举一律用英文标识（`weakened`、`both-favorable`、`luRen`、
`yangForwardYinReverse`…），它们是**代码的词汇**，不是读者的词汇。
`report/labels.ts` 集中维护映射，并由「报告全文不得出现三个及以上连续拉丁字母」的
断言兜底（唯一豁免：出处一行的参数哈希与太阳黄经算法标识，本就是标识符）。

这条断言当场逮到六处：神煞状态、宫星象限、通根等级、载体 id、流派开关、旺衰枚举。
其中旺衰那处出在 L4 的推导链里 —— 分档一步的 `detail` 写作「落入 身弱（WEAK）」。
修法是把枚举移进 `values`：**`detail` 是给人看的散文，`values` 是给机器看的**。

## 7. 国际化

三个语言包：`zh-Hans` · `zh-Hant` · `en`。

**现状：`zh-Hant` 的模板尚未撰写，调用即抛 `UnsupportedLocaleError`，不回落到简体。**
不做简转繁自动转换 —— 本领域的高频字恰好落在一简对多繁的歧义区：
余气→**餘**氣（非余氣）、历法→**曆**法（非歷法）、后天→**後**天（非后天）。
机械转换会在术语上出错，而术语出错的报告比没有报告更糟。
静默回落到简体则等于对外谎称支持了繁体，比抛错更坏。

但**繁体的禁令表已经就位**：Skill 场景下模型可能直接产出繁体，守卫不能有语言盲区。

- 命理术语（十神、神煞、格局）在 `en` 中保留拼音 + 汉字 + 意译三重标注：`Zheng Guan 正官 (Direct Officer)`
- 数值与图表全语言共用
- 措辞约束（§6）在三个语言包中**分别**维护禁用词表——英文的 "will definitely" 与中文的「必然」要各自拦截

默认语言由 UI 决定，`zh-Hans` 为默认。
