# 09 · L6 报告系统

报告层把 L0–L5 的结构化输出组织成人可读的内容。**它不做任何新的判断**——报告里出现的每一句结论，都必须能指回某个 `Verdict` 或 `YingqiEvent`。

---

## 1. 报告的三种形态

| 形态 | 载体 | 生成方式 |
| --- | --- | --- |
| **结构化报告** | Web UI | 模板 + 数据绑定，纯确定性 |
| **叙述报告** | Web / Skill | 模板槽位填充；Skill 场景下由模型润色 |
| **交互问答** | Agent Skill | 模型基于 `EvaluatedChart` JSON 回答具体问题 |

三者共用同一份数据。**模型永远不重新计算命理**——它只负责组织语言。这条边界一旦破了，系统就不可复现了。

---

## 2. 报告结构

```
§1  盘面
    1.1  四柱 + 胎元 + 命宫（含所用规则声明）
    1.2  时间校正明细（时区 / 夏令时 / 经度 / 均时差）
    1.3  纳音、空亡、藏干
    1.4  神煞总览（按宫位分组，非按名称罗列）

§2  力量结构
    2.1  五行权重（雷达图 + 数值表）
    2.2  十神权重（柱状图）
    2.3  五行流通桑基图（L3 的 flows）
    2.4  三项指标：vitality / circulation / evenness
    2.5  结构事件（L2 的 events：哪些合成了、哪些冲破了、哪些库开了）

§3  旺衰与取用
    3.1  日主旺衰（含 r 值、置信度、临界提示）
    3.2  通根明细
    3.3  特殊格局判定（从格 / 专旺 / 化气，或「未命中」）
    3.4  用神 / 喜神 / 忌神 / 仇神 / 闲神
    3.5  月令格局（与 3.4 并列，不合并）
    3.6  ⚠️ 若 3.4 与 3.5 取向不一致，明确并列说明

§4  宫位与六亲
    4.1  四柱八宫总览
    4.2  逐六亲的宫星同参（父 / 母 / 配偶 / 兄弟姐妹 / 子女）
    4.3  每项标注四象限与置信度

§5  大运
    5.1  全部大运一览（干支、起讫年月、三点顺逆指数）
    5.2  逐步展开：前段（重干）气象 / 后段（重支）气象
    5.3  换运时点提示

§6  流年
    6.1  120 年三线曲线（顺逆指数 / vitality / 日主党势）
    6.2  逐年卡片：六柱盘、结构事件、触发的应期规则、按域聚合
    6.3  高张力年份列表（tension 排序）

§7  当前时段
    7.1  本年
    7.2  本月：月柱、神煞、引动、tone、描述
    7.3  今日：五行冲突提示

§8  方法与边界
    8.1  所用流派与规则声明（rulesUsed 全量）

    8.3  待校准项提示
    8.4  声明
```

## 3. 叙述生成

### 3.1 槽位模板

每条叙述由 `(结论类型, 状态组合)` 索引到模板，模板中的槽位由数据填充。

```ts
interface NarrativeTemplate {
  id: string;
  appliesTo: { verdictKind: string; conditions: Record<string, unknown> };
  slots: string[];                 // 需要的数据字段
  zhHans: string;
  zhHant: string;
  en: string;
  confidenceFloor: number;         // 低于此置信度不使用此模板，改用 hedged 版本
  hedgedVariant?: string;          // 低置信度时的措辞
}
```

**`hedgedVariant` 是强制机制。**当 `confidence < confidenceFloor`，系统自动切到留有余地的措辞，而不是把一个 0.3 置信度的判定写成斩钉截铁的断语。

示例：

```
id: strength.weak.standard
confidenceFloor: 0.6
zhHans: "日主{dm}生于{monthBranch}月，同党占 {ratio}，身弱。取{yongshen}为用。"
hedged: "日主{dm}生于{monthBranch}月，同党占 {ratio}，偏向身弱，但距中和仅 {distance}，
        取用需兼看{altYongshen}。此盘属临界格局，两种取法各有依据。"
```

### 3.2 Skill 场景下的模型润色

Agent Skill 中，模型拿到的是 `EvaluatedChart` JSON + 命中的模板列表。它的职责：

- ✅ 把多条模板输出组织成连贯段落
- ✅ 依用户提问聚焦相关部分
- ✅ 解释某个判定是怎么来的（读 `derivation`）
- ❌ **不得**推导新的命理结论
- ❌ **不得**修改任何数值
- ❌ **不得**在数据未支持时补充「通常这种命格会…」

SKILL.md 中会把这四条写成硬约束。

## 4. 可视化

| 图 | 数据源 | 说明 |
| --- | --- | --- |
| 命盘四柱表 | L0 | 干支 + 藏干 + 十神 + 神煞 + 十二长生 |
| 五行雷达 | L3 `byElement` | 叠加「本命 / 当前大运 / 当前流年」三层 |
| 十神柱状 | L4 `tenGods` | 同党/异党分色 |
| **五行流通桑基图** | L3 `flows` | 最有解释力的一张图 |
| 权重迭代曲线 | L3 `convergence.history` | 调试与教学用，默认折叠 |
| 大运长条 | L5 | 每步一段，色深表 `favorIndex` |
| 流年三线图 | L5 | 顺逆指数 / vitality / 日主党势 |
| 月历网格 | L5 | 12 格，每格标 tone 与至多 3 条引动 |

**配色约束**：全部图表使用**中性色阶**（如蓝—灰—橙），禁止红绿吉凶色。顺逆指数低不等于「凶」，用红色会把一个结构性描述变成价值判断。

## 5. 导出

- **PDF** —— 完整报告，含方法声明页
- **JSON** —— `EvaluatedChart` 全量，供二次分析
- **Markdown** —— 供 Skill 场景引用

导出必须包含 `paramsHash` 与 `engineVersion`。半年后有人拿着一份旧报告来问「为什么现在算出来不一样」，这两个字段是唯一能回答的依据。

## 6. 措辞约束（硬性）

这一节是**产品规范，不是建议**。违反的输出视为 bug。

### 6.1 禁止的输出形态

- ❌ 断言式预言：「你 2027 年会离婚」「明年必破财」
- ❌ 医疗判断：「你肝不好」「注意心脏病」
- ❌ 财务建议：「今年适合买房」「该年不宜投资」
- ❌ 法律判断：「会有官司」
- ❌ 以神煞名直接作断语：「你有孤鸾煞，婚姻不顺」
- ❌ 对他人的判断：用户输入他人生辰时，不生成针对该人的人格或健康描述
- ❌ 吉凶总分：不给「命格评分 82 分」这类东西

### 6.2 要求的输出形态

- ✅ 描述**结构与张力**：「这一年配偶宫受冲，同时桃花逢合——婚姻领域的张力指数为本年最高」
- ✅ 保留**主体性**：「传统上此结构常被解读为……」而非「你会……」
- ✅ 标注**置信度**：低置信度判定必须带限定词与替代解读
- ✅ 五行与脏腑的对应，只作**传统对照表**呈现，措辞限于「传统上木对应肝胆」，不接任何关于用户身体的推论

### 6.3 强制声明

每份报告首尾各一次：

> 本报告为四柱命理的计算实现，属传统文化研究与自我省思的工具。
> 其中的判定基于传统命理典籍的规则与本系统的量化模型，**不具备预测未来事件的能力**，
> **不构成医疗、法律、财务或任何专业建议**。涉及健康、法律、财务的决策，请咨询相应领域的持证专业人士。

### 6.4 实现方式

措辞约束不能只靠模板作者自觉。实现上：

1. 模板库有一份**禁用词表**（「必」「一定」「会导致」「注意…病」「不宜投资」…），构建期扫描，命中即构建失败
2. Skill 的 SKILL.md 中把 §6.1 写成显式禁令
3. 报告导出前跑一次输出扫描，命中禁用模式则降级为 hedged 版本并记日志

## 7. 国际化

三个语言包：`zh-Hans` · `zh-Hant` · `en`。

- 命理术语（十神、神煞、格局）在 `en` 中保留拼音 + 汉字 + 意译三重标注：`Zheng Guan 正官 (Direct Officer)`
- 数值与图表全语言共用
- 措辞约束（§6）在三个语言包中**分别**维护禁用词表——英文的 "will definitely" 与中文的「必然」要各自拦截

默认语言由 UI 决定，`zh-Hans` 为默认。
