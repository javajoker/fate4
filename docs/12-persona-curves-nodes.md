## 1. 先厘清四条边界

### 1.0 「不再重新计算基础盘」的准确含义

你写的是：「基础盘是后续计算基准，不再重新计算基础盘。基于基础盘计算新的大运流年时间命盘。」

这句话包含两个可能的读法，**第一个成立，第二个不成立**，必须分开：

| 读法 | 是否成立 | 说明 |
| -- | -- | -- |
| **基础盘只算一次，冻结为定值，一切时点结果都以它为参照** | ✅ **完全照办** | 见 §2.0 |
| **即时盘不再跑全局的结构与生克，只在基础盘上叠加大运流年** | ❌ **做不到，也不该做** | 见下 |

第二个读法为什么不成立 —— 两个具体的反例：

**其一，三合需要全部地支同时在场才看得见。**
本命有寅、午两支，本身只成半合。流年来一个戌，寅午戌三合火局立成，
化神之火大增、非化神之支大减。这个判定**必须**在「本命四支 + 大运支 + 流年支」
的完整支集上重新检测 —— 只看基础盘的结果，永远看不到这个局。

**其二，冲的裁决依赖相对权重，而权重在运内是连续变化的。**
`structure/apply.ts` 中冲的损耗分三档，按强弱比 `ratio` 判：

```
ratio ≥ 2.50  → 拔根，弱方损 75%
ratio ≥ 1.20  → 强方损 20%、弱方损 50%
否则          → 势均，两方各损 35%
```

大运的天干占比自 0.70 线性降到 0.30，地支反向递增。
同一步运里，某个冲的强弱比会随之穿过 1.20 或 2.50 的门槛 ——
**冲的结局会在运程中途改变**。这不是数值噪声，是真实的现象，
而且正是曲线要画出来的东西之一。若把结构冻结在换运那一刻，这一整类变化就消失了。

**所以架构是这样的**：

```
基础盘（算一次，冻结）
  W1_natal = L1(四柱)                    ← 四柱的初始配重
  F_base   = L2(四柱)                    ← 结构因子
  W_base   = L3(W1_natal ⊙ F_base)       ← 冻结。一切 delta 的分母

即时盘 @ t（每个采样点）
  W1_all = W1_natal ∪ L1(大运@t, 流年@t)  ← 四柱部分复用，不重新配重
  F_t    = L2(全部地支)                   ← 全局重检测（三合、冲的裁决）
  W_t    = L3(W1_all ⊙ F_t)
  Δ(t)   = W_t 相对 W_base 的偏离          ← 报告与曲线呈现的量
```

**「不重算」落在两处**：四柱的 L1 配重复用不重算；`W_base` 算一次即冻结，
是所有 delta 的固定分母。**「重算」落在两处**：结构必须全局重检测，
生克必须全局重传导 —— 否则新来的干支就没有作用于命的通道，「运」也就不成其为运。

### 1.1 神煞仍不进入力量模型

你的原话：「神煞更多是给盘面变化一个解释」。方向单向：

```
力量 ──→ 神煞的解读强度（坐旺/坐衰/逢冲/落空/被引动）
神煞 ─╳→ 力量
```

需求 ③ 要「以大运流年神煞为理由」解释异常 —— 这正是单向的用法：
节点由权重曲线检出，检出**之后**再去找那个时点的神煞作为理由。

### 1.2 形体与脏腑：说传统对照，不说这个人

需求 ② 要「长相（五行指事）」与「人体易感的脏腑」，需求 ③ 要「五行指事对应的身体易感部位」。

这两项**可以做**，但必须落在一条明确的线上：

> **陈述「传统对照 + 本盘事实」，不作「关于这个人的判断」。**

具体见 §2.7。可以说「本盘水最弱，占 4.8%；传统上水对应肾与膀胱」——
这是两个可验证的陈述并列。不可以说「肾弱」「易患结石」「注意泌尿系统」——
那是在替读者做推论，而这个系统没有资格做这个推论。

配套的机械约束（§5.3）：**病名一律不得出现在任何报告输出中**，
无条件禁止，不看上下文。器官名可以出现，但只在带「传统上」框定的对照句里。
这条线是可执行的，不靠模板作者自觉。

### 1.3 统计节点是排序工具，不是概率陈述

命盘的时间序列是**确定性的**：大运十年一换、流年六十年一轮、
大运份额线性推移，全部由出生时刻决定。它不是从某个分布抽出的随机样本。

对它算 μ 与 σ，得到的是**这条序列自身的经验散布**。后果：
`|z| ≥ 2` 的采样点必然约占 5%，与这张盘是什么盘无关。

| | |
| -- | -- |
| ✅ 成立 | 「这是本命六十年中，该指标最偏离常态的三段时期」——排序 |
| ❌ 不成立 | 「这一年发生巨变的概率是 5%」——概率 |

报告措辞必须落在前者，由禁用词表拦截（§5.3）。
把百分位包装成统计推断，恰恰会让本来有用的排序失去可信度。

## 2. 基础盘与人格层（需求 ①②）

### 2.0 BaseChart 成为一等对象

现状：`evaluate({ chart })` 在多处被反复调用 —— `yearView` 每年一次、
`monthView` 每月一次、`buildReport` 又一次。它们算的是同一张基础盘，
彼此之间没有「同一个对象」的保证，只有「同一个函数应该给同样结果」的期待。

改为：

```ts
interface BaseChart {
  readonly chart: NatalChart;
  readonly params: Params;
  readonly paramsHash: string;

  /** 四柱的 L1 初始配重。即时盘复用这一份，不重新配重。 */
  readonly l1: readonly Carrier[];
  /** 基础盘的结构事件。 */
  readonly events: readonly StructureEvent[];
  /** **冻结的基础盘权重。一切 delta 的分母。** */
  readonly weights: readonly Carrier[];
  readonly propagation: PropagationResult;
  readonly conclusions: Conclusions;
  readonly shensha: readonly ShenshaHit[];
  readonly persona: Persona;
}

function buildBaseChart(chart: NatalChart, params: Params): BaseChart;
function evaluateAt(base: BaseChart, at: Instant): InstantChart;
```

`evaluateAt` 收 `BaseChart` 而不是 `NatalChart` —— 于是「基准算过一次」
成为**类型层面的事实**，而不是调用方需要记得的纪律。
`InstantChart` 一律携带指回 `base` 的引用与 delta。

**顺带解决的问题**：现在画一条 60 年曲线要重复算 60 次基础盘。
改完之后基础盘算一次，即时盘算 N 次。

| 职责 | 说明 |
| -- | -- |
| **干支五行的呈现** | 二者的干支与五行**单独列出**，不并入加权总量。报告中标为「辅助」 |
| **神煞落点** | 已实现（`mingGong` / `taiyuan` 各有专属宫位，不冒充他柱） |
| **扰动序列** | 命宫支与流年/大运/流月支的冲合刑害，形成一条**扰动曲线**（§3.2） |

第三项是需求 ③ 里「命宫等数值变化」的落法：命宫没有权重，但它有**被引动的程度**。

### 2.2 内 / 外：透干为显，藏支为隐

需求 ② 要「性格偏好」与「外在」。传统里现成的划分是「透干为显，藏支为隐」，
而这个划分**已经在数据里**（载体的 `origin: "revealed" | "hidden"`）。

```
内在分布  I_g = Σ { c.weight : c 为藏干载体, 十神(c) = g }
外在分布  E_g = Σ { c.weight : c 为天干载体, 十神(c) = g }
```

日主自身单列，不计入任一侧（沿用 L4 既有做法）。各自归一化后取三个派生量：

```
显隐比    R = ΣE / (ΣI + ΣE)              外显程度 ∈ [0,1]
内外张力  T = ½ · Σ_k |Î_k − Ê_k|          **按五组算**，k ∈ {比劫,印星,食伤,财星,官杀}
分歧组    按 |Î_k − Ê_k| 降序取前三
```

> **T 必须按五组算，不能按十档。**（实测后修正的一处。）
>
> 外在只有三个天干，与八九个藏干的分布本就难重叠 —— 十档下总变差距离
> 中位数 0.737、5.1% 恰为 1.000。那量的是「外在档位少」，不是「表里不一」。
>
> 按比劫/印星/食伤/财星/官杀五组聚合后：中位数 0.562、顶格率 1.1%，散布可用。
> 五组也是更恰当的粒度 —— 正印与偏印之别，对「表里是否一致」这个问题太细。
> 十档下的值仍然产出（`innerOuterTensionByGod`），但只作明细，不作头条。
>
> **R 的结构区间本就窄**：实测八成的盘落在 0.255–0.361 之间
> （天干占每柱 40%、地支 60%，再经 L3 重分配）。
> 所以 R 只在这个区间内部比较才有意义，报告须给出band 上下文，不宜孤立解读。

**T 不带褒贬。**T 高只表示内在构成与外在构成差异大 ——
传统上既可解为含蓄内敛，也可解为言行不一，取决于分歧落在哪几个十神上。
所以报告必须列出**分歧十神**，而不是只报一个 T 值。

### 2.4 十神 → 特质对照表（四栏）

```ts
interface GodTrait {
  readonly god: TenGod;
  readonly inner: readonly string[];      // 藏而不透
  readonly outer: readonly string[];      // 透干显用
  readonly excess: readonly string[];     // 过旺
  readonly deficient: readonly string[];  // 过弱或缺
}
```

**四栏缺一不可**：同一个十神旺弱表述相反 —— 食神适中为温和从容、太过为疏懒无争；
七杀有制为果决开创、无制为暴戾多惊。只给一栏，强弱两端会说同样的话。

```
过旺  分布占比 > persona.excessShare       0.35
真缺  分布占比 **恰为 0**                  无门槛，无歧义
过弱  0 < 占比 < persona.deficientShare    0.05
```

> **「真缺」与「过弱」必须分开报。**（实测后修正的第二处。）
>
> 原稿只有一档「过弱或缺」，实测每盘平均标出 **4.07 个** ——
> 十档里标四档，等于没标。
>
> 拆开之后：真缺（占比恰为零）每盘均值 2.56 个，且各档分布均匀
> （0 个 2%、1 个 15%、2 个 34%、3 个 29%、4 个 15%），是个有分辨力的量，
> 也正是传统上「四柱缺某神」的准确所指。过弱则降为明细。
>
> 参数校验强制 `excessShare > deficientShare`，
> 否则同一个十神会被同时判为过旺与过弱。

**用词约束**：一律取传统命理的常用表述（自立、竞争、表达、锋芒、务实、灵活、
自律、果决、内省、孤高……），**不用心理学量表词汇**（外向、宜人性、神经质、大五）。
混用会制造虚假的科学感 —— 读者会以为这些词背后有心理测量学的效度，而它们没有。

**底本**：十神性格对应在典籍中分布很散，没有一张现成的表可转录。

#### 2.7.2 三个可算的轴

不直接输出「阴虚」「阳虚」这类中医证型，而是给三个从盘面**可算**的轴，
每个轴都能回溯到具体的权重数字。

**轴一 · 虚实**（量的有余与不足）

```
占比      P(e) = W_e / ΣW
相对偏离  d(e) = (P(e) − 0.20) / 0.20              0.20 = 五行均分
受克份额  S(e) = attack(e) / Σattack
受克偏离  a(e) = (S(e) − 0.20) / 0.20              判据用它

d ≥ +excessBand     且 a ≤ band  →  实
d ≥ +excessBand     且 a >  band  →  实而受制
|d| < band          且 a ≤ band  →  平
|d| < band          且 a >  band  →  平而受制     ← 初稿漏了这一档
d ≤ −deficientBand  且 a ≤ band  →  虚
d ≤ −deficientBand  且 a >  band  →  虚而被伐
```

> **两处实测后的修正。**
>
> **其一，判据不能用「受克 / 自身权重」。**初稿写作 `A = attack(e) / W_e`。
> 低权重必然高比值 —— 虚与被伐由构造耦合，「虚而被伐」只是在复述「虚」。
> 实测按它判时该档占 **32%**，成了最常见的一档，与「值得单独措辞」正好相反。
> 改判**受克份额相对均分的偏离**，与虚实的判据同一形式，且与自身权重解耦。
>
> **其二，「平」那一档也必须看受克。**初稿只列五档，「平」不看 a。
> 于是一个占比适中、却承担了全盘 **2.6 倍**份额克流量的五行，
> 会被报成一个干净的「平」—— 那恰恰是这张盘最值得说的一件事，却被埋掉了。
> 补第六档「平而受制」。
>
> 修正后实测（528 盘 × 5 格）：
> 虚 31% · 平 31% · 实 19% · 实而受制 10% · 虚而被伐 9%，散布可用。

「虚而被伐」与「平而受制」是需要单独措辞的两档：
前者量已不足又持续受克，后者看似无恙而实为众矢之的。其余四档共用句式。

**轴二 · 阴阳**（干的阴阳构成）

```
阳占比(e) = Σ{ W_c : c.element = e, c.polarity = 阳 } / W_e
```

> **这是天干的形式阴阳，不是中医的阴阳。**
> 甲阳乙阴是干支系统里的奇偶，中医的阴阳是阴液与阳气。二者同名而异指。
> 把前者直接说成「阳虚」「阴虚」，是一次未经声明的概念跳跃。
>
> 所以报告的措辞是「本盘木**以阳干为主**」，不是「本盘木阳虚」。
> 「阴阳虚实」四个字合起来的意思由轴一与轴二**并列**给出，
> 而不是合成一个中医证型名。

**轴三 · 寒热燥湿**（命理自己的轴，与内经的五气可对接）

这条轴命理本来就有 —— 调候用的正是它，只是尚未单列成量。

```
热势 = P(火) + 0.5·P(木)                木生火，助热
寒势 = P(水) + 0.5·P(金)                金生水，助寒
寒热 H = 热势 − 寒势        ∈ [−1, 1]

燥势 = P(火) + P(燥土)                  燥土 = 藏于未、戌的土
湿势 = P(水) + P(湿土)                  湿土 = 藏于辰、丑的土
燥湿 D = 燥势 − 湿势        ∈ [−1, 1]

月令修正：生于亥子丑，H −= seasonAdjust；生于巳午未，H += seasonAdjust
```

燥土 / 湿土的划分是命理的通行做法（未戌为燥、辰丑为湿），
本项目已有每个藏干载体的 `hostBranch`，直接可分，不需新数据。

**这条轴是新增的可用产出**：它同时能反哺 §调候 —— 现行调候只看
「冬月火占比 < 8%」这类单点判据，有了连续的 H 与 D 之后可以细化。
但**本次不动调候**，避免一次改两处。

#### 2.7.4 「注意可能的问题」怎么写才不越界

你要的是「描述易感、注意可能的问题」，但「不需要给出明确的病」。
这两句合起来正好划出一条可执行的线，我的落法是：

| 写法 | 判定 | 理由 |
| -- | -- | -- |
| 「你会得肝病」 | ❌ | 预言疾病 |
| 「注意心脏病」 | ❌ | 点名病症并指向读者 |
| 「肝系易感」 | ❌ | 仍是对**这个人身体**下的断语 |
| 「传统养生之说据此提示相应系统宜加留意」 | ✅ | 把「留意」归于传统之说，不归于本系统；不点名病症；带免责导向 |

第四行做到了你要的**功能**（读者知道该留意哪一系），
而没有做出这个系统没资格做的**断言**（这个人的身体如何）。

差别不是修辞技巧。前三行如果出现在报告里，读者会合理地认为
「这套算法诊断出我肝有问题」—— 而它没有，它只是数了一下木的权重。

#### 2.7.5 四条硬约束

| # | 约束 | 落实 |

| 1 | **病名一律不得出现**（癌、肿瘤、结石、中风、梗、炎、糖尿病、高血压…），无条件，不看上下文 | 禁用规则 `zh.medical.diseaseName` |

### 2.8 神煞给出「强在哪里、为什么强」

需求 ② 的最后一句：「根据神煞给出命主性格、指事的解释（强在哪里？为什么强？）」。

神煞不产生结论，它**解释已有的结论**。算法：

```
对人格层的每条结论 c（主导十神、过旺五行、某宫得力…）：
  1. 找出支撑 c 的载体集合 S（如「正官主导」→ 全部正官载体）
  2. 取落在 S 所在宫位上的神煞
  3. 按以下顺序排列作为解释素材：
       tone = strengthened / activated 者优先
       narrativeTags 与 c 的特质词有交集者优先
       其余按 hostWeight 降序
  4. 叙述形如：「{结论}。该{宫位}另见{神煞}，传统上与{标签}一类语汇相联系。」
```

「为什么强」的答案来自**力量层**（通根、司令、透干、得生），
神煞只补「传统上此处还被赋予什么含义」。二者在叙述中分句，不混。

### 3.3 采样：月度

你写的是「按照大运流年的时间（**年度/月度**）命盘」。采月度，理由是曲线本来就是连续的：

- **流年**是阶跃：立春换柱
- **大运**是连续斜坡：天干占比自 0.70 线性降到 0.30，
  每年约有 5.2 个单位的力量从天干移向地支
- **结构的结局也在运内变化**：冲的强弱比会穿过 1.20 / 2.50 门槛（§1.0 反例二）

第三条已实测证实，不是推想：**528 步运里 191 次**出现同一组参与者的事件结局翻转。
形态举例 ——

```
运壬申 · 2013 · 冲(大运↔月柱)    冲而拔根  ⇄  相冲          强弱比穿过 2.50
运丙子 · 2008 · 冲(大运↔月柱)    合解冲    ⇄  相冲          冲合裁决整个反转
运丙子 · 2007 · 六合(月柱↔年柱)  争合      ⇄  合被冲破
```

第二行最要紧：一个原本被合解掉的冲，在运程中途生效了。年度采样看不到这件事。

所以改为**每月一个采样点**：

```
60 年 × 12 = 720 点
120 年 × 12 = 1440 点
```

（写这一节时流月不参与权重，曲线在月度上的变化只来自大运份额的连续推移。
**现在流月默认按流年的一半进权重**，月度变化多了这一个来源，见 §9。
报告与页面都写明流月此刻进不进、进多少，免得读者猜。）

**实测**：60 年 × 12 = 720 点，`buildSeries` 约 **590 ms**（基础盘只算一次；
立春每年解一次牛顿求根，不是每个采样点解一次）。Web 端首次进入曲线页算一次并缓存。

**月内变化确实存在，且两个来源可分**：实测非换运年的月内极差最大 12.1（大运斜坡），
换运年最大 113.1（换柱）。前者正是年度采样会抹掉的那一部分。

> **不能按（大运, 流年）缓存结构检测**：冲的裁决依赖相对权重，
> 而权重逐月推移。缓存会把「运内结局翻转」这个真实现象抹掉。

## 4. 统计节点（需求 ③）

### 4.1 两个量

你的原话：「高于和低于的偏离都会造成变化，表示的是**变化率和变化量**」。

```
变化量  z(t)  = (q(t) − μ) / σ                       水平偏离
变化率  ż(t)  = (q(t) − q(t−P) − μ_Δ) / σ_Δ          同比差分的偏离
```

μ、σ 取该指标在**基准窗**内的中心与散布；μ_Δ、σ_Δ 为差分序列的均值与标准差。

**⚠️ 差分的步长 P 是一整年（月度序列取 12），不是一个月。**

规格初稿写的是一阶差分。实现后实测发现：几乎**每一个**节点都起于寅月。
原因是月度序列被一个周期为 12 的确定性阶跃主导 —— 每年立春换流年柱，
曲线必跳一次。对月度一阶差分做 z 分数，量到的是「立春跳变比月内漂移大」，
而这**永远成立**，与这张盘是什么盘无关。
取同比差分则两端处于同一年内相位，立春的跳变相消，剩下的才是真的趋势变化。
中尺度的序列本就是每步一值，步长取 1。

**节点判据**：`max(|z|, |ż|) ≥ θ`。三种形态分别标注：

| 形态 | 判据 | 含义 |
| -- | -- | -- |
| **持续极端** | 高 \|z\|、低 \|ż\| | 长期处于偏离态 |
| **急速穿越** | 低 \|z\|、高 \|ż\| | 量不极端但变得很快 —— 换运前后的典型形态 |
| **突入极端** | 两者皆高 | 最强 |

只报一个合成分数，会把「一直如此」与「突然变成这样」混为一谈。

**θ 是参数，不是常数。**默认 2（`nodes.threshold`），也可就地覆盖
`findNodes(S, scale, { threshold: 1.5 })`。它没有任何理论地位 ——
序列是确定性的，改 θ 改的是**入选条数**，不是「显著性水平」。
实测大尺度（1990 例盘，60 年）：θ=1.5 → 987 段，θ=2 → 482 段，θ=3 → 99 段（流月进权重，默认）；
流月不进时 481 / 208 / 34 段。（此处原先写的 463 / 221 / 28 是更早的实测，已过时。）

### 4.2 三个尺度

| 节点 | 序列 | 基准窗 | 回答 |
| -- | -- | -- | -- |
| **小** | 月值 | 所在大运的 120 个月 | 这个月在**本运中**有多异常 |
| **中** | 大运步均值（每步一值） | 起运后 60 年的 6 步 | 这一步运在**一生中**有多异常 |
| **大** | 月值 | 起运后 60 年的 720 个月 | 这个时点在**一生中**有多异常 |

**基准窗固定为起运后 60 年，不随报告的时间跨度变**（§5.4）。跨度是 120 / 180 年时，
窗外的年份**也被扫描，但用同一把尺子量** —— μ 与 σ 仍取自头 60 年，
所以同一年的 z 分数在任何跨度下逐位相同。小尺度例外：它的基准是「所在的那一步大运」
本身，与那 60 年无关，窗外的步各用各的。

**⚠️ 采样不足的那一「步」不参与中尺度统计。**统计窗起点通常落在起运之前，
`luckIndex` 为 null 的那一段实测只有 7 个月，它的均值却与整整十年的均值
并列参与统计。实测后果：对一条**纯线性上升**的序列，这个残段自己就能撑出
一个 −2.23σ 的假中节点 —— 一条直线报出了「节点」。
门槛取最长一步的一半，随采样密度自适应，不另设参数。

### 4.3 ⚠️ 中节点必须用稳健估计

样本量只有 6。样本标准差极不稳 —— 任何一步稍偏都会被放大成 2σ，
中节点近乎恒有产出，也就等于没有产出。

```
M   = median(x)
MAD = median(|x − M|)
稳健 z = 0.6745 × (x − M) / MAD
```

0.6745 = Φ⁻¹(0.75)，使 MAD 在正态下等于 σ。
若 `MAD = 0`（六步全同），该指标**不产出中节点**，不做任何回退 ——
没有散布就没有偏离可言。

#### 4.3.1 ⚠️ 但中节点的 σ 比值**不得作为陈述出现**

这一条是实现后加的，起因是量到了下面这组数。
`正印` 的六步大运步均值：

```
4.64   5.39   46.04   4.74   4.97   18.95
M = 5.18   MAD-σ = 0.716   →   z = −0.7  0.3  57.1  −0.6  −0.3  19.2
```

`57.1σ`。而同一张盘的大尺度节点，|z| 最高只有 5.9。
两个数一旦并列，读者会当成同一把尺子上的读数 —— 它们完全不是：
n=6 时 σ 由两个次序统计量估出，四五步取值相近就能把比值推到几十。

这个数**说的事情是对的**，只是不该用这个形式说。它想说的是
「六步里有四步都在 5 上下，这一步是 46」，那就直接这么说：

```
中节点摘要： {label}在 {span}这一步，在这 {steps} 步大运中明显偏离
             （该步 {peakValue}，各步中位 {mean}，{shape}·{direction}）。
中节点展开： …另有 {flatSteps} 步都落在中位附近。
             此处不引「几个标准差」——（说明 n=6 的估计为何不可比）
```

比值仍保留在证据表里，**用来排序**：排序只需单调，不需量纲可比。
同理，中尺度也不单独陈述 ż —— 它在 5 个差分上估出，一样不稳。

### 4.4 节点 = θσ 穿越区间，不是孤立时点

你写的是「得到和 2sigma 的**时间交点**」—— 交点，不是峰值。这个说法更准确，采纳。

```
穿越区间 = max(|z|,|ż|) ≥ θ 的极大连续区间（同号者相隔 ≤ bridge 个采样点则并作一段）
  t_in    进入点
  t_peak  区间内 max(|z|,|ż|) 的极值点
  t_out   离开点
  持续     t_out − t_in
  面积     Σ(max(|z|,|ż|) − θ)        ← 「变化量」的积分形态
```

**桥距按月折算。**`bridgeGapMonths` 的单位是月，而区间合并的单位是**采样点**，
两者只在月度尺度上碰巧相等。中尺度一个采样点是一整步大运（120 月），
若把 2 直接当作 2 个点，就成了「隔二十年也算同一段」。

#### 4.4.1 ⚠️ 月序何时携带信息，何时是伪精度

规格初稿只说「插值只到月」。实现后实测发现，对**权重类序列**连「到月」都是伪精度：

| 序列类 | 节点起于寅月的比例 |
| -- | -- |
| 扰动（吃流月） | 27 % |
| 内外、综合 | 43 %–50 % |
| 十神、五行、宫位、日主、应期域 | **81 %–100 %** |

原因是模型的直陈，不是噪声：**那时流月只入符号层**（`fleetingMonthInWeights: false`，
当时是硬约束），于是立春年内唯一在动的权重来源是大运斜坡，而它缓慢单调；
真正的跳变全部发生在立春换柱那一刻。同比差分消掉了立春在**变化率**上的痕迹，
但**水平**上的年阶跃是真的。

所以 `Series` 带一个 `monthResolving`、节点带一个 `monthResolved`。
**现在流月默认进权重**（§9），权重类的月真的在动，取值随之改变：

```
                          流月进权重（默认）        流月不进（比例 0 / 关）
扰动序列                  报到月                    报到月
十神 / 五行 / 宫位 / 日主  报到月                    报到年
内外 / 综合               报到月                    报到年
应期域                    报到年（年级，不看流月）    报到年
```

流月进权重时，权重类节点起于寅月的比例从 75% 降到 20%（50%，1990 例盘小尺度）——
月现在携带信息了。流月不进时，对权重类写「2046 年寅月起」说的其实是「2046 这个立春年」；
把这件事标出来，而不是藏起来。判据与铺不铺流月载体是同一个（`monthInWeights`：
开关开着**且**比例大于 0），只看开关会把「开着但比例 0」误标为报到月。

#### 4.4.2 为什么没有「覆盖率上限」这条护栏

初版参数里有一条 `maxCoverage`：一段穿越若占满大半个基准窗，
就不是偏离，是基准取错了。**它已删除 —— 因为它永远不会触发**，
而永不触发的护栏只会让人以为有一层其实不存在的保护。

- 中尺度可证：MAD 是偏差的中位数，若过半的点满足 `d ≥ 2.965·MAD`，
  则 `MAD ≥ 2.965·MAD`，只能 `MAD = 0` —— 而那时 σ=0，序列本就被排除。
  故越阈点不超过一半；桥距在中尺度又折算为 0，覆盖率恒 ≤ 0.5。
- 小、大两尺度用样本标准差，`Σz² = n` 强制 `|z| ≥ 2` 的点不超过 n/4，
  变化率一路同理，合并也不到一半；且**桥接不跨号**，
  而尖峰序列的变化率必然一升一降成对出现，链条总被异号段打断。

该性质改由 `nodes.spec.ts` 当作不变量断言（三个尺度 × 三档门槛），
不再当作运行期过滤。

### 4.5 方向不定吉凶，但要标出

`z > 0` 与 `z < 0` **都是节点**。是机会还是压力，取决于指标与用忌的关系：

```
指标属用神向（用神/喜神的十神或五行）：偏离为正 → 偏机会    为负 → 偏压力
指标属忌神向（忌神/仇神）：            偏离为正 → 偏压力    为负 → 偏机会
宫位权重 / 宫位扰动 / 显隐比：         不判方向，只报「该宫变动」
应期域·张力：                          **恒不判方向**
应期域·净值：                          判方向（net = 顺 − 逆，符号即方向）
```

**域张力恒不判方向**：张力本身就是「顺逆并存」的度量，
给它定吉凶等于把已经拆开的东西又合回去 —— 那正是 tension 存在的理由。
**但净值不同**：`net = supporting − opposing`，符号就是方向。
初版两条都写了 neutral，后果是「婚姻感情·净值 −5.94σ」这样的节点一律报
「只报变动」，趋避一节（需求 ⑤）因而几乎空着 —— 而那恰恰是最该有内容的地方。

#### 4.5.1 ⚠️ 定吉凶取**驱动这个峰的那一个分量**

峰按 `max(|z|, |ż|)` 取。若驱动它的是 ż（急速穿越），
该点的水平往往正处在常态附近 —— 用它的符号判吉凶等于掷硬币。
此时改用变化率的方向：升即为正。持续极端与突入极端两种形态下，两者相同。

节点因此带两个符号：`sign`（水平偏离的方向，供陈述）与
`driveSign`（驱动峰的方向，供定吉凶）。

### 4.6 神煞作为「异常的理由」

节点检出**之后**，在 `t_in` 前后一个月的窗口内取即时盘的符号层，取三类作为理由：

```
1. 神煞的 tone 为 activated（被引动）
2. 该窗口内牵动大运或流年的结构事件（三合成局、冲、刑、开库…）
   —— 纯本命的结构在基础盘里就有，不是这一刻的变化
3. 该窗口内触发的应期规则
```

按「与 t_in 的时间距离」升序排列 —— **最靠近进入点的，最像是引发它的**，至多六条。

> **规格初稿另列了两条，实现时未采用**：「神煞落在本节点涉及的宫位上」与
> 「神煞的域标签与本节点的域重叠」。二者都是**静态**匹配 ——
> 本命神煞落在哪个宫、带哪些域标签，是基础盘就定下的，
> 六十年里每一个时点都成立。把它们列为「这一刻变化的理由」，
> 等于给每条节点都配上同一批理由，而恒真的理由不解释任何事。
> 保留的三条都要求**该时刻发生了什么**。

中尺度的理由另走一路：十年之变，因在运不在年，故理由就是那几步大运本身
（「第 4 步大运 乙酉，天干之木为闲神」）。

叙述形如：

> 2031 年 3 月起，官杀曲线进入偏离区（z = 2.3，持续至 2033 年 8 月，
> 2032 年 5 月最甚 z = 3.1）。同期流年支冲日支，配偶宫的驿马被引动，
> 大运支与本命月支三合成局。传统上这三项与变动、迁移一类语汇相联系。

注意末句的形状：**结构事实在前，传统语汇在后，中间不加因果连接词。**

**理由在截断之后才找。**每条理由要跑一次 `evaluateAt` 加一遍应期，约 4 ms。
对全部越阈段都算而后只留前十二条，就是把九成五的工作丢掉 ——
实测浏览器主线程因此卡住近一秒。先排序截断，再给留下来的那几条找理由。

### 4.7 五行指事在节点上的复用

需求 ③ 末句：「五行指事对应的身体易感部位一样可以提出」。

复用 §2.7 的配属表与三条轴，只是取值来自**节点时段**而非基础盘：

```
当某五行序列进入偏离区（偏高或偏低皆算）：
  「{t_in}–{t_out} 期间，{e} 偏离常态（z = {z}，{t_peak} 最甚）。
   该时段 {e} 为{虚实档}，以{阳|阴}干为主，寒热偏{H}、燥湿偏{D}。
   《内经》五行配属中，{e}应{脏}与{腑}，在窍为{窍}，在体为{体}。
   传统养生之说据此提示相应系统宜加留意。
   以上为传统对照与盘面数值的并列陈述，不构成任何关于身体状况的判断，
   亦不指向任何具体病症；健康相关的决定请咨询持证专业人士。」
```

**关键在「偏高或偏低皆算」**：这正是你说的「高于和低于的偏离都会造成变化」。
在内经的框架里二者也对应不同的一侧 —— 太过与不及，都是失衡。

§2.7.5 的四条硬约束**同样适用**，无例外。
节点段的措辞与基础盘段共用同一批模板，只换槽位来源 ——
两处若各写一套，迟早只有一处被守卫扫到。

### 4.8 ±θσ 交点：图上那条线穿过虚线的位置（曲线页）

统计节点（§4.4）是**排序工具**：它用 `max(|z|,|ż|)` 把时段按「有多不寻常」排出先后，
水平偏离与变化率哪个大就取哪个。那是为了不漏掉「值还在常态内但正在急转」的时段。

曲线页上要的是另一件事：**图上这条线在哪一刻穿过了画在图上的那两条虚线。**
那是一个几何问题，答案必须与图上看到的一致 ——
若用 `max(|z|,|ż|)`，会报出曲线明明在两条虚线之间的时段，读图的人只会认为程序错了。

| | 统计节点 §4.4 | ±θσ 交点 §4.8 |
| --- | --- | --- |
| 判据 | `max(\|z\|, \|ż\|) ≥ θ` | `\|z\| ≥ θ` 单独 |
| 用意 | 把时段排序，不漏急转 | 与图上那两条虚线逐点对应 |
| 曲线 | 采样点上的值 | **画出来的那条平滑曲线** |
| 桥接 | 同号且间隔 ≤ bridge 则并段 | 不桥接 —— 离开即断 |
| 落点 | 报告的「起伏段」 | 曲线页的交点表 |

**两者都对，因为问的不是同一个问题。**

#### 4.8.1 在**画出来的**曲线上求交点

函数是 `drawnCrossings(S, series, θ, keep, range?)`。

- `keep` 是图上实际画出的那些采样点（按年采样时每年一个，按月时是全部），
  与曲线页传给图的是同一份。
- 曲线是 Catmull-Rom 转三次贝塞尔（张力 0.5），数学在 `temporal/spline.ts`，
  **图（`charts.tsx` 的 `smoothPath`）与表共用这一份** —— 图里改了张力，表就跟着变；
  不会出现图上穿过去了、表上说没穿的局面。
- 每段细分 16 步找符号变化，再线性折出交点位置，换算成日期：
  `jd = jd[seg] + t · (jd[seg+1] − jd[seg])`。横坐标等间距时贝塞尔的 x 分量对 t 线性，
  所以曲线参数 t 就是这一段里走过的比例。
- **穿入与穿出各给一个大致日期**，并附公历季度（Q1–Q4）。
  日子可以差几天，季度一般不会错。

采样点的日期是 `frames[i].jd` —— 寅月的起点（约 2 月 4 日；按月采样时是各月起点）。
这是**回归年的等分**，不是真節（与真節差中位 0.96 日、最大 3 日，寒露最甚）；
对「大致到哪一周」的精度无碍，故**不求真節**。

##### 一个对账：表与图逐点一致

1990 年例盘，窗口 2007–2016，七杀：在图上用几何量出曲线与 +2σ 虚线的四个交点，
按横轴刻度换算：

| | 图上量得 | 表上给出 |
| --- | --- | --- |
| 上穿 | 2010.507 → 约 2010-08-08 | 2010-08-07 |
| 下穿 | 2011.174 → 约 2011-04-09 | 2011-04-08 |
| 上穿 | 2012.512 → 约 2012-08-09 | 2012-08-09 |
| 下穿 | 2013.264 → 约 2013-05-11 | 2013-05-10 |

差都在一天以内。

#### 4.8.2 ⚠️ 这是「图上」的交点，不是「模型里某一天发生了什么」

权重类序列在立春那一刻**真的阶跃**，年内几乎不动（§4.4.1）。
但按年采样时，图上画的是相邻两个立春之间一条平滑的坡。于是：

```
模型里   2010 年全年低于门槛 ──立春──▶ 2011 年全年高于门槛      跳变发生在 2011-02-04
图上     2010-02 的点在门槛下 ──平滑坡──▶ 2011-02 的点在门槛上    穿线发生在 2010 年内
```

表给的是后者。**两个日期都对，回答的是两个问题。**
想看阶跃本身，把采样切到按月，它就原样画出来了。

##### 这一条是怎么冒出来的

上一版（`d710b6d`）把交点报到日时，对权重类解的是**模型的阶跃那一刻**
（换柱、交节，精确到秒），于是同一行表上写着「穿入 2027-02-04」，
而图上那条线明明在 2026 年上半年就穿过了虚线 —— 读图的人看到的是对不上的。
需求是**图上的交点、大致日期、不必求真節**，所以改成在画出来的曲线上求。

上一版解的东西（`jieMonthBounds` 解真節、`Series.withinBlock` 区分阶梯与斜坡、
按 `precisionBandOf` 分档的误差半径）因此整体撤下 —— 它们回答的是
「模型里哪一刻」，而这一页要回答的是「图上哪一处」。

#### 4.8.3 相邻穿越要并成一段

```
一段 = |z| ≥ θ 且同号的极大连续区间（在细分后的曲线上）
  enterAt  曲线上穿过 ±θ 进入的那一处；窗口起点就在门槛外则为 null
  exitAt   曲线穿出的那一处；到窗口末尾仍未回则为 null
  peak     段内越线的**采样点**里 |z| 最大的那个
```

不并段的话，一条在门槛附近摆动的曲线能吐出几十个交点 ——
**逐个都真，合起来什么也说不出**。

`enterAt` 为 `null` 时不拿窗口起点冒充穿越时刻；
`exitAt` 为 `null` 时不拿末点冒充穿出时刻。

#### 4.8.4 平滑造成的伪影要丢掉

Catmull-Rom 会在两个采样点之间轻微**过冲**：两个采样点都是 1.9σ、
两侧是 −1.9σ 时，中间会鼓到 (1.9+17.1+17.1+1.9)/16 ≈ 2.375σ，越过 2。
若一段「越线」的曲线里**一个采样点都没越线**，那是平滑画出来的，数据里没有 ——
不列。测试里先断言曲线中点确实越线（证明这条不是空转），再断言结果为空，
并做过变异验证：去掉那行丢弃，两条测试同时垮。

#### 4.8.5 σ = 0 返回空，不返回一串 0/0

一条恒定序列的 σ 是 0，`(v − center) / 0` 得 `NaN` 或 `±Infinity`，
两者与 θ 比较都给得出「结果」—— 而那个结果毫无意义。显式判 `sigma > 0`。

μ 与 σ 取自 `curveStats`（月度全样本），**不随 `keep` 变、不随窗口变** ——
抽稀只是少画了点，没有换一把尺子；放大只改看哪一段。

#### 4.8.6 它不是吉凶

交点表给三样东西：**哪条曲线、朝哪个方向、什么时候**。
方向栏写的是该序列的用神 / 忌神倾向（§4.5），那是**序列的属性，不是这个时段的结论**。
一条忌神向序列越过 +2σ，说的是「这个量此刻远高于它自己的常态」，
不是「这段时间不好」—— 后者要看驱动这个峰的是哪一个分量（§4.5.1），
而那件事在统计节点那一页做，不在这一页。

### 4.9 节点页的分页与排序

统计节点页原先只列前 12 条（`params.nodes.maxShown`），而且是按偏离程度排好**之后**才截断的。
跨度是 120 / 180 年时越阈段成百上千（1990 例盘大尺度：60 年 482、120 年 1170、180 年 1657；
流月不进时 208 / 533 / 745），
读者没法翻到后面，也没法换成按年份看。现在可以分页，可以在两种排序间切换：

| 排序 | 含义 |
| --- | --- |
| 按偏离程度（默认） | \|峰值 z\| 大者在前 —— 与此前截断前的排法一致 |
| 按年份先后 | 进入那一刻早者在前；同一时刻进入的，偏离大的在前；仍相同则按序列名，次序确定 |

**怎么实现**（`temporal/nodes.ts`）：把 `findNodes` 拆成「扫描一次」与「取一页」：

```
scanNodes(S, scale, override?) → NodeScan { total, excluded, count(filter?), page({order, offset, size, filter?}) }
findNodes(S, scale, override?) = scanNodes(...).page({ order: "deviation", offset: 0, size: maxShown })
```

`findNodes` 走同一条路径，二者不会各自漂开。**重构前后 60 年的节点输出逐位相同**
（沿用 §5.1 那份金标准快照，3 张盘 × 3 个尺度，逐字节比对）。

三个要点：

1. **理由只给当前这一页找。**理由要跑 `evaluateAt` 与一遍应期，每条约 4 ms，
   越阈段有几百条，全算一遍是好几秒。扫描只做一次，页内再找，并缓存 ——
   翻回来的页是同一批对象，不重算。`buildFindings` 同样只给当前页生成。
2. **过滤在排序与切页之前。**普通读者档要略去未到来的时段（§4.5 的披露规则）。
   若先切页再略去，一页 12 条里略去 5 条，读者看到的是一页 7 条，
   而总页数还按没略去的算 —— 页是被切短的。先过滤再切页，每一页才是满的，页数才是真的。
   实测（1990 例盘 120 年，流月不进时）：普通读者档 103 段（9 页，末页 7 条，全是已过去的年份），
   命理师档 533 段（45 页）。流月进权重（默认）时分别是 228 段与 1170 段。
3. **换尺度、门槛、排序、跨度、读者档，页码都回到第一页** —— 旧页码指向的已是另一份清单。
   每条前面标全局序号（第 13–24 条……），翻页后不会失去位置感。

页码条顶上与底下各一条，翻到底不必滚回去；页数少于一页时不显示。

**测试**（`nodes.spec.ts`，9 条）：各页拼起来恰是完整清单（不重、不漏）；
两种排序是同一批节点；按偏离程度整条清单单调不增；按年份整条清单单调不减
且同一时刻偏离大的在前；过滤后每页仍是满的、页数是真的；越过末页给空页；
翻回来的页是同一批对象；`findNodes` 就是「偏离程度、第一页」。
变异验证：把过滤挪到切页之后，「过滤在切页之前」失败；去掉缓存，「同一批对象」失败。

报告 §6.5 与命令行 `--nodes` 仍是每个尺度前 `maxShown` 条，不分页 ——
Markdown / JSON 是一次性输出，翻页是交互才有的东西。

## 4a. 两层结论与趋吉避凶（需求 ④⑤）

### 4a.1 一条不变量：摘要里的每个数字，都必须在展开层的证据里找得到

需求 ④ 是「默认输出简单结论，点击查看详细解释」。分两层写的报告有一种
**特有的失真方式**：摘要写「财运向好」，展开写「财星被劫、比劫夺财」，
两层各自都不算错，合起来却把一个有保留的判断变成了无保留的断言 ——
而**读者通常只看一层**。

`auditFinding` 把摘要里出现的每一个数字抠出来，逐个要求它等于某条
`Evidence` 的规范化取值，**构建期即执行**，对不上直接抛。

```
Evidence { label, value, unit, ref }
  unit   sigma | value | share | count | year | months
  ref    node:tenGod.正财 | shensha:羊刃 | luck:4 | series:window

formatEvidence 是全系统唯一把 Evidence 变成串的地方 ——
摘要写 3.5、展开写 3.54，机械比对便认不出它们是同一个数。
```

它拦不住形容词层面的失真（那需要语义判断，此处不假装能做到），
但拦得住数字层面的，而分层报告出问题十有八九正是这一种。

两条实现上的教训：

- **取值精度随量级走**（`unit: "value"`）。一律 `toFixed(1)` 会把
  同党占比的 `0.473` 与 `0.358` 压成 `0.5` 与 `0.4` ——
  读起来像两个几乎相同的数在争谁更偏离，而它们相差整整一个 MAD。
- **区间连字符不是负号**。审计第一次跑就报了警，抓的是它自己：
  `2003–2004 年` 里的破折号被半角化成减号，`–2004` 于是被读成一个负数。
  只把真正的减号（U+2212）半角化，破折号留着。

**摘要也走模板。**§0 的硬约束是「报告层不做新判断」，而摘要是最容易破这条
规矩的地方 —— 它短、要好读、又最显眼。故摘要与展开走同一套模板机制，
同样受置信度降级与措辞守卫管辖。

**吉凶取向单独存字段。**摘要措辞随尺度而变（中尺度不引 σ 比值），
拿字符串去判方向早晚会读错 —— 初版的测试正是这么写的。

### 4a.2 趋吉避凶

需求 ⑤ 是「可能遇到的问题、神煞诱因、注意的规避方案」。三者一一对应：

```
problem   哪一域、什么形态 —— 只写结构，不写具体事件
trigger   该节点自己的神煞理由（§4.6 的第一类）
line      传统趋避之说 —— 描述姿态，不指派动作
```

只对**压力向**的节点产出。「趋吉」那一半在本系统里只能说成「此段顺遂」，
那是同一句话换个说法，不另立一条；不判方向的节点同样不产出 ——
张力本就是顺逆并存的度量，给它派一个规避方案等于把已经拆开的东西又合回去。

三种形态各配一句姿态性的话：

| 形态 | 传统趋避之说主张 |
| -- | -- |
| 持续极端（一段状态） | 以守代攻、缓图为上 |
| 急速穿越（一次转折） | 凡事多留一分回旋，不轻许诺 |
| 突入极端（两者兼有） | 先安内而后图外，不宜多头并进 |

#### 4a.2.1 ⚠️ 每条趋避自带传统框定与免责导向

**因为它是全份报告里最容易被单独复制走的一块。**一句孤零零的「宜守不宜攻」
就是建议，无论它原本挂在多少免责声明底下。故三条各自是**完整成句**的模板，
而不是「框架 + 可插拔的短语」。

写成片段的那一版被措辞守卫当场拦下了，守卫是对的：那个串一旦存在于模板库里，
就是一句可以被原样摘走的行动指令，无论调用方本来打算把它插进多完整的框定里。

判定域是**段**，与脏腑段同一个理由、同一种做法（见 §5.3）。

### 4a.3 一条趋避都没有时，必须说清那不等于「一生平顺」

```
「本命六十年中没有张力显著偏高的时段可供列举。这说的是这条序列自身的散布较平，
  不是「一生平顺」—— 同一套判据在任何一张盘上都只挑出最偏的那几段。」
```

空着会被读成「一生平顺」，而那是这套判据根本不能支持的结论。

> ### 界面上的跨度：60 / 120 / 180 年
>
> 生命曲线页可以把绘制跨度切到 120 或 180 年（`buildSeries(base, { years })`）。
> 两条规矩：
>
> **一、跨度要连大运柱数一起换。** 大运由 `temporal.luckPillarCount` 定，
> 默认 12 柱 = 120 年。只拉年数不加柱，末尾那些帧 `luckPillar === null` ——
> 曲线少了一整层，而那个断口看起来像一个真实的转折。
> 实测：180 年配 12 柱，**三分之一的帧没有大运**。
> 故每一档带上它需要的柱数（⌈N/10⌉），由 `test/series.spec.ts` 断言，
> 并带反向对照（柱数不够时确实缺一大片）。
>
> 页面另建一份带足够柱数的基础盘，**不改全局参数** ——
> 改了会连带改掉大运页、报告与节点页的范围，而用户只是想把这一张图拉长。
>
> ### 横轴缩放：拖一段即放大
>
> `LifeCurves` 收 `window` 与 `onWindow`。要紧的是**三个下标空间**别搞混：
>
> ```
> 1 帧下标      S.frames 里的位置        —— 调用方持有
> 2 显示下标    抽稀之后，组件收到的数组  —— 组件只管这一层
> 3 像素
> ```
>
> 缩放只改 2 → 3 的映射，**不裁数组** —— 一裁，`mark` 与 `luckBreaks`
> 的下标就全错位，而那种错位画出来像真的。`onPick` 回的仍是显示下标，
> 由调用方按原来的 `keep` 换回帧下标。
>
> 换跨度或换采样密度时窗口必须清空：那两样都会改变显示下标的含义，
> 旧窗口的下标会指向另一段时间。
>
> 拖动不足三格当作点选 —— 否则手一抖就把图缩到两个月宽，
> 而用户以为自己只是点了一下。SVG 上加 `userSelect: none`，
> 不然拖选时会顺手把坐标轴文字也选中。
>
> **纵轴不随窗口重算。** 否则同一个 z 值会因为缩放到哪里而落在不同高度，
> 而「纵向位置 = 离这条序列自己的常态有多远」这个意思就没了。
> 与下面那条是同一个道理：**显示选择不得改变数值的含义。**
>
> **二、`spanYears` 不跟着跨度走 —— 基准窗恒为头 60 年。**
> `buildSeries` 里取 `min(opts.statsYears ?? spanYears, years)`，故基准窗恒为头 60 年。
> 这一条要紧：若基准跟着跨度走，同一年的 z 分数会随**用户把跨度拖到哪里**
> 而变 —— 一个统计节点会因为显示选择而出现或消失。
> **节点是盘的性质，不是界面状态的函数。**
>
> **这条规矩经历过一次反复，把经过记下来，因为这个取舍会被反复想起：**
>
> 1. 最初：基准窗恒为头 60 年（上面这条）。
> 2. 做「报告时间跨度」时，用户要求「跨度换了，2σ 要重新计算」，
>    于是改成基准窗 = 整个跨度（`statsYears = years`）。当时就写明了代价：
>    同一年的 z 分数、哪些年越线随跨度而变；切到 120 / 180 年，基准里纳入第 60 年之后
>    那些已超出寿数的年份，会拉大或压低 σ。
> 3. 用户看到之后**选择回到原算法**：基准窗取 60 年。现行行为即此。
>
> 但回去不是把第 2 步原样撤销，因为那一步有一个副作用：跨度只是「看多远」，
> 要让窗外的年份**也被扫描**（统计节点页切到 120 / 180 年才有东西可看），
> 就不能再让「算 μ、σ 的值」和「被扫描的值」是同一批。
> `findNodes` 因此把两者拆开（`ScanGroup`：`scan` 是被扫描的点，`baseVals` 是基准）：
>
> | 尺度 | 基准取自 | 扫描 |
> | --- | --- | --- |
> | 大 | 基准窗内的月值（头 60 年） | 整个跨度 |
> | 中 | 基准窗内的那几步均值；窗口边缘那一步在基准里只有残段 | 整个跨度里每一步的完整均值 |
> | 小 | 所在的那一步自己（与 60 年无关） | 整个跨度，窗外的步各用各的 |
>
> 同比差分的散布（`rz` 用的 σ_Δ）同样只取基准，与 μ、σ 同一口径。
>
> **重构前后 60 年的节点输出逐位相同。**这是一次改核心检出算法，所以事先拍了
> 金标准快照：3 张盘 × 3 个尺度（共 1.1 MB 序列化输出），重构后逐字节比对相同，
> 46 条节点测试照常通过。窗口边缘那一步在 60 年时与重构前一样（扫描 = 基准）。
>
> 测试（`span.spec.ts`）：同一年的 z 分数在三个跨度下逐位相同；μ 与 σ 逐位不变；
> 窗内、且远离窗口边界的节点三个跨度下逐位相同；60 年时窗外没有节点、120 / 180 年时有。
> 两条反向对照：把「基准窗 = 跨度」显式造出来，σ 与 60 年时不同；
> 基准随跨度时窗外节点的 σ 不同。变异验证：让 σ 取自被扫描的值、
> 让 `seriesForSpan` 的基准窗跟着跨度，各有 4 条与 7 条测试失败。

### 5.3 新增禁用规则

```

zh.guidance.prescription  趋避不得指派动作（P16 新增）
  pattern  (?:应当|应该|务必|切记|建议|最好|千万)[^。；！？\n]{0,8}
           (?:去|别|不要|停止|辞职|跳槽|搬家|签约|结婚|离婚|生育|
              手术|服药|就医|体检|求医|吃药)
  why      趋避一节最容易被单独复制走，而一句孤零零的行动指令就是建议 ——
           无论它原本挂在多少免责声明底下。传统趋避之说只描述姿态。

zh.guidance.framing       趋避语句须同时带传统框定语与免责导向（P16 新增）
  mode     requireContext
  domain   paragraph
  pattern  趋吉避凶|趋避之说|宜守|以守代攻|缓图|不轻许诺|先安内
  context  (?=[\s\S]*(?:传统|旧说|之说|典籍|古人))
           (?=[\s\S]*(?:不构成|请咨询|非建议))
  why      与 zh.body.framing 同一个理由：趋避条目会被逐条摘出来读，
           框定与免责都得在这一条自己身上，不能指望报告里别处的那句。

zh.remedy.imperative      对治不得写成祈使句（若日后加对治层）
zh.remedy.commerce        不得导向任何消费（佩戴/开光/请一尊/转运/法器…）
```

**这两条把「片段模板」这条路堵死了。**趋避初版抽了三条
`guidance.attention.*` 片段（「以守代攻、缓图为上」），由 `guidance.item`
拼装 —— 守卫扫模板库时当场拦下。改法不是放宽守卫，而是让片段不存在：
三种形态各自是一条完整成句、自带框定与免责的模板。

**一条实现上的注意**：`zh.body.framing` 的 `context` 用了两个前瞻断言，
必须在**整段**（而非整句）上求值 —— 框定语在段首、免责语在段尾是正常的写法。
故这条规则的判定域是「段」，需要 `scanText` 支持第三种判定域。
现行守卫只有「±4 字窗」与「整句」两档，需新增「整段」。


### 5.4 报告的时间跨度：60 / 120 / 180 年

曲线、流年、统计节点、大运、完整报告原本各管各的年数（曲线 60、流年曲线 120、
节点基准 60、大运 12 柱）。要让它们**一起**切，就得有一个说法：

```
跨度 = 自起运起算的年数，取 60 | 120 | 180
大运柱数 = 跨度 / 10                      一步十年
```

| | 60 年（默认） | 120 年 | 180 年 |
| --- | --- | --- | --- |
| 大运柱数 | 6 | 12 | 18 |
| §6.1 流年曲线 | 60 年 | 120 年 | 180 年 |
| §6.5 节点扫描 | 60 年 | 120 年 | 180 年 |
| §6.5 节点**基准窗** | 60 年 | 60 年 | 60 年（**不随跨度变**） |

**一处定义**：`temporal/span.ts`（`SPANS`、`DEFAULT_SPAN`、`baseForSpan`、`seriesForSpan`）。
各页各调各的，迟早有一页停在旧跨度上而别的页已经换了。

**入口**：

- `buildReport(base, { span })`；不给就是 60。默认值放在 core 里，Web 与 CLI 才同源。
- 网页顶栏一个**全局**开关（只在大运 / 流年 / 生命曲线 / 统计节点 / 完整报告五页出现；
  其余页读的是本命，与跨度无关，摆上去只会让人以为它也管那一页）。
  存在本机，**不进命盘的参数覆盖** —— 它是看的人的偏好，不是这张盘的参数，
  与读者档同理，分享链接不该把它带给别人。
- `fate report --span` 与 `fate luck --span`；Skill 的 `report.sh` 透传。非法值报错，不静默取默认。
- **移动版**（`/m` 关于你、`/m/time` 按年）也有同一个开关，存在**同一个本机键**
  （`fate.span.v1`）—— 同一台设备上是同一个偏好，手机上切了桌面版也跟着。
  `useSpan` 把「选中的」与「已用于计算的」分成两个值：切到 180 年，节点要按月跑
  2160 个点，手机上是好几秒的同步计算；先让界面画出「正在重新计算」，再去做那段重活，
  不让计算变快，只让用户知道发生了什么，免得点了没反应又点第二下。
  普通读者档本来就不给未到来的时段，切长往往看不出变化，界面上写明了这一点。
  `/m/time` 的按年列表默认只列前 16 年，跨度更长时「展开全部」才出。

**大运柱数不够就另建一份基础盘**（`baseForSpan`）。柱数够时原样返回同一个对象；
不够才另建，**不改传入的那一份**。另建的盘与原盘在已有的柱上逐柱相同，只是更长。

**参数指纹不随跨度变。**另建的盘 `luckPillarCount` 不同，若指纹跟着它走，同一张盘
同样的参数只因换了跨度就得到不同的指纹，而逐年的数其实一位不差。
故指纹取**传入的那份**基础盘；跨度单独记在 `meta.span`。
指纹相同、跨度不同的两份报告：**逐年的数相同，同一年的 z 分数也相同**（§4.2：基准窗不随跨度变），
只是后者看得更远、大运列得更多。报告 §8 方法一节写明跨度与这一点；
`NodesSection` 另带 `statsFrom / statsTo`（基准窗）与 `scanTo`（扫到哪一年），
精度地平线据 `scanTo` 覆盖到节点实际扫到的年份。

**默认值改变了什么**（60 年，与节点基准窗一贯的取值一致，默认下节点与 σ 逐位不变 ——
重构检出算法前后用金标准快照逐位比对过，见 §5.1 末的说明）：

| | 此前默认 | 现在默认 |
| --- | --- | --- |
| §6.1 流年曲线 | 120 年 | 60 年 |
| §5 大运列 | 12 柱 | 6 柱 |
| §6.5 节点扫描 / 基准窗 | 60 年 / 60 年 | 60 年 / 60 年（不变） |

要回到旧的长度，传 `--span 120`。`temporal.yearRangeYears` 参数随之取消（被跨度取代，
留着就是一个没人读的死参数）。移动版只取曲线前 16 年，不受影响。

**精度地平线自然跟着走**：60 年的报告对 1990 年的盘只到 2058，越过 2050 的容差线，
没越过 2100 的跨度；180 年则到 2170，两条都越。`method.horizon` 本来就从已装配的各节
取年份，不另推一遍（§5.3 的同一条规矩），所以不需要为跨度另写一份警告。

**测试**：`span.spec.ts` 15 条、`cli.spec.ts` 5 条。三条是对照：

1. **60 年时与此前逐位相同**（以旧的 `buildSeries(base)` 为参照，逐序列比 values、μ、σ）；
2. **同一年的 z 分数在三个跨度下逐位相同**，μ 与 σ 逐位不变；
3. **逐年数值不随跨度变**；
4. **反向对照**：把「基准窗 = 跨度」显式造出来（被推翻过的做法），σ 与 60 年时不同 ——
   若 `seriesForSpan` 其实让基准随跨度走，上面几条与这条会同时暴露。

变异验证：把 `seriesForSpan` 的基准窗改成跟着跨度，「曲线画满整个跨度、基准窗仍只有 60 年」
「μ 与 σ 逐位不变」「z 分数逐位相同」等 7 条同时失败；让节点的 σ 取自被扫描的值，4 条失败。

### 6.7 曲线页三件后续（跨度、缩放、交点）完成记录

### 6.8 交点报到日：做了一版，被图纠正，改了

这一节记的是一次**方向错了又改回来**。

**第一版**（`d710b6d`）把交点报到日，做得很讲究：权重类的跳变是立春换柱，
就去解换柱那一刻（精确到秒）；流月换支是节，就去解真節；
区间里同时有两个边界就老实说归因不唯一；连地平线都按 `precisionBandOf` 分档。
实测 157 个交点里 154 个是这样得到的。

**然后用户把图和表并排截了张图**：七杀曲线在 2026 年上半年穿过 +2σ 虚线，
表上却写 2027-02-04。表上那个日期没错 —— 模型里跳变确实发生在 2027 年立春 ——
但**读图的人看的是图**，而图上不是那样的。

| 第一版回答的 | 用户问的 |
| -- | -- |
| 模型里哪一刻发生了跳变 | **图上**那条线哪一处穿过了虚线 |
| 精确到秒，要解真節 | **大致日期**，不必求真節 |

两个问题都正当，但这一页的读者问的是第二个。
于是第一版整体撤下（`jieMonthBounds` 求真節、`Series.withinBlock`、
误差半径与四种「来历」），换成在**画出来的曲线**上求交点（§4.8.1）。

这次修正里值得记下的几件事：

1. **图与表共用一份曲线数学。**`spline.ts` 里的 `catmullRomControls`
   被图的 `smoothPath` 和表的 `drawnCrossings` 同时调用，不是两份各写一遍。
2. **用闭式答案核日期，不拿实现去核实现。**统计窗之外的帧不影响 μ 与 σ，
   于是在那里摆精确的 z 形状（`[0,1,2,3,4]` 在门槛 2.5 上穿过第 2、3 点正中），
   日期有公式可算。
3. **真盘上的核对是独立的**：在浏览器里用 DOM 量出曲线与虚线的几何交点，
   按刻度换算成日期，与表逐行对账（§4.8.1 那张表），差都在一天内。
4. **丢弃平滑过冲的伪影有变异验证**（§4.8.4）。
5. 不替读者隐瞒那个落差：表下的说明直接写明「这是图上的交点，
   不是模型里某一天发生了什么」，并告诉他切到按月就能看见阶跃本身。

`nodes.spec.ts` 里这一组共 17 条，两条是反向对照：
线性点列上的闭式答案；以及上一版修的那个错（`[0,0,1.9,7,7,7]` 里，
穿入日期必须落在越线那个采样点**之前**，而不是等于它）。

**面板开关**是读这一页时的实际障碍引出的：
图、交点表、神煞、权重、全序列统计原本是一条长栏，
后果是**图与正在读的那张表永远不在同一屏** ——
点一行跳到某个时点，滚回去看图，标记线早滚出视野。
故给两个开关：出哪几块，以及要不要并排（左列 sticky）。
默认全出、单列，与原先一致 —— 不替读者决定他该看什么。

CSS 上有一处值得记：并排用 `minmax(0, 1fr)` 而非 `1fr`。
grid 轨道默认最小尺寸是 `auto`，里面一张宽表会把轨道顶开，整页横向滚动，
`.scroll` 就白写了。另外交点表在半幅宽下会把日期折成「1999-02-」「04」两截 ——
**一个被折断的日期比没有日期更坏**，故整表 `nowrap`，由 `.scroll` 横滚。

## 9. 流月进权重（默认开，流年的 50%）

> 流月原先「不进权重」是硬约束。它先在实验分支上试过（下文 9.2–9.6 是当时的发现），
> 然后**定为默认：流月按流年的一半进权重**，并入主线。0 即不进，与关掉开关逐位相同。
> 默认开启时另修了一处：年级的应期域改在不含流月的盘面上判（§9.8）。

### 9.1 做什么

| 项 | 值 |
| --- | --- |
| 开关 | `series.fleetingMonthInWeights`（**默认 `true`**） |
| 配重 | `weights.fleetingMonth.ratioToYear`（**默认 0.5**）：流月总量 = 流年 × 比例（110 → 55），干支内部按流年的 40:70 同比缩放。曲线页可临时切 **0% / 25% / 50%**，只改那一页 |
| 载体 | 新增 `PillarKind` `"fleetingMonth"`；比例为 0 时一个载体都不铺（见 §9.2） |
| 作用范围 | 曲线、统计节点、报告 §6.5；月历视图仍不给权重；开与关的参数指纹不同，数不可相比；已列入待校准清单 |
| 桌面版 | 参数校准页两项（随盘保存）；曲线页可临时切 0 / 25% / 50%，只改那一页 |
| 移动版 | 「关于你」页「每个月算多少分量」：不算 / 一年的 25% / 一年的 50%（默认）。存在本机 `fate.m.monthRatio.v1`，**不与桌面版共用** —— 桌面版的比例是那张盘的参数，移动版没有逐盘参数，存的是看的人的偏好。「关于你」与「时间」两页按同一个值算 |

取比例而非绝对数：流年的总量日后若重新校准，流月跟着走，两者的相对大小不会悄悄漂开。

主线另有一条 `temporal.monthLayer.recomputeWeights: false`，它管的是**月历视图**
（`monthView`）的月层，与曲线上的这个实验开关是两回事，互不影响。

### 9.2 第一版的比例是摆设 —— 以及为什么

第一版只让流月载体的**总量**等于流年的一个比例。扫描比例时发现：
**比例设成 0（载体在场、权重为零），年内月间变化中位数仍有 0.115σ**（关时 0.004σ），
23% 的月间跳变 ≥ 0.3σ；0.0001 与 0.05 的效应几乎一样。

原因是有四处**只看「有没有」、不看质量**的地方，零权重的载体照样起作用：

| 位置 | 为什么不看质量 | 修法 |
| --- | --- | --- |
| 结构事件（合绊、刑、破、冲、局） | 事件威力不随参与者的权重缩放；零权重的流月照样合绊本命、削掉别人五六分 | 牵涉流月的事件，距离系数乘比例；绑缚向「无操作」同比靠拢 |
| L3 传导的受方分摊 | 流量按**耦合强度**分摊给受方，与受方的质量无关（`iterate.ts` 自己的注释：「多个受方是分摊而非倍增」）；0.03 分的载体进了别人的受方集就分走一份流量 | 流月载体带 `couplingScale`（= 比例），作受方时耦合同比缩放 |
| 通根评分 | 按支计一份根，贡献 = 根系数 × 距离 | 同样乘 `couplingScale` |
| 比例为 0 仍铺零权重载体 | 零权重的载体照样触发结构事件 | 比例为 0 时不铺 —— 「比例 0 ≡ 关」逐位相同 |

定位靠的是**量**，不是猜：先看 L2 的逐步记录，各步在 0.001 下几乎不变，差别全在 L3；
再看残留的 2.1% 跳变，100% 来自 `dayMaster.rootScore`。

修正后比例是真旋钮：单调、向 0 连续地回到「关」。
`series.spec.ts` 固化三条第一版缺的性质：比例 0 ≡ 关（逐位相同）；
比例 1e-6 时任何权重动不超过 0.01（第一版是 76 量级）；比例越大月间变化越大。
变异验证：撤掉受方耦合缩放，连续性测试立刻失败（17.3 > 0.01）。

### 9.3 三条离散规则，权重解决不了

修完上面四处，仍有三条规则对流月起**全强度**的作用，因为它们的判定只看有无：

| 规则 | 判定 | 读权重？ | 受影响帧数 | 单次改动 |
| --- | --- | --- | --- | --- |
| 墓库被冲刑则开 | 侦测到冲或刑就开，在互解之前 | 否 | 10 | 权重 7.35 |
| 会局夺合 | 局成则六合不再论（范围大者优先） | 否 | 9 | 解除一处合绊 |
| 争合妒合 | 同一干支进入两个以上合 | 否 | 67 | 活性合计 0.30 |
| *冲合互解（对照）* | 合力与冲力，由参与者权重算出 | **是** | 随比例变 | 冲被判不成立 |

**判断：流月入权重（无论比例多少）解决不了前三条。**10% 与 1/3 下它们受影响的帧数
**完全相同**（10 / 9 / 67）—— 权重根本不是它们的输入。而单次改动不小：
开库一次动 7.35 分，比 10% 时流月自己的全部分量（11.0）的一半还多。

读权重的冲合互解则随流月的权重变：流月合解冲的新增帧数
10% 时 4、25% 时 39、1/3 时 74、50% 时 83（单调）。这是传统说的「流月合解冲」，行为合理。

**选定方案 A：结构层对流月看不见这三条**（`structure/apply.ts`）：

- 牵涉流月的冲、刑不开别人的库；流月自己的支也不论开闭；
- 含流月的三合 / 三会不夺别人的六合；
- 数争合时不计含流月的合。

修后重测，三类漏出全部归零。变异验证：分别撤掉争合 / 会局夺合 / 开库的过滤，
「三条规则对流月看不见」测试各自失败。

不选另两条路：**B**（带流月与不带流月各解一次、按比例线性混合）计算量翻倍、语义难解释；
**C**（让这三条规则读权重）要改规则本身，而它们同样作用于流年与大运，会动主线的行为。

### 9.4 信息不丢：流月应期，注明「流年大运应期」

三条规则对流月看不见之后，「流月冲开了墓库」这类信息不能就此消失。
这些正是传统说的**引动** —— 月、日是扳机，不是力量的来源。
`temporal/monthTrigger.ts` 把它们单独算出，在曲线页神煞一栏的
**「流月应期　流年大运应期」**下展示。

**为什么是「流年大运应期」**：流月不是独立的力量，它引动的是当前流年、大运已经摆好的局面
—— 库在本命、在大运、在流年里；局的另两支也在这几处。拿掉流年大运的背景，
流月单独什么也引动不了。所以它的触发要放回那个背景里读。

怎么算：

- 复用结构层的侦测函数（`detectHe` / `detectClash` / `detectXing`），不另写一套；
  它们只看支与干，不看载体与权重，所以不需要先把盘算一遍。
- **差分**：带流月侦测一遍、不带流月一遍，只报因流月在场才成立的 ——
  本命、大运、流年自己已经成立的，不算流月引动的。
- 不依赖实验开关，开着关着都能展示；只说触发了什么，不说改了多少分，不含吉凶。

页面把原神煞列表里落在流月上的移入应期块，免得重复；应期块还收了
`monthView` 已有的流月神煞与「流月与本命四柱的合冲害破伏吟」。

### 9.5 交叉验证：新模块对旧结构层逐帧一致

新模块是独立写的差分侦测，不能拿它自己去核自己。参照是**旧结构层**
（三条规则还会把流月算进去的那个提交）在同一张盘、同样 720 帧上，实际改动了
本命等自身事件的帧：开库 10、会局夺合 9、争合 67。
把旧提交检出到临时目录、逐帧比对：**三类的帧集合逐帧相同**（只在旧 0、只在新 0）。
`monthTrigger.spec.ts` 把 10 / 9 / 67 固化为锚点。

这次比对逮到了我自己的一个错：第一版会局夺合要求六合的**两支同在一个流月局里**，
只数到 4 帧而不是 9。旧规则判的是「六合的**每个柱**是否被**某个局**吞过」
（各局柱的并集），可以是一个柱被流月的局吞、另一个被本来就有的局吞。
已改成同一语义，补了对应的单元场景（巳申六合：月柱被流月酉成的巳酉丑吞，
大运申被原有的申子辰吞）。

| 比例 | 年内相邻月，中位 | 90% | 小尺度节点 | 权重类节点起于寅月 | 权重类 ±2σ 交点段数 |
| --- | --- | --- | --- | --- | --- |
| 关 | 0.004σ | 0.014σ | 185 | 75% | 76 |
| 10% | 0.050σ | 0.163σ | 285 | 49% | 127 |
| 25% | 0.121σ | 0.399σ | 424 | 33% | 220 |
| **50%（现在的默认）** | **0.230σ** | **0.757σ** | **634** | **20%** | **358** |

（「小尺度节点」一列在 §9.8 的修正之后重量过：应期域不再随流月变，节点比修正前少，
50% 时 730 → 634。其余各列只涉及权重类序列，不受影响。）

### 9.7 已知局限

### 9.8 默认开启后的一处修正：年级应期不看流月

应期规则是年这一级的，写的时候外部柱只有大运与流年。流月进了即时盘之后，
「流年六合本命」把流年与流月相合也算进去，「空亡填实」「驿马被合」被流月的冲合逐月改写。
实测（1990 例盘，50%）720 帧里 **387 帧**的年级应期命中因流月而不同。
现在应期域与节点理由里的应期都在不含流月的即时盘上判（比例为 0 时是同一份，不多算）。
代价是多一遍求解：60 年 0.49 → 0.81 秒，180 年 1.06 → 2.33 秒（笔记本）。
测试：应期域序列在开与关下逐位相同；反向对照显示含流月时应期确实会变。
