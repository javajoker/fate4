## 1. 三条边界

写在最前面，因为它们决定了后面每个算法的形状。

### 1.1 神煞仍不进入力量模型

你的原话：「神煞更多是给盘面变化一个解释」。这与现行架构一致，本次不放开。

神煞在新层里的职责是**为曲线上的拐点提供解释**：节点由权重序列检出，检出**之后**
再去找该时点命中的神煞作为叙述素材。方向仍然单向 ——

```
力量 ──→ 神煞的解读强度（坐旺/坐衰/逢冲/落空）
神煞 ─╳→ 力量
```

一旦让神煞加分，符号层与力量层就混成一锅，产出的东西既不符合古法也不符合量化。

### 1.2 「身体」一节只谈结构张力，不谈身体

需求 ②③ 提到「身体变化诱因」。措辞守卫禁止医疗判断，这一条不放开。可做的是：

- 保留 `health` 域的**张力**曲线 —— 那是结构指标，不是身体状况
- 五行↔脏腑只作传统对照表，措辞限于「传统上木对应肝胆」，且必须带框定语
- 输出一律称「健康域的结构张力」，不称「身体状况」「体质」「易患」
- 该域的节点叙述**强制**附加导向持证专业人士的一句

这不是把需求砍掉：健康域的张力曲线与节点照常产出，只是它描述的是盘面结构，
而不是命主的身体。二者的区别不是措辞技巧，是这个系统有没有资格说的问题。

### 1.3 统计节点是**排序工具**，不是概率陈述

**这一条最重要。**

命盘的年度序列是**确定性的准周期序列** —— 大运十年一换，流年六十年一轮，
干支排列完全由出生时刻决定。它不是从某个分布里抽出来的随机样本。

对这样一条序列算 μ 与 σ，得到的是**这条序列自身的经验散布**，不是「小概率事件」。

后果：|z| ≥ 2 的年份**必然**约占 5%，与这张盘是什么盘无关。所以 ——

| | |
| --- | --- |
| ✅ 成立 | 「这是本命六十年中，该指标最偏离常态的三年」——排序陈述 |
| ❌ 不成立 | 「这一年发生巨变的概率是 5%」——概率陈述 |

报告的措辞必须落在前者。这条会写进禁用词表（见 §5.3），构建期扫描拦截。

把一个百分位筛选包装成统计推断，是这类系统最容易产生的伪精确 ——
而它恰恰会让本来有用的排序失去可信度。

## 2. 基础盘与人格层（需求 ①）

### 2.1 ⚠️ 胎元与命宫是否入权重 —— 需要你先定

你写的是「以四柱**胎元命宫**，干支（地支藏干）后阴阳五行和日主信息……
经过五行生克平衡之后的权重为基础盘」。

现状：胎元不入配重（`weights.includeTaiyuan: false`），命宫连载体都没有 ——
二者只在符号层展示（神煞落点、宫位）。

三个选项：

| | 方案 | 后果 |
| **A** | 维持现状，不入权重 | 今日的一切结论不变。胎元命宫只作符号层 |
| **B** | 入权重，小份额（各 40，对比每柱 100） | 参与流通但不喧宾夺主 |
| **C** | 入权重，等同一柱（各 100） | 两者合计 200，占全盘约三分之一 |

**我建议 B**，理由是**避免同一份信息数两遍**：

- 胎元由**月柱**推得（月干进一、月支进三），它的信息已大部分蕴含在月柱里
- 命宫由**月支与时支**推得，同理

给它们等同一柱的权重，等于把月柱的信息又数了一遍，而月令本已有 2.0 倍放大 ——
会让月令一系的力量被系统性夸大。给小份额则既让它们参与生克流通，
又承认它们是**派生**而非独立的信息源。

**无论选 B 还是 C，警告如下**：旺衰分档、用神、格局、六亲、全部曲线与节点
都会移动，四十个数值参数需要重新校准，现有的全部测试基线作废。
选 A 则今日的一切不变，人格层照样能做（只是不含胎元命宫的力量贡献）。

### 2.2 内 / 外的划分：透干为显，藏支为隐

需求 ① 要「内在性格」与「外在表现偏好」两条。传统里现成的划分是
**「透干为显，藏支为隐」** —— 而这个划分**已经在数据里**（载体的
`origin: "revealed" | "hidden"`），不需要新造概念。

```
内在分布  I_g = Σ { c.weight : c 为藏干载体, 十神(c) = g }
外在分布  E_g = Σ { c.weight : c 为天干载体, 十神(c) = g }
```

日主自身单列，不计入任一侧（沿用 L4 的既有做法）。

各自归一化为分布 Î、Ê（在十神单纯形上），再取三个派生量：

```
显隐比    R = ΣE / (ΣI + ΣE)                 外显程度 ∈ [0,1]
内外张力  T = ½ · Σ_g |Î_g − Ê_g|            总变差距离 ∈ [0,1]
主导十神  内外各取前二（argmax 与次大）
```

**T 是这一层最有意思的量**：它把「表里不一」变成一个可算的数，
且**不带褒贬** —— T 高只表示内在倾向与外在表现的构成差异大，
传统上既可解为含蓄内敛，也可解为言行不一，取决于是哪几个十神在分歧。
报告必须把分歧最大的那两三个十神列出来，而不是只报一个 T 值。

### 2.3 月令不再额外加权

月令是提纲，L1 已给 2.0 倍放大与司令加成。人格层**不再加权**，
否则同一份信息数两遍（同 §2.1 的理由）。

但**司令干**单独标出，作为「本性的底色」—— 它是月令当权者，
在传统里正对应「禀气」。这是标注，不是加权。

### 2.4 十神 → 特质对照表

需要一张 `十神 × 情境 → 表述` 的对照表。这是**新的知识录入**。

四栏，缺一不可：

```ts
interface GodTrait {
  readonly god: TenGod;
  readonly inner: readonly string[];      // 藏而不透
  readonly outer: readonly string[];      // 透干显用
  readonly excess: readonly string[];     // 过旺
  readonly deficient: readonly string[];  // 过弱或缺
}
```

**为什么必须四栏**：同一个十神，旺与弱的表述相反 ——
食神适中为温和从容，太过则为疏懒无争；七杀有制为果决开创，无制则为暴戾多惊。
只给一栏，会让强弱两端说同样的话，那张表就废了。

判据：

```
过旺  Î_g（或 Ê_g）> persona.excessShare      建议 0.35
过弱  < persona.deficientShare                建议 0.05（含为 0 即「缺」）
```

**用词的约束**：特质词一律取传统命理的常用表述（自立、竞争、表达、锋芒、
务实、灵活、自律、果决、内省、孤高……），**不用心理学量表的词汇**
（外向、宜人性、神经质、大五）。混用会产生虚假的科学感 ——
读者会以为这些词背后有心理测量学的效度，而它们没有。

**关于底本**：十神的性格对应在命理典籍中分布很散，不像《穷通宝鉴》
那样有一张现成的表可转录。我可以写出一张站得住的表，
但它会标为 `personaSource: 'conventional'`（通行表述），
并列入待校准清单，等你指定底本后替换 —— 处理方式与调候表一致。

### 2.5 宫位 → 亲人环境

八宫已有。人格层补三件：

```ts
interface PalaceState {
  readonly palace: PalaceName;
  readonly weight: number;          // 当前权重
  readonly share: number;           // 占全盘比
  readonly gods: Record<TenGod, number>;  // 宫内藏干的十神构成

```

「亲人环境」的描述 = **宫位状态 + 六亲星状态（现有 KinReading）+ 结构事件**，
三者**并列呈现，不合并**。理由同 §3.6：合并会把宫星不同步这类真实的张力抹掉。

### 2.6 输出

```ts

  readonly outer: Readonly<Record<TenGod, number>>;
```

## 4. 统计节点（需求 ③）—— 本次的核心

### 4.1 两个量，不是一个

你的原话：「高于和低于的偏离都会造成变化，表示的是**变化率和变化量**」。

拆成两个可算的量：

```
变化量  z(y)  = (q(y) − μ) / σ                水平偏离
变化率  ż(y)  = (q(y) − q(y−1)) / σ_Δ         一阶差分的偏离
```

μ、σ 为该指标在**基准窗**内的算术平均与标准差；σ_Δ 为一阶差分序列的标准差。

**节点判据**：`max(|z|, |ż|) ≥ θ`

取 max 而非只看 z，是因为**两种情形都是「变动」，但含义完全不同**：

| 形态 | 判据 | 含义 |
| **持续极端** | 高 \|z\|，低 \|ż\| | 长期处于偏离态。如某运十年官杀极旺 |
| **急速穿越** | 低 \|z\|，高 \|ż\| | 量本身不极端，但变得很快。换运年的典型形态 |
| **突入极端** | 两者皆高 | 最强的节点 |

**报告必须分别标注这三种形态。**只报一个合成分数，会把「一直如此」
与「突然变成这样」混为一谈 —— 而这两件事在现实里完全不同。

### 4.2 三个尺度

| 节点 | 序列 | 基准窗 | 回答的问题 |
| **小** | 年值 | 所在大运的 10 年 | 这一年在**本运中**有多异常 |
| **中** | 大运步均值（每步一值） | 起运后 60 年的 6 步 | 这一步运在**一生中**有多异常 |
| **大** | 年值 | 起运后 60 年全程 | 这一年在**一生中**有多异常 |

### 4.3 ⚠️ 中节点的样本量只有 6

六个样本算出来的样本标准差极不稳 —— 任何一步稍偏，都会被放大成 2σ。
用样本 σ 会让中节点近乎恒有产出，也就等于没有产出。

必须换**稳健估计**：

```
M   = median(x)
MAD = median(|x − M|)
稳健 z = 0.6745 × (x − M) / MAD
```

0.6745 是使 MAD 在正态下等于 σ 的换算常数（Φ⁻¹(0.75)）。样本 6 时它比样本 σ 稳定得多。

若 `MAD = 0`（六步取值全同，罕见但可能），该指标**不产出中节点** ——
不做任何回退，因为没有散布就没有偏离可言。

### 4.4 阈值与分级

| 级别 | 判据 | 60 年中的预期个数 |
| 显著 | max(\|z\|,\|ż\|) ≥ 2.0 | ~3 |
| 值得注意 | ≥ 1.5 | ~8 |
| 轻微 | ≥ 1.0 | ~19 |

**这些个数是由构造决定的，不是这张盘的性质**（§1.3）。
报告只呈现前两级，且措辞落在排序上，不落在概率上。

### 4.5 方向不定吉凶，但要标出

`z > 0` 与 `z < 0` **都是节点**。是「机会」还是「压力」取决于该指标与用忌的关系：

```
指标属用神向（用神/喜神的十神或五行）：z > 0 → 偏机会    z < 0 → 偏压力
指标属忌神向（忌神/仇神）：            z > 0 → 偏压力    z < 0 → 偏机会
指标为宫位权重：                       不判方向，只报「该宫变动」
指标为域张力：                         **恒不判方向**
```

**域张力恒不判方向**，因为张力本身就是「顺逆并存」的度量 ——
给它定吉凶，等于把已经拆开的东西又合回去，那正是 tension 这个量存在的理由。

### 4.6 节点的合并

1. **同年多指标** → 合并为一个**节点事件**，携带全部命中指标，按 |z| 降序
2. **相邻年份**（间隔 ≤ 2 年）**且指标重叠 ≥ 半数** → 合并为**节点区间**，
   报起讫年而非单年

第二条很重要：结构性变动不会只持续一年。报「2031」不如报「2030–2033，
其中 2031 最甚」—— 后者既准确又不给人虚假的时点精度。

### 4.7 神煞作为解释

节点检出**之后**，取该年即时盘的神煞命中，筛出满足以下之一者作为叙述素材：

- 神煞的 `tone` 为 `activated`（被引动）
- 神煞落在本节点涉及的宫位上
- 神煞的域标签与本节点的域重叠

**神煞不参与节点的检出，只参与节点的叙述。**
这是「神煞更多是给盘面变化一个解释」的直接实现。

## 5. 对治（需求 ⑤）

### 5.1 边界

只给**命理内部的对治**，不给生活建议。

| ✅ 可给 | ❌ 不可给 |
| --- | --- |
| 补何五行、取何十神为解药 | 今年不宜投资 / 适合买房 |
| 哪一步大运可解、何年得援 | 注意心脏病 / 易患某疾 |
| 五行方位与时节的传统对照 | 别打官司 / 会有牢狱 |
| 该结构的传统解法（印化杀、食制杀、财生官…） | 任何针对读者行动的祈使句 |
| 「盘中自有解，只是当年被压制」 | 佩戴 / 开光 / 改名 / 择日 |

### 5.2 算法

对每个**压力向节点**（指标属忌神向且 z > 0，或属用神向且 z < 0）：

```
1. 定病  病 = 该节点中权重最大的忌神向指标所属五行
2. 求药  药 = controlledBy(病)                    克病者
         若 W(药) < remedy.weakThreshold，再求 generatedBy(药)（生药者）作辅
3. 查援  在未来 remedy.horizonYears 年内，扫描药之五行占比显著上升
         （z ≥ 1.0）的年份与大运步
4. 查解  本命盘中是否已有制病之神：
           有 → 「盘中自有解」，并指出当年它为何失效（被合/被冲/被泄）
           无 → 「须待外援」，落到第 3 步的年份
```

输出结构化的 `Remedy`，**不是散文建议**：

```ts
interface Remedy {
  readonly ailment: { element: Element; god: TenGod; z: number };
  readonly cure: { element: Element; god: TenGod; presentWeight: number };
  readonly assist: Element | null;
  readonly innateCure: { present: boolean; suppressedBy: StructureEvent | null };
  readonly reliefWindows: readonly { fromYear: number; toYear: number; z: number }[];
  readonly traditionalCorrespondence: { direction: string; season: string };
}
```

叙述模板一律以「传统上此结构以……为解」开头，主语是结构，不是读者。

### 5.3 新增禁用规则

```
zh.stats.probability   —— 统计节点不得写成概率陈述
  pattern: (?:概率|几率|可能性)[^。；\n]{0,6}(?:为|是|达)\s*\d
         | \d+\s*%\s*(?:的概率|的可能)
  why:    序列是确定性的，σ 只是经验散布。把百分位包装成概率是伪精确。

zh.remedy.imperative   —— 对治不得写成祈使句
  pattern: (?:应当|务必|记得|一定要|建议你|你需要|最好)[^。；\n]{0,12}
           (?:化解|佩戴|摆放|改名|择日|搬迁|避开)

zh.remedy.commerce     —— 不得导向任何消费
```

## 6. 简单结论 / 详细解释（需求 ④）

### 6.1 两层结构

每条结论由一个 `Finding` 承载：

```ts
interface Finding {
  readonly id: string;
  readonly summary: NarrativeLine;       // 一句话，默认显示
  readonly detail: {
    readonly narrative: readonly NarrativeLine[];
    readonly derivation: readonly DerivationStep[];
    readonly evidence: readonly Evidence[];   // 数据引用
    readonly alternatives: readonly Alternative[];
  };
  readonly confidence: number;
  readonly hedged: boolean;
}

interface Evidence {
  readonly kind: "carrier" | "event" | "rule" | "series" | "node";
  readonly ref: string;                  // 载体 id / 事件序号 / 规则 id / 指标名
  readonly value: number | string;
}
```

**硬约束**：`summary` 与 `detail` 的模板**共用同一组槽位**，
且测试断言 —— **summary 中出现的每个数字，都必须在 detail 的 `evidence` 里找得到**。

没有这条，两层会各说各话：摘要写「财运向好」，展开却是「财星被劫」。
这类不一致在两层结构里极难被发现，因为读者通常只看一层。

### 6.2 三个前端的默认行为

| 载体 | 默认 | 展开 |
| Web | 只渲染 summary，可点开 | detail 内联展开 |
| CLI | summary | `--detail` |
| Skill | 模型拿到完整 Finding | **先说 summary，用户追问再说 detail** —— 写进 SKILL.md |
