# 18 · 塔罗与合盘

> 两样放在一篇，因为它们共用一条主题：**这个项目在什么地方选择不做。**
>
> 塔罗是「没有可核对的东西」，合盘是「有东西但不该加总」。
> 两种「做不到」不是同一件事，而把它们说成同一种，是对读者不诚实。

---

## 一 · 塔罗（`tarot/`）

### 1. 它在版图上的位置

九套占法里唯一的两项极端：**天文含量为零**（起牌不需要知道今天是哪天），
**本性随机**（复算没有意义）。

实现它不是凑数 —— 《测天，还是约定》反复拿它当特例引用，
实现之后那几条从论述变成可运行的东西。

### 2. 牌组（`deck.ts`）

78 张 = 22 大牌 + 4 花色 × 14 位阶。

三处流派分歧，**一处都不替读者定**，随结果声明，并且**全部在 `Params.tarot` 里**：

| | |
| --- | --- |
| 大牌序号 | 马赛系 8 正义 11 力量 / 韦特系相反 |
| 花色元素 | 金色黎明杖火剑风 / 另一系相反 |
| 逆位 | 用 / 不用 |

> 韦特系对调 8 与 11，是为了让大牌序与黄道十二宫对得上 ——
> **那次对调本身就是后加的占星注解留下的痕迹。**

它们在参数里而不是函数参数里，因为**它们会改变结果**：
同一次洗牌在马赛系与韦特系下，8 号与 11 号是两张不同的牌。
不进指纹的话，两份不同流派的记录会得到同一个指纹。
塔罗页把指纹显示出来 —— 换一个开关，当场能看见它变。

13 号在马赛系牌面**无名**，不是印漏了。

### 3. ⚠️ 「牌—行星—星座」对应是 1888 年起后加的注解

不是塔罗的来历，也不进起牌。拿它论证「塔罗与占星同源」是**循环论证** ——
那层对应本来就是照着占星编出来的。本项目给出它，但标明它是注解而非来历。

### 4. 随机必须是真的（`draw.ts`）

六爻那边本项目**拒绝过**把问题文本哈希进起卦 ——
那是发明一种传统里没有的方法还伪装成传统。
塔罗正好相反：它本来就是随机的，洗牌就是起法本身。

故 `drawSpread` **没有「问题」参数，而且不该有**。

三处都「实际看不出来」的坑：

| 坑 | 后果 | 做法 |
| --- | --- | --- |
| `Math.random()` | 多数引擎里可预测 | 用 `crypto.getRandomValues` |
| `value % 78` | 模偏约 1e-8 | 拒绝采样 |
| Fisher–Yates 与 `[0, n)` 交换 | 排列不均匀 | 与 `[0, i]` 交换 |

**「看不出来」不是正确的理由。** χ² 检验锁住前两条，
并带**反向对照**：把错写法注入，必须被同一个检验逮到
（实测有偏版 χ² 远超临界值）。没有那条反向对照，前一条可能只是在测恒真。

### 5. 一事不二占在这里不适用，而且不该有

那条规矩属于**确定性系统**：六爻反复重问等于一直问到自己满意。
塔罗每一次抽都是独立试验，「重抽就是另一次」是定义不是漏洞。
故本模块**不记录、不限制重抽**，界面把「再抽一次」摆在显眼处 ——
那不是便利功能，是这套方法的性质。

### 6. ⚠️ 牌义不收录

六爻那边给的是《周易》**爻辞原文**，一段可考的引文。塔罗没有对应的东西：

- 马赛系小牌**本来就没有画面**，十八世纪以前也没有成文牌义
- 韦特系（1909）牌义是**新造的**，与马赛不兼容
- 各家差异之大，不存在可引的底本

故只给牌的身份与牌阵位置的**问题**。
**一个没有底本的牌义表写出来只能是编的，而编出来的读起来与有来历的一模一样。**

有一条测试在 `Card` 上扫字段名，确保没人日后悄悄加一个 `meaning`。

### 7. 牌阵是这套东西里最经得起说的部分

它是一组**预先定好的问题**，在抽牌之前就固定。
那与「先看到牌再决定它回答什么」有本质区别 —— 后者是事后编故事。
与「回看」页的「先出说法，后翻年份」是同一条道理。

凯尔特十字状态数已逾 10²¹。**那不是优点**：位置越多，
事后拼出一个说得通的故事就越容易。

## 二 · 合盘（`pair/`）

### 1. ⚠️ 这是整个项目里最该小心的功能

它是一个人最可能拿去**对另一个人下判断**的地方，而那个人多半不在场。
前面所有功能都只描述一张盘。

两条比别处都严的纪律：

### 2. 不给分数，一个都不给

`score` 的类型是 `null`，**不是 `number | null`**。

本项目别处是给数的（流年的顺逆指数）。为什么这里不给：

| | 流年那个数 | 合盘那个数 |
| --- | --- | --- |
| 说的是 | 一个人与一段时间 | **两个具体的人** |
| 读者怎么读 | 今年这段合不合我的结构 | **我们合不合适** |
| 读错的代价 | 明年还能再看 | 可能促成**不可撤回**的决定 |
| 牵连谁 | 自己 | **一个没有参与的人** |

无论措辞怎么框，「我们合盘 42 分」只会被读成一句判决 ——
因为读者正是为那句判决来的。

**只列逐条的结构关系，不加总。加总就是替人下结论。**

有一条测试**在源码里扫**，确保没人日后加一个打分函数再在出口处置空；
另一条按**字段名**（不是序列化文本）查有没有混进总分一类的字段。

> 用文本扫会把 `notes` 里「为什么不给总分」那句解释当成违例 ——
> 这个坑在合盘与紫微解读两处各踩过一次，两处都写了注释。

### 3. 不出人格描述

沿用 `subject: "other"` 的先例（人格、身心、六亲结构性略去）。
合盘只产出两张盘之间的**关系**。
想看某一方的描述，就去单独排那一张盘，并且自己清楚那是谁的盘。

### 4. 四柱合盘（`pair/bazi.ts`）

**十六组柱位全看**，不只看日柱 —— 只看日柱是一种取法，不是全部。
天干五合/相冲、地支六合/相冲/相害/三合，逐条带柱位与来历。

用神供给**两个方向各算一遍**，并带上它在**自己盘里的占比**作对照 ——
没有那个对照，「20.3%」读不出意思。

### 5. 星盘合盘（`pair/synastry.ts`，子路径 `@fate/core/sky-pair`）

交互相位，以及落宫**两个方向各算一遍**：
「甲方金星在乙方第七宫」与「乙方金星在甲方第七宫」是两件不同的事，
因为两张盘的上升点不同。**只算一边是这类实现的常见错误**，测试锁住。

### 6. 紫微合盘不收

各家取法差异极大而无可靠底本。合盘本来就是最容易被当成判决的地方，
再加一套来历不明的规则，等于拿编的东西去影响一个人对另一个人的看法。

### 7. 界面上的克制

没有分数、没有进度条、没有任何可以一眼读成结论的图形。

桌面版要求两张盘**都已存在**，不另开输入表单 ——
那会让人顺手填进一个随口问来的生辰。
移动版只存一个人，那条要求没法照搬，故改为**表单摆在说明之后**；
第二张盘单独存（`fate.m.partner.v1`），随时可单独清掉。

### 8. 关于知情

```
第二张盘是另一个人的生辰。数据始终不出本机 ——
但那是技术上的保证，与那个人知不知道这件事无关。两者是两回事。
```

措辞上这一句原本写作「不代表那个人知道你在算」，
被技术档守卫的第二人称规则拦下。改成现在这样，
把技术保证与知情分开说，反而更准。
