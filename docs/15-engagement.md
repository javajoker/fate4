# 15 · 移动版的留存设计 —— 让用户自己检验它准不准

> **状态：已实现（P28）。**

---

## 0. 问题

算命应用的留存靠什么？行业里的答案很一致：**每天给一条关于明天的话**。
用户来看今天说了什么，明天再来看。

这条路本项目**走不了**，而且不是因为技术做不到 —— 是因为
[09-report](09-report.md) §6 的措辞守卫从头到尾在禁的就是这个。
「明天会发生什么」是这套模型给不出的东西，装作给得出，
用户会来得更勤，但那是靠一句谎话换来的。

于是问题变成：**一个不肯预言的推演应用，凭什么让人再打开一次？**

---

## 1. 答案：把「它准不准」这件事交回给用户

传统算命的信息是单向的 —— 它说，你听。它从不告诉你它上次说得对不对，
因为**没人记录**。记忆会自动完成这份工作：说中的记得清楚，说错的自然忘掉。
这叫事后偏误，是所有此类系统能长期存在的心理基础。

本项目的立场（[11-validation](11-validation.md)）一向是可复现、可审计、可校准。
把这条立场推到用户那一侧，就得到本文的四个功能：

| 功能 | 它做什么 | 为什么它能留住人 |
| **回看** | 挑一个你记得的年份，看模型当时的说法 | 你在**检验它**，而不是听它讲。检验比听有意思得多 |
| **标注** | 给每条说法标「说中了 / 没说中 / 说不清」 | 一旦标了，你就有了自己的账 |
| **个人准确率** | 汇总你标过的全部，算出命中比例 | **这是别处没有的东西** |
| **复盘** | 问过的事，事后回来记结果 | 同上，落在具体的事上 |

留存的来源从「明天会怎样」换成了「我记的这本账现在什么样」。
后者是用户自己的东西，前者从来不是。

---

## 2. 为什么这个设计是诚实的，而不只是好玩

三条，都必须落到界面上，不能只写在文档里：

### 2.1 先看说法，后看年份 —— 否则量到的是记忆不是模型

若先告诉用户「2018 年」，再让他看说法，他会先想起 2018 年发生了什么，
再去说法里找对得上的部分。那样量到的是**他的记忆有多丰富**，不是模型有多准。

故回看页的默认次序是：**先出说法，用户想好了再翻年份**。
这一条不能省 —— 省掉之后这个功能就只是个好玩的东西，不再是个检验。

### 2.2 小样本要明说

标了七条，中了四条 —— 这不是「57% 的准确率」。
七次里中四次，在完全随机的情况下也一点都不稀奇。
故凡展示比例处，**必须同时给出「这个数字现在还说明不了什么」的判断**，
且这句判断随样本量变化，不是一句摆设的免责。

阈值取三十条：低于三十，界面上不出百分数，只出「你标了 N 条，其中 M 条你觉得说中了」。
数字本身照给，**但不做成一个看起来像统计量的东西**。

### 2.3 每条说法本来就有它的置信度

模型自己就说了哪些条不确定（`Verdict.confidence`）。
若用户标注的结果显示「模型说有把握的那些反而没说中」，那是有信息的；
若「模型说不确定的那些没说中」，那只是它自己承认过的事。

故汇总分两栏：**模型说有把握的** 与 **模型说不确定的**，分开看命中。
合成一个总数会把这个差别抹掉，而那恰恰是最有意思的一处。

## 3. 功能规格

### 3.1 回看（`/m/recall`）

```
1 用户挑一个年份（默认给出他 12–40 岁之间的若干年，随机排列，不按顺序）
2 页面先出该年的**人话说法**，年份**折叠**
3 用户读完，点开年份，然后标：说中了 / 没说中 / 说不清
4 标注存在本机，附上是哪一条、模型给的置信度、标注时间
```

年份的说法来自已有的 `yearView` + `plainCards` 的今年那一档，
**不新造判断** —— 与 [14-plain](14-plain.md) 同一条纪律：人话是判定的渲染，不是新判断。

### 3.2 复盘（`/m/ask` 内）

问过的事已经存了指纹与时刻（一事不二占）。补一个字段：结果。
`应验 / 不应验 / 还没结果 / 说不清`。同样只存哈希不存原文。

### 3.3 我的账（`/m/recall` 底部）

- 标注总数、各档计数
- 按模型置信度分栏（≥0.7 与 <0.7）
- 样本量不足三十时不出百分数
- 一句随样本量变化的判断

### 3.4 分享（各页）

只分享**人话文本**，不含出生信息、不含年份对照。
出生数据不出本机这条纪律，不因为「分享」而松动。

---

## 4. 不做的事

| 不做 | 为什么 |
| 推送通知「今日运势」 | 那是靠预言换留存 |
| 连续签到奖励 | 把「检验」变成「打卡」，用户就不再认真标了 |
| 与他人比准确率 | 准确率是用户对自己记忆的判断，不是可比的量 |
| 用标注结果反过来调参数 | 事后偏误会直接进模型。校准要用金标准集，不是用户的印象 |

最后一条最要紧：**用户的标注是给用户自己看的，不回流到引擎**。
一旦回流，这套系统就会朝着「让用户觉得准」的方向漂移，
而那正是所有算命系统最终会变成的样子。
