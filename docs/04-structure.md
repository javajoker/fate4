# 04 · L2 结构层（会合冲刑害破）

L2 在生克传导**之前**运行，因为合冲刑害改变的是「场上有什么」，而生克计算的是「场上的东西如何互相作用」。顺序颠倒会得到错误的结果：对一个已经被合化成土的甲木，再按木去算生克，是错的。

L2 有两类产出：

1. **权重与元素的改写** —— 合化转五行、冲损、库开释放
2. **活性阻尼 `activity`** —— 合绊者仍在场但施力打折

---

## 1. 优先级与结算顺序

```
structure.precedence = [sanhui, sanhe, banhe, liuhe, ganhe, chong, ganchong, xing, hai, po]
```

理由：**范围大者优先，成局者优先，静者先于动者。**三会是三支同方，格局最大；三合次之；六合是两支之私；冲刑害破是既成结构上的扰动。

**结算分两轮**：

- **Round A（成局）**：三会 → 三合 → 半合 → 六合 → 天干五合。检测所有候选，做争夺裁决，标记成败。
- **Round B（破坏）**：地支六冲 → 天干相冲 → 三刑 → 六害 → 六破。对 Round A 的结果施加损耗。

Round A 的成局结果会影响 Round B 的判定（合住的支被冲，力度打折），反之亦然（被冲破的支参与的合可能不成）。因此二者之间有一次**互解裁决**，见 §6。

## 2. 三会方

条件：三支**全见**于场上载体的宿主支中（本命 + 大运 + 流年）。

| 会 | 支 | 化神 |
| --- | --- | --- |
| 东方 | 寅 卯 辰 | 木 |
| 南方 | 巳 午 未 | 火 |
| 西方 | 申 酉 戌 | 金 |
| 北方 | 亥 子 丑 | 水 |

**效果**（`structure.sanhui`）：

```
参与支中，五行 == 化神 的藏干：weight ×= gain        # 1.40
参与支中，五行 ≠ 化神 的藏干：weight ×= decay        # 0.50
```

「其气专于一行」。辰中乙癸被吸入木局，戊土被压制；未中丁乙被吸入火局，己土被压制。

**不做元素转换**——被压制的藏干仍是它自己，只是力量被夺。转换只发生在六合与天干五合（见 §5），因为那里是两两私合，有明确的「化神」归属。

## 3. 三合局与半合

| 局 | 生 | 旺 | 墓 | 化神 |
| --- | --- | --- | --- | --- |
| 水 | 申 | 子 | 辰 | 水 |
| 木 | 亥 | 卯 | 未 | 木 |
| 火 | 寅 | 午 | 戌 | 火 |
| 金 | 巳 | 酉 | 丑 | 金 |

**全三合**（`structure.sanhe`）：`gain 1.30` / `decay 0.60`，机制同三会。

**半合**（`structure.banhe`）：

| 组合 | 类型 | gain | decay | 说明 |
| --- | --- | --- | --- | --- |
| 生 + 旺（申子、亥卯、寅午、巳酉） | `SHENG_WANG` | 1.20 | 0.75 | 力强，有旺神 |
| 旺 + 墓（子辰、卯未、午戌、酉丑） | `WANG_MU` | 1.15 | 0.80 | 力中 |
| 生 + 墓（申辰、亥未、寅戌、巳丑） | `GONG` 拱 | 1.05 | 0.95 | 缺旺神，几乎只作标记 |

**旺神（中神）是三合的必要条件。**缺子的申辰不成水局，只是拱。代码中必须显式检查，不能只数「凑齐两个就算半合」。

**距离衰减**：合局参与支若不相邻，效果打折。

```
邻柱          × 1.00
隔一柱        × 0.80
隔两柱        × 0.60
含大运/流年   × structure.externalHeFactor   # 0.90
```

三支的距离取**两两距离之和**归一后的系数。

### 3.5 优先级的实际后果：会局夺合

优先级表「范围大者优先」不只是排序，它有**annul 语义**：

> 若一个六合的两支**都已被三会或三合吞没**，该六合整条不再论 ——
> 不降级为合绊，不打活性折扣，`outcome = 'neutralized'`，权重零改动。

「巳午未三会火，那午未还算不算合土？」传统的答案是不算：二支之私合已被方局吞没。
把它降级成争合是不够的 —— 争合仍会打 0.85 的活性折扣，等于让一个不存在的合继续产生后果。

`narrativeTag = '会局夺合'`。此路径不经互解裁决，故不带 `strengthScores`，
但必须带 `note` 说明缘由。

## 4. 六合

| 组合 | 化神 |
| --- | --- |
| 子 + 丑 | 土 |
| 寅 + 亥 | 木 |
| 卯 + 戌 | 火 |
| 辰 + 酉 | 金 |
| 巳 + 申 | 水 |
| 午 + 未 | 土（日月合，化气最弱） |

六合有两种结局：**合化** 或 **合绊**。判定见 §5。

## 5. 合化判定（六合与天干五合共用）

**天干五合**：甲己→土 · 乙庚→金 · 丙辛→水 · 丁壬→木 · 戊癸→火

化成的四个条件，**全部满足**才转换：

| # | 条件 | 判据 |
| --- | --- | --- |
| C1 | 月令支持化神 | 月支本气五行 == 化神，**或** 月支本气生化神 |
| C2 | 有引化 | 化神五行在天干层有透出的载体，**或** 局中化神总权重 ≥ `catalystThreshold`（默认 30） |
| C3 | 无争合妒合 | 参与的任一载体未同时被第三方以同类合关系锁定 |
| C4 | 未被冲破 | 参与的任一支未在 Round B 中被判为冲破（互解裁决见 §6） |

```
structure.transform:
  requireMonthSupport: true       # C1
  requireCatalyst: true           # C2
  catalystThreshold: 30
  blockOnContention: true         # C3
  blockOnChong: true              # C4
  gainOnSuccess: 1.20
  bindFactorOnFailure: 0.70
```

**化成**：

```
两个载体的 element ← 化神
两者 weight 之和 ×= 1.20，按原比例重新分配
flags += TRANSFORMED
```

**不化（合绊）**：

```
weight 不变
activity ×= 0.70
flags += BOUND
```

`activity` 只影响该载体**对外施力**（L3 中作为 `i` 的系数），不影响它**被作用**。这正是「贪合忘克」——被合住的七杀不再去克身，但它仍然在那里，仍然可以被制。

**争合妒合**：两个乙争合一个庚 → 三者皆标 `CONTESTED`，不化，且 `activity ×= 0.85`（比普通合绊更弱，因为力量分散）。

**距离**：天干五合要求**相邻**（`|Δpillar| ≤ 1`）才可能化。隔位只作 `BOUND`，不作转换。地支六合无此限制但按 §3 的距离系数打折。

## 6. 冲与合的互解裁决

一个支同时进入「合」与「冲」时，比较两方强度：

```
合力 = (参与载体权重之和) × typeCoef
       typeCoef: 三会 1.00 · 三合 0.85 · 半合 0.65 · 六合 0.55
       再乘距离系数

冲力 = min(W_A, W_B) × 2.0 × 距离系数
       （取弱方权重，因为冲的破坏上限由弱方决定）
```

| 结果 | 处理 |
| --- | --- |
| 合力 > 冲力 × 1.2 | **合解冲**：合成立，冲被annul，记 `CHONG_NEUTRALIZED` |
| 冲力 > 合力 × 1.2 | **冲破合**：冲成立，合降级为 `BOUND`（不化），记 `HE_BROKEN` |
| 两者接近（差 < 20%） | **两败**：合降级为 `BOUND`，冲的损耗系数 × 0.6，双方各记 `CONTESTED` |

裁决结果写入 `StructureEvent[]`，报告中必须能展开这条链路。

**两条裁决路径都要带 `strengthScores`，不只是「合被冲破」那一条。**

| 结局 | 事件 | 读者会问 |
| --- | --- | --- |
| 冲胜 | `liuhe: broken` | 「巳申看似合水，为何不化？」 |
| **合胜** | **`chong: neutralized`** | **「巳亥看似相冲，为何不冲？」** |

后者最初被漏掉了 —— 不变量只查了 `broken`，于是「合解冲」的事件不带分数，
而它恰是更需要解释的一半。现两条路径皆带 `strengthScores` 与 `note`，
并由 `test/structure.spec.ts` 的「互解裁决的实证覆盖」一组用真实命例保证断言不空转
（条件断言若无样本命中，会静默地空转通过 —— 这是不变量测试最常见的失效方式）。

## 7. 地支六冲

| 对 | 性质 |
| --- | --- |
| 子↔午 · 卯↔酉 | 四正冲，力最猛（无杂气可缓冲） |
| 寅↔申 · 巳↔亥 | 四生冲，主动摇迁移 |
| 辰↔戌 · 丑↔未 | 四墓冲，**开库**，见 §9 |

**损耗计算**：

```
W_A, W_B = 两支各自藏干权重之和
r = max(W_A, W_B) / max(min(W_A, W_B), ε)

if r ≥ structure.chong.uprootThreshold:      # 2.5
    弱方 ×= (1 − chong.weakLossUproot)       # 1 − 0.75 = 0.25   拔根
    强方 ×= (1 − chong.strongLoss)           # 1 − 0.20 = 0.80
elif r ≥ 1.2:
    弱方 ×= (1 − chong.weakLoss)             # 1 − 0.50 = 0.50
    强方 ×= (1 − chong.strongLoss)           # 1 − 0.20 = 0.80
else:
    双方 ×= (1 − chong.equalLoss)            # 1 − 0.35 = 0.65   两败俱伤
```

损耗按比例施加到该支的**全部藏干**上，不改变藏干内部比例。

**距离系数**（`structure.chong.distance`）：

```
邻柱 1.00 · 隔一柱 0.60 · 隔两柱（年↔时）0.30
大运冲本命 0.90 · 流年冲本命 0.85 · 大运↔流年 1.00
```

远冲力弱，是传统共识（「远隔不冲」的温和版）。年柱与时柱之间的冲只留 30%。

## 8. 天干相冲

甲↔庚 · 乙↔辛 · 丙↔壬 · 丁↔癸。

天干为虚，机制同 §7 但整体乘 `structure.ganchong.factor = 0.50`，且要求相邻（`|Δpillar| ≤ 1`）。戊己不参与。

## 9. 墓库开合

辰（水库）· 戌（火库）· 丑（金库）· 未（木库）。

```
structure.tomb:
  sealedFactor: 0.60      # 未开之库，库中的中气/余气打折
  openOnChong: true
  openOnXing: true
  releaseGain: 1.30       # 开库后中气/余气的加成
```

**默认状态：闭库。**辰中的乙木与癸水按 0.60 计——它们在库里，是存量不是流量。

**开库条件**：该库支被冲（辰戌、丑未）或被刑（丑戌未三刑、辰辰自刑）。开库后：

```
中气与余气 weight ×= 0.60 → 恢复原值再 × 1.30    (净效果 ×2.167)
flags += TOMB_OPENED
```

开库是四柱中最强的「事发」信号之一。库中藏的往往是六亲星或财官星，冲开即应事。此标记会直接进入 [08-temporal](08-temporal.md) 的应期规则。

**本气不受闭库影响**——戌中戊土是墙本身，不是墙里的东西。

## 10. 三刑

| 类型 | 组合 | 系数 | 语义标签 |
| --- | --- | --- | --- |
| 无恩之刑 | 寅→巳→申（需**三支全见**） | 0.80 | 恩义反目、法律 |
| 恃势之刑 | 丑→戌→未（需三支全见） | 0.80 | 恃强、争斗、开库 |
| 无礼之刑 | 子↔卯（**二支即成**） | 0.85 | 礼法、亲缘 |
| 自刑 | 辰辰 · 午午 · 酉酉 · 亥亥 | 0.90 | 自我耗损 |

**只见两支的寅巳、巳申、丑戌等**：`structure.xing.partialFactor = 0.93`，标记 `XING_PARTIAL`，属于「有刑意无刑局」，主要作叙述素材，数值影响极小。

刑的损耗同样受距离系数约束（同 §7 的表）。

## 11. 六害与六破

| | 组合 | 系数 |
| --- | --- | --- |
| 六害（穿） | 子未 · 丑午 · 寅巳 · 卯辰 · 申亥 · 酉戌 | `0.93` |
| 六破 | 子酉 · 午卯 · 申巳 · 寅亥 · 辰丑 · 戌未 | `0.97` |

数值影响刻意做得很小。害与破在传统中主要是**叙事性**的（害主暗损、破主分离），不是力量层面的大事。它们的价值在应期规则与宫位解读，不在权重。

`structure.po.enabled`（默认 `true`）—— 部分流派完全不用破，可关闭。

## 12. 输出

```ts
interface StructureResult {
  readonly carriers: readonly Carrier[];        // element/weight/activity 已改写
  readonly events: readonly StructureEvent[];
}

interface StructureEvent {
  kind: 'sanhui' | 'sanhe' | 'banhe' | 'gong' | 'liuhe' | 'ganhe'
      | 'chong' | 'ganchong' | 'xing' | 'hai' | 'po' | 'tombOpen';
  participants: CarrierId[];
  hostBranches: Position[];
  outcome: 'transformed' | 'bound' | 'contested' | 'neutralized'
         | 'broken' | 'applied' | 'partial';
  transformedTo?: Element;
  strengthScores?: { he: number; chong: number };   // 互解裁决的依据
  weightDelta: Record<CarrierId, number>;
  distanceCoef: number;
  narrativeTag: string;                              // 供 L6 取文案
}
```

## 13. L2 不变量

1. `activity ∈ [0, 1]`，只减不增。
2. 合化转换后，参与载体的 `element` 必须一致且等于化神。
3. 任一载体最多参与 **一次** 成功的合化转换（`TRANSFORMED` 标记互斥）。
4. `events` 中每条 `weightDelta` 之和 == 该轮实际权重变化总量（可用于审计）。
5. 凡经互解裁决者（`broken` 与 `合解冲` 两条路径）必须留下 `strengthScores`；
   凡 `bound`／`contested`／`broken`／`neutralized` 者必须带 `note` 说明缘由。
   条件断言须有实证覆盖，否则会空转通过。
6. 三合局若缺旺神，`kind` 必须是 `gong` 而非 `banhe`。
