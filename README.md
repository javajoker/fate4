# fate — 四柱预测引擎

一套**可复现、可审计、可校准**的四柱（八字）推演系统，由三部分组成：

| 组件 | 说明 |
| --- | --- |
| `packages/core` | 纯 TypeScript、零运行时依赖的推演内核。排盘、配重、传导、断论、神煞、应期全在这里。可单测、可被任何宿主调用。 |
| `packages/web` | Next.js（App Router）Web 应用。命盘、大运、流年、流月、流日与报告的可视化。 |
| `packages/skill` | Claude Agent Skill。通过 CLI 调用 `core`，拿到结构化 JSON 后由模型组织叙述。 |

**核心设计约束：Skill 与 Webapp 共用同一份 `core`。** 不存在两处实现，因此不存在结论漂移。

---

## 设计原则

1. **确定性层与解释层严格分离。** 排盘、配重、传导、旺衰判定是纯函数，同一输入永远同一输出，可回归测试。命理叙述是它之上的一层，永远不反过来改写数值。
2. **每个结论都带 explain trace。** 「身弱」不是一个字符串，是一条可展开的链路：哪些载体、哪些权重、哪条阈值。没有 trace 的结论不允许进报告。
3. **零硬编码常数。** 所有系数集中在 [`params/default.yaml`](params/default.yaml)，运行时以 zod 校验载入。调参不需要改代码。
4. **流派差异是配置，不是事实。** 阳顺阴逆 vs 阴阳同生同死、火土同宫 vs 水土同宫、早晚子时三种处理——全部是开关，默认值写明出处。
5. **权重引擎只跑到流年。** 流月、流日是纯事件匹配层，不重算权重。月日是引动的扳机，不是力量的来源。

## 计算管线

```
L0 排盘   干支 → 10 维天干载体向量（五行 × 阴阳）
          节气 / 真太阳时 / 四柱 / 胎元 / 命宫 / 大运起运时刻
L1 配重   基础 100 → 干支 40:60 → 藏干下发 → 月提放大 → 司令分野修正
L2 结构   会 > 合 > 冲 > 刑 > 害 > 破，改写载体
          合化转五行 / 合绊降活性 / 冲损 / 刑冲开库
L3 传导   生克核 × 阴阳系数 × 距离衰减 × 活性阻尼
          带泄耗守恒，同步迭代至收敛
L4 断论   五行向量 → 十神向量 → 旺衰 → 从格 → 用神 → 格局 → 宫位六亲
L5 时间   大运 / 流年重跑 L1–L4；流月 / 流日只跑事件匹配
L6 报告   汇总为分层报告
```

### P1 的精度实测

节气验收判据是「与参考数据误差 ≤ 1 分钟」，折合太阳视黄经约 **2.5″**。

黄经级数取 **VSOP87D**，系数由 `scripts/generate-vsop87.mjs` 自官方档案生成 —— CDS/VizieR（斯特拉斯堡）与 IMCCE（巴黎天文台）两处独立来源字节完全相同，SHA256 已固化在生成器里，取回的文件不符即中止。解析后逐一核对文件自报的项数（17 个序列全部相符）。数字全程未经任何模型转述。

对**香港天文台** 2019–2028 共 240 个节气的实测：

| provider | 最大偏差 | 均值 | 均方根 | 偏置 | 超 60 秒 |
| --- | --- | --- | --- | --- | --- |
| **VSOP87D** | **42.2 秒** | 15.2 秒 | 18.0 秒 | −4.1 秒 | **0 条** |
| Meeus 简化解（对照） | 800.6 秒 | 271.9 秒 | 328.8 秒 | −196.0 秒 | 213 条 |

HKO 只公布到分钟。纯量化噪声（均匀 ±30 秒）的均方根为 17.3 秒，而实测 18.0 秒 —— **误差几乎全部由参考数据自身的取整解释**，反推我方真实误差约 5 秒。偏置仅 −4.1 秒，说明 HKO 用的是四舍五入而非截断。

误差预算（详见 `astro/vsop87.ts`）：级数截断 0.03″ + 章动简化式 0.5″ + 光行差简化式 0.01″ ≈ 13 秒，加 ΔT 外推偏差 2–3 秒，合计约 16 秒。余量 3.7 倍。最大的一块是章动简化式，若日后要更高精度，换 IAU 完整章动序列是唯一值得做的下一步。

⚠️ **2050 年以后不承诺 60 秒容差**：ΔT 是对地球自转不规则变化的外推，届时不确定度已超过容差。这是物理限制，非实现缺陷。
⚠️ 外部验证覆盖 2019–2028（HKO 的发布范围）。此区间外只有结构性验证 —— 见 [11-validation §2.1a](docs/11-validation.md)。

完整实施顺序与完成判据见 [10-architecture §7](docs/10-architecture.md)。**P2 不零误差不进 P3** —— 排盘的对错是可以 100% 客观验证的。

文档中标记 `⚠️ 待校准` 的条目表示该处存在流派分歧或公式需外部验证，默认值已给出但需以参考万年历/命例回归确认。清单见 [11-validation §5](docs/11-validation.md)。
