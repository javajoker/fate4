# 4 · 力量

从这一章起，离开了可验证的领域。下面讲的是一套**传统规则的数值化实现** ——
它自洽、可复算、可审计，但没有外部真值可对。这个区别请一直记着。

---

## 4.1 为什么要有「数」

传统断八字靠的是口诀与经验：「月令得时」「通根透干」「身弱喜印」。
这些说法都在描述**多与少**，但从不给数字。

于是同一张盘，两位师傅可以得出相反的结论，而且**谁也无法说服谁** ——
因为没有共同的刻度。

这套系统做的事就是：把那些「多」「少」「有力」「无力」变成数。
这么做有代价，也有收益：

| | |
| --- | --- |
| 代价 | 数字是人定的。典籍没给过，是本项目填的，**可能填错** |
| 收益 | 填错了至少**看得见、改得动、能验证改完之后差多少** |

本项目的态度是：带着已知瑕疵的明确数字，胜过听上去圆融的含混说法。
所有这些数都集中在一个文件里（[`params/default.yaml`](../params/default.yaml)），
标了 `[校准]` 的就是「这是待校准的数，不是定理」。

---

## 4.2 配重：八个字变成十个数

### 第一步：一百分，先分给干和支

每一柱有 100 分的基础分，天干与地支按 **40 : 60** 分。

地支拿得多，因为传统上「支为根」—— 天干是显露在外的，
地支才是立足的地方。4:6 这个比例是参数。

### 第二步：地支的分数再下发给藏干

地支那 60 分要分给它藏的一到三个天干：

```
本气 : 中气 : 余气  ≈  0.6 : 0.3 : 0.1
```

只藏一个的（子、卯、午、酉）就独得 60 分。

**这三个数是整套系统里最没有出处的数。** 各家给的比例差别很大，
有给 7:2:1 的，有按日数分的（司令分野）。本项目默认用上面这组，
并另外实现了**司令分野修正** —— 按出生日在该月的第几天，
调整三者的比例，因为传统认为一个月里本气与中气的当令程度是变化的。

### 第三步：月令放大

出生在哪个月，对应的那一行要放大。这是「月令得时」的数值化。

```
生在寅月（木当令）→ 全盘的木类载体乘以一个大于 1 的系数
```

放大多少、放大哪几类（当令、相、休、囚、死五档），全是参数。

### 结果

八个字变成**十个数**：

```
阳木  阴木  阳火  阴火  阳土  阴土  阳金  阴金  阳水  阴水
```

你在「力量结构」那一页看到的那十条，就是它们。

## 4.3 传导：让它们互相作用

十个数还不是最终答案 —— 它们之间有生克。

### 一轮里发生什么

每个载体对每个别的载体施加影响，强度由四项相乘：

```
影响 = 生克核 × 阴阳系数 × 距离衰减 × 活性阻尼
```

| 项 | 含义 |
| --- | --- |
| **生克核** | 生是正的、克是负的，各有基础强度 |
| **阴阳系数** | 同性相生弱于异性相生（传统说法），同性相克则更烈 |
| **距离衰减** | 隔得远的柱之间作用打折。年柱对时柱的影响小于月柱对日柱 |
| **活性阻尼** | 被合绊住的载体「在场但施力打折」 |

### 为什么要迭代

因为生克是**循环**的：木生火、火生土、土生金、金生水、水又生木。
一轮算完，每个数都变了，于是上一轮算出的影响量已经不对了。

所以要**反复跑，直到数值不再变动**（收敛）。本项目的报告里会写明
跑了多少轮、最后一轮的变化量是多少。

### 同步更新，不是依次更新

这是一个关键的实现选择：

```
依次更新（错）   算完木，立刻把木的新值写回去，再用新值算火
同步更新（对）   先把所有载体的增量都算出来，一起写回，再跑下一轮
```

依次更新的结果会**依赖于「先算谁」**，而「先算谁」在典籍里没有规定 ——
那意味着同一张盘换个遍历顺序就得出不同答案，这不叫算法，叫巧合。

本项目有一条测试把载体顺序**随机打乱 200 次**，断言结果逐位相同。
这条叫「顺序无关性」，是这一层最硬的一条保证。

## 4.4 两个会在报告里看到的数

| 名字 | 它在说什么 |
| --- | --- |
| **流通度** | 五行之间转得顺不顺，有没有堵在某一处。五行俱全且首尾相接则高 |
| **单轮留存** | 跑一轮之后力量留下了多少，衡量这个结构耗不耗 |

这两个都是**整盘指标**，不针对某一类事。它们在[生命曲线](07-时间.md)里
也各有一条序列。

---

## 4.5 这一章最该记住的

1. **数字是人填的，不是典籍给的。** 这是这套系统最大的不确定性所在。
2. **它们都集中在一个文件里，可改。** 改完能立刻看到差多少。
3. **传导要迭代到收敛，且必须同步更新。** 否则结果依赖遍历顺序。
4. **顺序无关性由测试锁住**（200 次随机打乱）。
