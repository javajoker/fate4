# 10 · 怎么用

四个入口，同一台引擎。这一章讲各自适合谁、在哪儿点什么。

---

## 10.1 四个入口

| 入口 | 适合 | 特点 |
| --- | --- | --- |
| **移动版** `/m` | 第一次用、不想看术语 | 全是平常话，术语折在「看依据」里 |
| **网页版** `/` | 想看完整推演 | 术语版，每一层都摊开 |
| **命令行** | 要存档、要批量、要接别的程序 | Markdown 或 JSON |
| **Claude Skill** | 想用对话的方式问 | 两档：术语版与人话版 |

四柱是主线，但不是全部。本项目实现了七套占法，各自要的输入不同 ——
首页底下那张表把它们的落位列在一处：四柱要生辰，六爻只要一个时刻，
星盘要时刻加经纬度，**塔罗连时刻都不要**。

**四个入口共用同一份内核。** 不存在两处实现，因此不存在结论漂移 ——
命令行输出与网页上看到的是同一个函数的同一份产出，有测试逐字节比对。

## 10.2 移动版：从这里开始

打开 `/m`，六个标签：

```
我      时间      别的盘      回看      问事      关于
```

排法按**你在做什么**，不按占法分类：前三个都在看「我这个人（这一刻）」，
只是算法不同；「别的盘」里装着星盘、紫微与合盘，「问事」里装着六爻与塔罗。

### 「我」

第一次进来先填出生信息：日期、时间、城市、性别。

- **只存在这台设备上，不上传。**
- 不知道出生时间？勾「不知道具体时间」。系统会**留白**，
  不会拿中午十二点顶上 —— 与时辰相关的那几项（晚年、子女、志向）
  会直接缺席，并告诉你少掉了大约三成信息。

填完之后，顶上是一张**资料卡**：四项都能回看，点「改一下出生信息」
可以修改（出生时间最容易记岔，也最值得试着改一改看看）。
卡片里还有一个「看八字（传统记法）」，展开是那张干支表。

下面按五个主题分：性格、身心、亲近的人、人生轨迹、起伏。
**每张卡片都有一个「看依据」** —— 点开是产生这句话的技术原文。
这不是装饰：人话是概括，你必须随时能看到被概括的是什么。

### 「你是以什么身份在看」

三档：**普通读者 / 学习中 / 命理师**。

| | 看到什么 |
| --- | --- |
| 普通读者 | 平常话为主，不出量化数字，**不给指向未来的时段** |
| 学习中 | 完整的推导链与数字，每个数附一句它是什么意思 |
| 命理师 | 原始数值直出，不加解释；候选时段与待校准项全给 |

**有两样东西任何档都给**：这张盘的来历警告（见下），
以及每张卡的「看依据」—— 人话是概括，而被概括的原文必须随时看得到。
那不是一种深度，是一条底线。

换一档不是换一套说法，是同一句话后面多出一截。
同一张盘的「你的底子」那张卡：

```
普通读者   你的底子偏轻，容易顺着环境走 —— 顺境里借力顺畅，逆境里消耗得快。

学习中     （同上）　〔数〕同党/总量 0.3679（帮日主的那一半占全盘权重的
           比例）；距最近档界 0.0679（贴近零说明这张盘在界上，两种读法都
           成立）；档界 0.3；置信度 1.00（0–1。低于 0.7 时本系统必须同时
           给出另一种读法）

命理师     （同上）　〔同党/总量 0.3679｜距最近档界 0.0679｜档界 0.3｜置信度 1.00〕
```

人话那一句三档逐字相同 —— 后两档加的是**数**，不是另一个结论。
学生那一档每个数附一句它是什么意思；命理师那一档不附，
因为他不需要被解释，而解释会占掉他要扫的地方。

**这个开关只决定给你看多少，不决定这套东西能说什么。**
三档的[措辞检查](11-它算不出什么.md)完全一样 —— 换到「命理师」
不会让它开始预告事件，只是把本来就算出来的数和候选时段给出来。

默认是最严的那一档。关掉了什么会明说，不默默少几条：
普通读者档的「起伏」那一屏会写出压下了几条、为什么压。

同一个开关在网页版 `/chart` 的顶栏也有（见下节 10.3）。
两边各记各的，因为一台设备上多半是同一个人在看，
而他在手机上与在桌面上要的深度常常不同。

### 「这张盘是怎么定下来的」

资料卡下面那张，**任何档都出**。它写的是这一类话：

```
出生于晚子时（真太阳时 23 时后），按「晚子换日」规则日柱已进位。
出生时当地行用夏令时，已扣除一小时。
```

第一条要紧得多：它意味着**日柱换了一个**，而日干就是日主 ——
整张盘的基准点。而它由一个可改的参数决定
（[第 12 章](12-自己调参.md)的 `chart.ziHourRule`，三说并存，无正确答案）。

不知道这件事，就不知道自己看的是三张盘里的哪一张。

### 「时间」

今天、本月、今年、按年。

「今天」那一屏下面还有两块：「还有另一套说法」（四柱与六爻并列，
不合并）与「今天说的是什么事」（日卦的爻辞指事）。

### 「回看」

这一页是整个应用里**唯一不讲未来**的一页，也是最值得花时间的一页。

做法是：挑一个**过去的**年份，先看模型当时的说法，
然后由你判断它说中了没有。

三处讲究写在界面上：

1. **先出说法，后翻年份。** 若先给年份，你会先想起那年发生了什么，
   再去说法里找对得上的部分 —— 那样量到的是你记忆有多丰富，
   不是模型有多准。
2. **标注不足 30 条不出百分数。** 七次中四次在完全随机时也不稀奇，
   写成 57% 会让一个说明不了什么的数字看起来像统计量。
3. **按模型自己的置信度分栏**，而不是给一个总命中率。
   最有意思的问题不是「准不准」，是「它说有把握的那些是不是真的更准」。

标注只存在你的设备上，而且**不回流引擎**。
拿用户的印象去调参数，事后偏误就直接进了模型，
整套系统会朝着「让用户觉得准」的方向漂移 —— 那正是所有算命系统的归宿。

### 「别的盘」

里面是**星盘**、**紫微斗数**与**合盘**，并列切换。两者都读同一个出生时刻，
而要的输入正相反：星盘要经纬度（真天体，算星历），
紫微连地点都不要（虚星，纯算术）。摆在一起，这个分别自己就看得出来。

#### 星盘

与「我」那一页同一个出生时刻，换一套占法：七政四余与西洋古典占星。
最前面是一张圆图 —— 手机上它比表格好读得多，因为**它语言最少**：
位置就是位置，不必读文字就看得出谁挨着谁、谁对着谁。

> ⚠️ **这一页与移动版别的页不一样：它有术语。**
>
> 别的页把推演换成了平常话，这一页换不了，而原因不是偷懒：
> 本项目的星盘**根本不做解读** —— 它只给位置、强弱与相位，没有一句断语。
> 既然没有断语，也就没有「换成平常话」这一步可做。
> 所以这一页术语照用，但每个术语当场解释一句。

它要**纬度**。城市表里带着，选了城市就有了 ——
老的存档没有纬度，重新选一次城市即可补上。

#### 紫微斗数

四方十二宫的方图，与桌面版同一张。它**不要纬度**，
所以即便没补上纬度，这一边照样排得出来。

方图下面是**盘面的解读**：三方四正（四宫同看）、空宫借对宫、
格局、四化落在哪一宫。每一条都指得回已经算好的落位，不另引一张表。

> ⚠️ 不收**星曜庙旺表**（十四主星 × 十二宫 = 168 格）。
> 那一层凭记忆转录的风险比调候 120 格更大，而结构性检查对它几乎无能为力。
> 这是一个真实的缺口，不是取舍。

#### 合盘

唯一牵涉**第二个人**的一页。**一个分数都不给** ——
理由见[第 11 章](11-它算不出什么.md) 11.3.1。

第二张盘**单独存**，随时可以单独清掉 ——
它是另一个人的生辰，不该混进你的资料里悄悄留着。
表单摆在那段说明**之后**才出现：桌面版要求两张盘都已存在，
移动版只存一个人，那条要求没法照搬，故改为先读完说明再填。多一步，
而那一步值得。

### 「问事」

两套方法摆在同一页：**六爻**与**塔罗**。

摆在一起，是为了让它们的差别看得见：

| | 六爻 | 塔罗 |
| --- | --- | --- |
| 要出生信息 | 不要 | 不要 |
| 要时刻 | 要 | **不要** |
| 同一问题重问 | **当天只一次** | 想抽几次抽几次 |

最后一行不是随意，是**确定与随机**的分别。六爻同一时刻重起会得到同一个卦，
反复重问等于一直问到自己满意为止；塔罗每抽一次本来就是一次新试验。
拿六爻的规矩套塔罗，是把确定性系统的伦理搬到随机系统上。

塔罗那一边**不给牌义**，而且那不是省略 —— 理由见
[《测天，还是约定》第 12 章](../book-compare/12-塔罗的结构.md)。

#### 六爻

就一件具体的事起一卦。**不需要出生信息。**

- 32 类占事，选一类（取哪个用神全由它决定）
- 可以写一句具体想问什么 —— 这句话**不出你的设备**，
  只在本机换算成一串指纹
- **同一个问题当天只起一次**。允许反复重问等于允许一直问到自己满意为止，
  那样得到的不是占问，是挑选
- 结果分两节：「这件事在卦里的分量」（这套推演算的）
  与「说的是什么事」（《周易》的引文）

## 10.3 网页版：看完整推演

`/` 输入出生信息后进 `/chart`，顶栏是各节：

| 页 | 内容 |
| --- | --- |
| 盘面 | 四柱八字、藏干、十神、权重、神煞落宫 |
| 旺衰与取用 | 同党异党、根、五档、用神的几条取法 |
| 宫位六亲 | 星与宫的四象限 |
| 大运 | 十年一柱，起运时刻 |
| 流年 | 逐年，可展开到月 |
| 月历 | 当月与今日 |
| 生命曲线 | 55 条序列，可单选/多选/全选 |
| 统计节点 | θσ 穿越区间 |
| 人格 | 内外十神、五行偏枯、形体与《内经》配属 |
| 完整报告 | 可导出 Markdown |
| 参数校准 | **拖系数，实时看结论怎么变** |

顶栏上面还有一条**读者档**（普通读者 / 学习中 / 命理师），
与移动版 10.2 的那一档是同一个开关、同一张披露表。
桌面版本来就是术语版，每一页都摆着数，所以这里的档位**不管数**，
只管两处：

- **「统计节点」** —— 尚未到来的那些节点出不出
- **「完整报告」的待校准清单** —— 那是工程信息（哪几张表还没拿实体书核过）

两处都不默默少几条：节点页会写出压下了几条，
待校准那一节普通读者档下仍会说「有 N 项尚未核对」，收起的只是清单本身。
**有没有东西没核过，属于这份报告有多可信，任何档都该知道。**

顶栏另有一条**另一套占法**，底下是两页：`/chart/sky` **星盘**
与 `/chart/ziwei` **紫微斗数**。

它与前面十二页同一个出生时刻、同一个地点，但**不是四柱的又一个视图** ——
是七政四余与西洋古典占星，同一组行星位置的两套读法。
分成两组摆，是因为混在一排里读者会把它当成四柱的一个分支，而那正好说反了。

> 这一页要**纬度**。四柱对出生地的依赖只到真太阳时那一层，用的是经度；
> 纬度根本不进算式。上升点要纬度，而且南北差一度就能差出几度。
> 没填纬度时这一页不替你猜一个 —— 随手填出来的上升点，
> 看起来与真的一模一样，而你无从分辨。

技法上它怎么算、为什么那么算，见[《测天，还是约定》第 11 章](../book-compare/11-星盘的技法.md)。

**紫微斗数**那一页正相反：它既不查星历，也不看节气，**连出生地点都不要** ——
整张盘由五个整数推出（农历年干支、农历月、农历日、时辰、性别）。

两页并排放在同一组，是因为这个对照自己就说明问题：

| | 星盘 | 紫微 |
| --- | --- | --- |
| 「星」是什么 | 真天体 | 虚星（算术摆出来的） |
| 要算星历 | 要 | 不要 |
| 要出生地点 | 要经纬度 | **一样都不要** |

紫微的盘用传统的**四方十二宫**方图，不用列表 ——
对宫（相隔六位）与三方四正（相隔四位）在方图上一眼可见，
在列表里要数行数，而那些关系正是这套东西的全部。
逐步怎么算，见[第 13 章](../book-compare/13-紫微的技法.md)。

> ⚠️ 紫微的年干支**以正月初一为界**，而四柱的年柱**以立春为界**。
> 生在这两个日子之间的人，两套给出的年干支不是同一个 ——
> 而年干在紫微里决定四化、禄存、羊陀、魁钺。
> 这不是哪一套错了，是两套的岁首本来就不同。盘上会明写。

`/pair` **合盘**要两张盘，故也不挂在某一张盘底下。
它列的是两张四柱盘之间的结构关系，**一个分数都不给** ——
理由见[第 11 章](11-它算不出什么.md) 11.3.1。
两张盘都从本机已存的命盘里选，这一页不另开输入表单：
那会让人顺手填进一个随口问来的生辰。

另外三页不挂在 `/chart` 下，因为它们不要生辰：

- `/ask` 六爻问事
- `/cross` 四家合参
- `/tarot` 塔罗 —— 连时刻都不要

### 两个值得专门去点的地方

**参数校准面板。** 它比这本书任何一章都更能说明「这些数有多要紧」：
把藏干比例拖一拖，看着「身弱」变成「中和」。
看过一次之后，你对所有排盘软件给出的结论都会多一分合适的怀疑。

**生命曲线页。** 可以切换：单条/多条/全部、按 ±2σ 对齐还是按权重对齐、
门槛取 2σ 还是 3σ、采样按月还是按年。点曲线上任意一点，
下面会列出那个时段被引动的神煞。

## 10.4 命令行

没有全局命令，直接跑：

```bash
node packages/cli/bin/fate.mjs --help
```

常用的几条：

```bash
# 排盘，存成文件
node packages/cli/bin/fate.mjs chart --date 1990-05-12 --time 14:30 \
  --city 上海 --gender male -o c.json

# 完整报告（Markdown）
node packages/cli/bin/fate.mjs report --chart c.json --nodes

# 人话版
node packages/cli/bin/fate.mjs plain --chart c.json

# 六爻问事（人话版，「说的是什么事」单列一节）
node packages/cli/bin/fate.mjs ask --topic career.promotion --city 上海 --plain

# 当日运程 / 四家合参
node packages/cli/bin/fate.mjs daily --chart c.json
node packages/cli/bin/fate.mjs cross --chart c.json --city 上海
```

加 `--json` 得到结构化输出，供别的程序消费。
加 `--locale zh-Hant` 得到繁体。

> 命令行**没有「点开看依据」这个动作**，所以 `plain` 的输出是
> 「一句人话 + 缩进的依据」两层并排 —— 若只出人话，
> 那层来历就等于不存在了。

## 10.5 Claude Skill

两个：

| | |
| --- | --- |
| `fate`（术语版） | 排盘、断论、问事，模型组织叙述，但判定全部来自内核 |
| `bazi-plain`（人话版） | 同一台引擎，转述而非翻译 |

要紧的是第二个的定位：**转述，不是翻译。**
人话由引擎的定值映射产出并过人话专用的守卫，
模型做的是把这些卡片组织成对话，而不是自己从术语版里现翻一遍 ——
那样会绕过守卫。

## 10.6 你的数据去哪了

一句话：**哪儿也没去。**

| | |
| --- | --- |
| 出生信息 | 浏览器本机（移动版 localStorage，网页版 IndexedDB） |
| 命盘标识 | URL 的 **片段**（`#` 之后）—— 片段不随请求发往服务器，也不进访问日志 |
| 问事的问题文本 | 只在本机算出一串指纹，原文不上传不存储 |
| 回看的标注 | 本机，且不回流引擎 |
| 分享 | 只分享人话文本，**不带链接**（链接会带上片段，片段里是命盘标识） |

整站是**静态导出**，没有服务端路由，也没有后端。
所有推演都在你的浏览器里跑完。

## 10.7 这一章最该记住的

1. **四个入口，同一份内核**，结论不会漂移。
   而四柱之外另有几套占法，各自要的输入不同 —— 那是实质差异，不是风格差异。
2. **移动版每张卡都有「看依据」**，点开能看到被概括的原文。
3. **「回看」是唯一不讲未来的一页**，也是最值得花时间的。
4. **参数校准面板值得去点一次** —— 它会改变你对所有排盘软件的态度。
5. **数据不出本机。**

下一章是全书的底线：它算不出什么。
