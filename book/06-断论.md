# 6 · 断论

到这一步，手里是一组收敛后的数。这一章把它们变成词 —— 旺衰、用神、格局、六亲。
这是整套系统第一次说出带判断性质的话，所以也是规矩最多的一章。

---

## 6.1 旺衰：五档，以及「离界多远」

把十类载体分成两边：

```
同党（帮日主）   与日主同类的 + 生日主的
异党（耗日主）   日主生的 + 日主克的 + 克日主的
```

算出同党占总量的比例，按阈值分五档：

```
极旺  ←  偏旺  ←  中和  →  偏弱  →  极弱
```

一张真实的盘算出来是这样：

```
同党 172.17，异党 295.83
r = 同党 / 总量 = 0.3679
落入「身弱」
```

### 两条规矩

**第一，必须带推导链。** 上面那三行就是推导链本身 —— 哪些载体、
多少权重、哪条阈值、落在哪一档。报告里每一条结论旁边都有它，
可以展开。**没有推导链的结论不允许进报告。**

**第二，离界近就要说。** 假设某张盘算出 r = 0.4498，而档界在 0.45 ——
差 0.0002。这时候说「身弱」是误导：换一组同样合理的藏干比例，
它就变成「中和」了。

本项目的做法是：**低置信度的结论必须同时给出另一种读法**。
报告会写「这张盘在界上，两种读法都成立」，然后把两种都列出来，
而不是挑一个说得斩钉截铁。

> 这条规矩在代码里是强制的：`Verdict` 这个类型要求置信度低于阈值时
> 必须填 `alternatives`，填不出来就报错。

### 还有一个数：根

「通根」指日主在地支里有没有同类的藏干。没有根的日主，
力量完全来自别人的支持，这样的结构对大运更敏感。
报告会单独给一个**根分**，并在无根时明说。

## 6.2 从格：当平衡被彻底打破

如果异党压倒性地多，而日主又完全无根，传统认为这时候不该再「扶弱」，
而该**顺着**那股势走 —— 这叫**从格**。

| 类 | 大意 |
| --- | --- |
| 从财、从杀、从儿 | 顺着最强的那一行 |
| 一行得气（专旺） | 整盘归于一行 |
| 化气格 | 日主与邻干合化成另一行 |

**从格是全书争议最大的判定。** 各家的门槛差别很大，同一张盘有人作从格断、
有人作身弱断，而两者的用神**正好相反** —— 一个要扶，一个要顺。

本项目的处理：

- 门槛进参数；
- 盘若落在门槛附近，**同时输出从格读法与普通读法，两者并列不合并**；
- 化气格的置信度由设计上限封顶 —— 它是实践中最有争议的一类。

## 6.3 用神：这张盘最需要补什么

**用神**是传统断法的核心：整盘最需要的那一行。补上它，结构就顺；
缺了它，就处处别扭。

取用神有几条路：

| 取法 | 什么时候用 |
| --- | --- |
| **扶抑** | 身弱则扶（取印、比），身旺则抑（取财、官、食伤） |
| **调候** | 冬天的水要火暖、夏天的火要水润 —— 看月令的寒暖燥湿 |
| **通关** | 两行相战，取中间那一行化解 |
| **病药** | 盘里有一个明显的毛病，取能治它的那一行 |

**这几条路可能给出不同的答案。** 冬天生的身旺之人，扶抑说要泄要克，
调候说要火 —— 可能是两个方向。

本项目不合成、不投票。它**各自给出，并写明两者分歧**：

```
扶抑取木，调候取火 —— 两说分歧，下列并列，不合并。
```

### 调候的那张表

调候用的是《穷通宝鉴》的一张表：十天干 × 十二月 = **120 格**，
每格写明这个日主生在这个月该取什么。

⚠️ **本项目的这张表是凭记忆转录的，尚未经实体书核对。**
其中 31 格各家有异，8 格已列出明确的不同版本。这件事写在
[`docs/11-validation.md`](../docs/11-validation.md) 的待核对清单里，
也写在这里 —— 它是这套实现里已知最大的一处数据风险。

## 6.4 格局：这个结构属于哪一类

看月令透出来的是哪个十神，就入哪个格：正官格、正财格、七杀格、
食神格……每个格有自己的「顺用」或「逆用」之法。

```
正财格   顺用   相神：食神、伤官、比肩   忌：劫财
```

「相神」是辅助用神成立的那一个，「忌」是破格的那一个。

格局这一层在传统里分量很重，但它本质上是**对结构的分类命名**，
不是对人生的判断。本项目照实处理：给出格名、给出入格的依据（从哪里透出）、
给出相神与忌神，仅此而已。

## 6.5 宫位六亲：星与宫，两条线索

看一段关系有两条线索：

| | 看什么 |
| --- | --- |
| **星** | 代表这类关系的那个十神，在盘里力量如何 |
| **宫** | 对应的那个位置（如配偶看日支），状态如何 |

例如看配偶：男命以**正财**为妻星，而**日支**是配偶宫。
两者可能一致（都好或都差），也可能相反。

**本项目不把两者合成一个分数。** 它分成四个象限照实报：

| | 宫好 | 宫差 |
| --- | --- | --- |
| **星好** | 这一路在结构里分量足，位置也稳 | 心里分量重，但落脚的位置不够稳 |
| **星差** | 位置摆得稳，但不占太多心思 | 既不重也不稳，着墨很少 |

> 为什么不合成：合成要一个权重，而「星占几成、宫占几成」典籍里没有。
> 编一个出来，读者看到的就是一个有精度外观、实则是我编的数。
> 分开报，读者自己能看出两条线索的张力在哪。

### 一条硬规矩：不描述第三方

这里有一条本项目明确的边界：**不用你的盘去描述另一个人。**

报告不会说「你配偶是什么性格」。它只说「你与这一路关系的相处结构」。
理由很直接：那是把一份推演套到一个没有同意过的第三方身上。
这条在代码里由措辞守卫强制（见[第 11 章](11-它算不出什么.md)）。

## 6.6 这一章最该记住的

1. **每条结论都带推导链**，可以展开看到数。
2. **离阈值近就得说**，并给出另一种读法 —— 这是代码强制的。
3. **用神有几条取法，可能分歧。** 分歧就并列，不投票、不合成。
4. **调候那张 120 格的表是凭记忆转录的**，这是已知最大的数据风险。
5. **星与宫分开报，不合成分数。**
6. **不描述第三方。**
