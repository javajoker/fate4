# 12 · 自己调参

这套系统里有几百个数字。它们不是定理，是**选择**。
这一章讲怎么改，以及改之前该想清楚什么。

---

## 12.1 一条贯穿全项目的原则

> **流派差异是配置，不是事实。**

同一张盘，不同门派会得出不同结论，而且各有典籍支持。
这种时候有三种做法：

| 做法 | 问题 |
| --- | --- |
| 挑一家，说它是对的 | 凭什么？ |
| 都算一遍取平均 | 平均一个「早子时换日」与一个「晚子时换日」，得到的是不存在的第三种说法 |
| **做成开关，默认值写明出处** | ← 本项目 |

于是整套系统里凡是有争议的地方，全部是参数，集中在一个文件：
[`params/default.yaml`](../params/default.yaml)。

---

## 12.2 两类参数，性质完全不同

这个区分很重要：

| 类 | 例子 | 能不能拟合 |
| --- | --- | --- |
| **流派选择** | 子时归哪天、阳刃看劫财还是看日刃、五窍配属取哪一篇 | **不能。** 它是「用哪一家的说法」，不是「哪个数更准」 |
| **待校准的数** | 藏干比例、月令放大系数、距离衰减、各种阈值 | **能。** 它们本来就是本项目填的 |

**把流派选择交给拟合，会得到一个在古籍命例上分数很高、
但内部理论不自洽的模型。** 那不是校准，是过拟合到一堆互相矛盾的样本上。

所以：想调数，调第二类；想换说法，改第一类 —— 但要知道你换的是一整套，
而不是一个数。

## 12.3 几个值得先动的开关

### `structure.rewriteCarriers`

会合冲刑害破要不要在传导之前先改写权重。

```
false（默认）  只「察」不「改」：事件照出，权重交给传导层算
true           察 + 改：传统做法
```

实测 120 张盘：**旺衰档位 0% 改变，用神 28.3% 改变。**
所以这个开关的真正含义是「用神由谁定」。

### `chart.ziHourRule`

子时归哪一天。三选一，没有正确答案，但会整柱改变日柱。

```
lateZiNextDay（默认）  23:00–24:00 为晚子时，日柱算次日
earlyZiSameDay         一律 00:00 换日
split                  一律 23:00 换日
```

### `conclusion.congge.*`

从格的门槛。这是全书争议最大的判定 —— 同一张盘有人作从格断、
有人作身弱断，而两者的用神**正好相反**。

```
ratioThreshold: 0.3     同党占比低于它才考虑从格
requireRootless: true   要求日主完全无根
yinThreshold: 25        印的权重上限
```

门槛调松一点，更多盘会入从格。调之前先想清楚你信哪一派。

### `nodes.threshold`

统计节点的 θ。

```
1.5  →  463 段
2.0  →  221 段     ← 默认
3.0  →   28 段
```

再说一次：**这是「取多少条」的旋钮，不是显著性水平。**
调大它不会让结论更可靠，只会让列表更短。

### `report.guard.neutralPalette`

图表禁红绿吉凶配色。**这一条不可关闭** —— 改它参数校验会直接失败。

理由：顺逆指数低不等于「凶」，它衡量的是当年五行结构与本命喜用的契合度。
图表一旦染上红绿，有序量立刻被读成好坏，而且读者不会意识到
那层意思是配色加上去的、不是数据里的。

## 12.4 怎么改

### 最简单：网页上的参数校准面板

`/chart/params`。拖系数，实时看结论怎么变。

**建议第一次就拖藏干比例。** 看着「身弱」变成「中和」，
你会对所有排盘工具（包括这个）给出的结论多一分合适的怀疑。
这一分怀疑是对的。

### 命令行：给一个覆盖文件

```bash
node packages/cli/bin/fate.mjs chart --date 1990-05-12 --time 14:30 \
  --city 上海 --gender male --params my.json
```

`my.json` 只写要改的项，与默认值**深合并**后校验：

```json
{
  "structure": { "rewriteCarriers": true },
  "nodes": { "threshold": 3.0 },
  "chart": { "ziHourRule": "earlyZiSameDay" }
}
```

也接受 `.yaml`。

### 每份报告都带参数指纹

报告末尾有一行：

```
参数指纹   252fddd5
```

它是整份参数的哈希。**两份报告的参数指纹相同，才谈得上可比。**
拿一份用默认参数的报告去比一份改过从格门槛的报告，比的不是同一回事。

一件要紧的事：**四柱之外那几套的流派，也在同一份参数里。**

紫微的闰月归属、星盘的相位容许度、塔罗的大牌序号 ——
这些此前散在函数参数与硬编码里，于是两张用不同取法排出来的盘
会得到**同一个指纹**。那是说不过去的：指纹的全部用处就是
「指纹相同，两份才可比」，而它们明明不可比。

现在它们与四柱的开关同列，同样进指纹。塔罗页把指纹直接显示在开关下面 ——
换一个流派，当场能看见它变。

指纹算的是**会影响数的那些参数**，不含 `report` 那一节。
读者档、简繁、要不要折叠 —— 这些改的是呈现，一个数都不动。
若把它们也算进去，同一张盘的普通读者版与命理师版会得到两个不同的指纹，
看起来像是两份不可比的报告，而它们逐数相同。
反过来，`weights`、`congge`、`structure`、`nodes` 任何一处一动，指纹就变。

## 12.5 改完之后怎么知道没改坏

本项目有 **1241 条断言**。改参数之前先跑一遍，改完再跑一遍：

```bash
pnpm test
```

多数参数改动不会让测试变红 —— 测试断言的是**不变量**
（顺序无关、权重守恒、繁简对等、守卫咬合），不是具体数值。
若某条变红了，那通常说明你改的东西碰到了一条结构性的保证，
值得停下来看看。

## 12.7 这一章最该记住的

1. **流派是配置，不是事实。** 但流派选择不能靠拟合定。
2. **参数分两类**：可校准的数，与不可拟合的流派选择。
3. **几个开关值得先动**：`rewriteCarriers`、`dayBoundary`、从格门槛、节点 θ。
4. **有一条不可关闭**：图表禁红绿。
5. **参数指纹相同，两份报告才可比**；指纹只认影响数的参数，不认呈现。
6. **先去拖一次藏干比例。** 那一分怀疑是对的。
